# World Programs:VLM agent 在有 oracle 的世界里主动探索、归纳可执行的科学机制

### Closed-Loop Scientific Discovery with a VLM Agent

> **一句话 claim.** 把科学发现做成一个**闭环**:一个 **VLM agent** 在程序生成的世界里**主动探索**——自己决定看哪张图、查哪段数据、做哪个检验——提出机制假说、验证、修正,最终交出一段**可执行的生成程序**。生成这个世界的那段原始程序就是 **deterministic oracle**,直接判定发现对不对。难度天然分级、层层递进。

> **定位.** 第一个**带 ground-truth oracle 的科学发现 agent 环境**。AI scientist 能提假说但无法验证发现对不对(真实科学没有 oracle);chart benchmark 只问答案不问机制;program synthesis 没有多模态观测、没有发现框架。本篇站在三者交汇,谁都不能完全覆盖。

## 0. 一个例子看懂全篇

> 一个具体场景,看懂这个就懂了整篇 paper 在做什么。

### 给 agent 的输入

```
场景简介:"某城市急诊数据,600 条记录,含医院、严重程度、
          等待时间、费用、就诊日期等。"

Schema(只给列名+类型,不给任何机制):
  hospital      categorical    severity   categorical
  visit_date    temporal       wait       numeric
  insurance     categorical    cost       numeric
```

### VLM agent 怎么探索(典型过程)

```
[1] request_view(直方图 wait)        → VLM 看到右偏长尾,猜 wait ~ lognormal
[2] request_view(散点 cost vs wait)  → VLM 看到整体正相关,但隐约分两簇 → 起疑
[3] request_view(同图,按 insurance 着色)
                                     → VLM 一眼看到:两簇各自"向下"倾!
                                     → 假说:cost 其实随 wait 下降,是分组把整体拉成了正向
[4] run_stat_test(分组拟合)          → 确认组内斜率 ≈ -8;有保险组整体更贵
... 再花几步精修参数、查异常
[B] submit_program(...)
```

### agent 交出的东西(可执行程序)

```python
sim = FactTableSimulator(target_rows=600, seed=...)
sim.add_category("insurance", values=["yes", "no"], weights=[0.5, 0.5], group="payer")
sim.add_measure("wait", family="lognormal",
    param_model={"mu": {"intercept": 2.8, "effects": {"insurance": {"no": 0.0, "yes": 0.7}}},
                 "sigma": {"intercept": 0.3}})
sim.add_measure_structural("cost",
    formula="wait * (-8.0) + insurance_base",          # 组内:wait 越久 cost 越低
    effects={"insurance_base": {"no": 200, "yes": 900}}, # 组间:有保险整体更贵
    noise={"family": "gaussian", "sigma": 25})
```

### oracle 怎么判(全自动,不用 LLM 打分)

```
跑 agent 的程序  → agent 的数据  ┐
跑 GT 的程序     → GT 的数据      ├─▶ 比对:统计是否一致?
做一个"反事实"干预(见 §5)   ──▶ 改变条件后,两个程序的预测还一致吗?
```

> **看点:** 第 [2]–[3] 步是关键——光"算"(整体回归)会得到**正斜率**,结论是错的;要 agent **主动去看、去分组**才能发现真相是负斜率。这就是为什么发现需要**主动探索**,以及为什么用 **VLM**(它能看图)。

## 1. Motivation

### 1.1 三个交汇的空白

| 领域 | 强项 | 缺口 |
|---|---|---|
| AI Scientist (Sakana / METR / Paperbench) | 大规模提假说 | **没有 oracle**,无法验证发现对不对 |
| Chart benchmark (ChartQA / ChartBench) | 测能不能读图 | 只问答案,不问背后机制 |
| Program / DGP synthesis | 从 spec 反推代码 | 没有多模态观测、没有"科学发现"的框架 |

### 1.2 关键洞察:逆问题天生自带 oracle

> [`FactTableSimulator` SDK](../data_generation/phase_2.md) 是一个 `机制代码 → 可观测数据` 的**正向映射**。**反过来跑,就是科学发现**:从数据反推出生成它的机制。而正向映射是完全写定的代码,所以**逆映射有一个确定性的 oracle**——生成数据的那段程序本身。这是其他 AI scientist 环境结构上拿不到的东西。

### 1.3 为什么"给全量数据也难"

就算把每一行都给 agent,它也不能"抄":分布族要识别、相关与因果在观测上长得一样、噪声里藏着模式、没见过的干预下要预测——这些都是**推断问题**,不是信息缺失问题。所以这是一个真正的发现任务,不是查表。

---

## 2. 任务与 agent 的动作空间

**输入.** 场景简介(文字)+ schema(只有列名和类型)。
**输出.** 一段可执行的生成程序。
**评估.** 跑 agent 的程序和 GT 的程序,比对它们生成的数据(含干预后的数据)。

### 2.1 这是一个 VLM agent

agent 的"主动探索"具体化为下面这组动作。每个动作花 1 步,总预算 B 步——逼它像科学家一样**有选择地做实验**。

| 动作 | 返回 | 干什么 |
|---|---|---|
| `request_view(spec)` | **一张 chart 图像 (PNG)** | VLM 直接**看**形状/趋势/分簇(如 "scatter cost~wait, 按 insurance 着色") |
| `request_table(spec, k)` | 一段数据表 | 精确**读**数值 |
| `run_stat_test(name, args)` | 统计量 / p 值 | **量化验证**一个假说(分布拟合、相关、分组斜率…) |
| `run_code(snippet)` | sandbox 输出 | 灵活**计算**(拟合、分组回归…) |
| `submit_program(code)` | — | 交出最终生成程序,结束 |

> **图**适合**看出**形状与结构(分布、趋势、分簇),**表/检验/代码**适合**算准**数值。VLM agent 自己权衡何时用哪个——这就是"主动"的全部含义:不是看得多,而是**会选该看什么**。

### 2.2 一段程序要"装下"什么(也是评估的层次)

| 层 | 程序要编码的东西 | 例子 |
|---|---|---|
| 表面 | 均值、排名、极值 | 协和的平均等待最长 |
| 分布 | 分布族 + 条件参数 | wait 是 lognormal,重症更长 |
| 结构 | 公式 + 列间依赖 | cost = f(wait, insurance) |
| 模式 | 隐藏的异常 | 某医院 3 月中旬出现跳变 |
| **反事实** | **干预下的预测** | 改变投保比例后会怎样 |

越往下,越不可能靠"拟合记住"蒙对,越需要真懂机制(详见 §5)。

## 3. 方法:主动探索闭环(就两件事)

> Method 故意做得很轻——**没有额外的规则、打分启发式或模板**。难度全部来自世界本身的结构,不来自方法。

### 3.1 闭环

```
   主动观测 ──▶ 提出假说 ──▶ 计算/统计验证 ──▶ 写程序、跑、和反馈对照
      ▲                                              │
      └──────────────── 修正 ◀───────────────────────┘
```

### 3.2 世界与 oracle 复用现有 pipeline

| 组件 | 来源 |
|---|---|
| 生成世界 | [Phase 0–2](../data_generation/):领域池 → 场景 → SDK 生成 Master Table |
| GT 程序 = oracle | Phase 2 的 `FactTableSimulator` 脚本,**本来就是机制真值** |
| `request_view` 的后端 | [Phase 3](../data_generation/phase_3.md) 的 `extract_view` + 渲染,改成按需调用 |
| schema(只给名字类型) | Phase 2 §2.6 的 schema metadata,**去掉机制部分** |
| 新增 | agent harness + 统计检验封装 + 干预引擎 + 比对器,**约 1–2 周** |

### 3.3 对 data generation 的修改意见(high-level,本篇不动手实现)

> storyline **不强绑定**当前 pipeline 的全部细节。为这个发现任务,建议两处调整——都让 pipeline 更贴合、而且更**简单**:

| pipeline | 现状 | 建议改动 |
|---|---|---|
| **Phase 3** | 把 Master Table 确定性枚举成 10–30 个 `(chart, 多跳 QA)` 任务(operator 代数 / bridge / 难度=#ops) | **整套 QA 生成不再需要**:发现任务里 agent 主动 `request_view` 自己看,评估比对程序而非答案。**只抽出 `extract_view` + 渲染**,做成一个按需服务,当 `request_view` 的后端。Phase 3 因此大幅瘦身。 |
| **Phase 2** | 列间关系:measure 用线性加性 formula + 共享 predictor;categorical 用层级 + 跨组 root 依赖 | 为支撑难度递进,**增强"列之间关系"的表达力**:formula 支持少量非线性原语(`x²`、`max(x−t,0)`、交互项、随量变化的方差),让阈值/倒U/交互/异方差等结构可生成。少量改动,不改 API 风格。 |
| **Phase 0–1** | 领域池 + 场景 | 基本不变(场景本来就不绑定 chart 类型)。 |

> 多模态在这里很自然:`request_view` 给 VLM 看图,`request_table`/`run_*` 给它算数。不需要为"多模态"做特别设计,它就是探索动作的一部分。

## 4. 难度:从线性到隐藏结构,层层递进

> **线性加性不禁**——它就是最简单那一档,是 baseline 该轻松通过的"地面"。有意思的科学藏在更高档。难度的本质是:**机制对朴素观测藏得有多深 = 需要多主动地探索才能揭开**。

| 难度 | 机制类型 | 朴素地"算"会怎样 | 要恢复它得做什么 |
|---|---|---|---|
| **Easy** | 线性加性、可直接读出的关系 | 一次 OLS / 看一张柱状图就对 | 几乎不用探索 |
| **Medium** | 分布形状(双峰、偏态)、简单依赖(中介、共同原因) | 聚合统计漏掉形状,或多连一条边 | 选对视图、做一次分组或控制变量 |
| **Hard** | 聚合下被掩盖甚至**反号**的结构(Simpson 反转)、多机制叠加 | 结论性地错(如 §0 的正负斜率) | 必须主动分组、对照、反复看才能揭开 |

这套分级**自然、可叠加**:复杂世界 = 在同一张表的不同列上叠几个机制。它同时对应"程序层次"(Easy≈表面/分布,Hard≈结构/反事实)和"需要多少步主动探索"。**Hard 档正是 §3.3 里 Phase 2 要增强表达力的地方**。Phase 0 的 sanity check(§6.1)先确认这条难度曲线真实存在。

## 5. 评估:反事实是分水岭

普通比对(表面/分布/结构/模式)问的是:**"agent 的程序能不能复现见过的数据?"** —— 这有捷径:**死记硬拟合**也能复现。

**反事实**问的是:**"能不能预测从没见过的情况?"** —— 拟合永远答不对。

### 用 §0 的 Simpson 例子说清楚

真机制:`cost = -8·wait + 投保基线`(组内 wait 越久 cost 越低,有保险整体更贵)。

- **拟合派**:把整体看成一条正斜率 `cost ≈ +12·wait`,见过的数据复现得不错。
- **机制派**:还原了"两组 + 组内负斜率 + 组间差异"的真实结构。

平时两者看不出差别。**但 oracle 做一个干预**——把有保险的比例从 50% 提到 80%,重新生成数据:

| | 干预后的预测 | 真值 | 对不对 |
|---|---|---|---|
| 拟合派(正斜率) | 按老规律外推 | 整体形状变了 | ✗ |
| 机制派(真结构) | 重算两组混合 | 对上了 | ✓ |

> 道理很简单:拟合派没有"投保比例"这个**显式的可调旋钮**,世界一变就错;机制派还原了结构,任何扰动都能模拟。**显式结构 vs 死记硬拟合,就是真懂机制的标志。** 干预的种类(改比例、删一条依赖边、移走一个异常)都由 oracle 自动施加,无需人工。

## 6. 实验

### 6.1 先做一个轻量 sanity check(<1 天)

给 SOTA 模型**完整 CSV + SDK 文档 + 场景**,一次性问、不让它主动探索,看它在三档难度上的恢复准确率。**目的:确认 Easy 档它能过、Hard 档它过不了**——也就是确认"难度曲线"和"主动探索的必要性"真实存在。如果 Hard 档一次就解决,这个方向就得先升级难度。

### 6.2 主实验(三个朴素直接的问题)

在 30 个世界 × 3 档难度上,跑几个 frontier 模型,回答:

1. **难度真的递进吗?** —— 准确率应随 Easy → Medium → Hard 下降。
2. **主动探索有用吗?** —— 对比三种模式(预算严格对齐):
   - 被动看表(一次性 CSV)
   - 被动看图(预先给几张图)
   - **VLM agent 主动探索**(自己选该看图还是查表,⭐)
3. **是真懂还是死记?** —— 反事实(§5)的准确率 vs 普通比对的准确率。若反事实远低,说明模型在拟合——**这本身就是一个有价值的发现**。

> 没有花哨的设计:就是"按难度分层 × 按观测模式分层 × 看反事实掉多少"。

## 7. 长期定位与诚实风险

```
v1  SciGym-Tabular      表格机制 from 图 + 表
      ├─▶  SciGym-Spatial:    场景/物理 from 渲染图像
      ├─▶  SciGym-Molecular:  反应机制 from 分子观测
      └─▶  SciGym-Dynamics:   微分方程 from 轨迹
```

**统一主线:** 科学发现 = 归纳出一段 oracle 可验证、可执行的世界程序。

**三个要正面处理的风险:**

1. **搜索空间大,可能退化成记忆模板** —— 测试集在 Phase 0 的子领域层面完全 holdout;比对只看"生成的数据是否统计一致",不看代码长得像不像。
2. **"真实科学没有 oracle"的迁移质疑** —— 补一个真实数据 case study(在已知经济/流行病数据上恢复已知效应),证明沙盒里练出的能力是真的。
3. **比对器的设计** —— 把最终判定压在反事实(干预后)的比对上,普通层次只作诊断;并报告判定对参数扰动的稳健性。

## 8. Abstract 草稿

> 科学发现是数据生成的逆问题:从观测反推一个能解释、复现、并预测的机制。AI scientist 系统能大规模提假说,却无法验证发现本身;chart benchmark 只问答案不问机制。我们注意到:程序化数据合成 pipeline 生成数据的那段代码,本身就是机制的 ground truth——于是这个逆问题第一次拥有了 deterministic oracle。本文构造一组由程序生成的世界,一个 **VLM agent** 在其上**主动探索**(请求图像、查表、做检验),在固定动作预算下提交一段可执行的生成程序;我们用生成该世界的原始程序自动判定它恢复了什么,并通过**反事实干预**区分"真懂机制"与"死记硬拟合"。世界的难度从线性关系到聚合下被掩盖的反直觉结构**层层递进**。在 30 个世界、若干 frontier 模型上,我们发现 [核心结果];针对难度分级、主动 vs 被动探索、以及反事实的实验,刻画了当前模型科学发现能力的边界。
