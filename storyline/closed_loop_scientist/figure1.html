为什么发现需要主动探索,而不只是"算"

同一份急诊数据:cost vs wait

① 只是"算":整体回归

corr +0.53

② 主动去看 + 按 insurance 分组

两簇 · 组内斜率 −8.5 / −7.5

左:整体回归得到正斜率 +15.7 → "等得越久越贵"——所有汇总数字都对,但结论是反的。 右:主动按 insurance 分组,看到两簇各自向下(真相:cost 随 wait 下降)。
光"算"会被聚合骗;要"主动看、主动分组"才能发现真机制。 (示意为 140 点子样本;全样本 N=600 时整体 +12.4 / 组内 −8.0)

难度层层递进(线性不禁,是最简单那档)

机制对朴素观测藏得多深 = 要多主动地探索才能揭开

Easy
线性加性、可直接读出的关系。
一次 OLS / 看一张柱状图就对。
几乎不用探索
Medium
分布形状(双峰/偏态)、简单依赖(中介/共同原因)。
聚合统计会漏掉,需要选对视图、做一次分组或控制。
要会选该看什么
Hard
聚合下被掩盖甚至反号的结构(Simpson 反转)、多机制叠加。
光算会结论性地错。
必须反复主动探索
复杂世界 = 在同一张表的不同列上叠几个机制。自然、可叠加、可控。

怎么区分"真懂"和"死记":反事实

普通比对能被拟合蒙混;干预下的预测不能

拟合派
把整体记成一条正斜率 cost ≈ +12·wait。
见过的数据复现得不错,但没有"投保比例"这个旋钮。
机制派
还原"两组 + 组内负斜率 + 组间差异"的真实结构。
oracle 做一个干预:把有保险比例 50% → 80%,重新生成
拟合派按老规律外推 ✗ 错　·　机制派重算两组混合 ✓ 对
显式结构 vs 死记硬拟合,就是真懂机制的标志。世界一变,只有真懂的程序还对。
范围:程序生成的世界 + 已知 SDK + 确定性 oracle · 不主张 general causal discovery
