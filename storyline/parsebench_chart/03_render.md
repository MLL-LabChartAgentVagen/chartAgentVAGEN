# 03 · 渲染

把 FigureSpec 画成页面图像，同时把画的过程记下来。项目的工作量重心。

**这一阶段全部由程序执行，不调用 LLM。**

**子阶段**

| # | 子阶段 | 谁做 | 产出 |
|---|---|---|---|
| [3](#3-风格向量) | 采样风格向量 | 规则 | 一组风格取值 |
| [1](#1-边画边记) | 逐面板绘制，边画边记 | 规则 | 图元的框、键、值；面板与轴的值域像素域 |
| [4](#4-图上的字) | 画绘图区之外的字 | 规则 | 每段字的框、角色与**画出来的那个字符串** |
| [6](#6-页面合成) | 贴进页面版面 | 规则 | 页面图像 + 页面元素的框与类别 |
| [5](#5-图像退化) | 图像退化，框同步变换 | 规则 | 退化后的图像与框 |

参考：[2 只有一个渲染器](#2-只有一个渲染器) · [7 数值标注](#7-数值标注)

先看 [§0 示例](#0-示例)，只看那一节就能明白这个阶段在干什么。

## 0. 示例

输入是 [02](02_figure.md#0-示例) 意图①的 FigureSpec：单面板 bar，三个条，值 42.3 / 35.8 / 28.1 分钟，外加图号、标题、副标题、单位、出处五段字。

### 第一步 · 采样风格

风格与 FigureSpec 正交，独立按种子采样。同一份 FigureSpec 配不同风格，得到外观不同、答案相同的图。

```
数值标注  全不画            配色    企业报表低对比（三条同色系蓝）
轴        y 起点为零，刻度每 10 分钟     版面    单图
图像      900 × 600，dpi 100  退化    JPEG 质量 75
页面      嵌入单栏版面，图表居中，上方一段正文，下方图注
```

### 第二步 · 画图，同时记下位置

布局参数写死，不用自动布局。边距 `{左 96, 上 132, 右 80, 下 120}`，于是：

```
绘图区  [96, 132, 820, 480]      宽 724，高 348
y 轴    值域 [0, 50] 分钟  ↔  像素域 480（值 0）→ 132（值 50）
x 轴    值域 (-0.5, 2.5)   ↔  像素域 96 → 820
```

每画一个条，就用 `y_px = 480 − 值 / 50 × 348` 算出它的位置并写进记录：

| 条 | 值 | 条顶像素 | 框 |
|---|---|---|---|
| Mercy General | 42.3 | 480 − 294.4 = 185.6 | `[165, 186, 269, 480]` |
| St. Luke's | 35.8 | 480 − 249.2 = 230.8 | `[406, 231, 510, 480]` |
| Riverside | 28.1 | 480 − 195.6 = 284.4 | `[647, 284, 751, 480]` |

框、键、值三者在画的那一刻同时写下，不是画完之后再回头解析图像。同时记下的还有一件事：`hospital` 这一段键写在**类别轴的刻度**上——这是 [02](02_figure.md#5-键的每一段从哪读出来) 定的，渲染器照着画。

一个像素在这条轴上代表 `50 / 348 = 0.14` 分钟，42.3 的 1% 是 0.42 分钟、合 2.94 个像素，所以这个值[量得出来](chart_types.md#4-值的画法)。

### 第三步 · 页面合成与退化，框跟着变

页面 1000 × 1400，单图占一格：缩放 `840 / 900 = 0.933` 后贴到 `(80, 260)`。三个框各自过一遍同样的平移加缩放，Mercy General 那个条落在 `[234, 433, 331, 708]`。JPEG 压缩是恒等变换，框不变；退化后的图像写在原图旁边，不覆盖原图。

### 输出

一张页面图像，加一份几何记录：三个条的框、键、值与它们各自靠哪条轴量出来，绘图区与轴的值域像素域，页面上每段字的框、角色与内容。这就是 [04](04_record.md) 的 L1 与 L0 两层。

## 1. 边画边记

渲染器每画一个图元，就在同一处把它的**框、键、值**写进记录。框由绘图库自己的坐标变换算出：数据坐标 →（轴变换）→ 像素坐标。

不做"先画完图，再回头解析图像里有哪些图形"。只有在画的那一刻，框、键、值三者才同时在手；事后解析要重新把像素和数据对应起来，而这正是要消除的误差来源。

**每个图元还记下它是靠哪条轴、按哪种形状量出来的。** 单视图的面板上这两样都能从图表类型反推，但一块绘图区里可以叠两个视图、两条值轴、两种图元形状，而下游不许回头去读 FigureSpec 才知道该用哪条。

每种图表类型画出什么形状的图元、每个图元记哪几个值，见 [chart_types.md §3](chart_types.md#3-图元形状)。

**坐标约定**：像素坐标，原点在图像左上角，框写成 `[x0, y0, x1, y1]`，随图像宽高一并记录。全流水线只有这一套约定。

**布局参数冻结**：图像尺寸、dpi、四条边距、绘图区矩形，这几项在画之前定死。**冻结的是"给定这套风格向量之后不再动"，不是"所有图共用一套"**：图像尺寸、dpi、边距各是一个风格维度，换一套重画一张图，绘图区可以不一样，因为那一次的框是那一次重新记的。自动布局是另一回事——它会在画完之后挪动绘图区，此时已经记下的框全部失效，而且不报错。

### 1.1 画布是三个维度，不是一个常数

| 维度 | 取值 | 说明 |
|---|---|---|
| 图像尺寸 | 900×600 · 1000×640 · 800×560 · 1200×720 · 680×680 · 720×900 | 横版四档、方版与竖版各一档 |
| dpi | 72 · 100 · 150 | |
| 边距 | 常规 · 紧 · 宽 | 常规是 `{左 96, 上 132, 右 80, 下 120}` |

三个都标着"会改可读性"：它们决定一个值分到多少像素，而值量不量得出来正是由每像素代表多少值决定的。

### 1.2 图像切成块，绘图区是剩下的

每个块声明它要哪条边、有多厚，同一条边上的块从绘图区往外叠，**绘图区是四条边剩下的那一块**。边距不再是输入，而是每条边的预算：其中一部分（沟）留给轴自己画的东西——刻度标签与轴标题——剩下的由块瓜分。

| 块 | 默认在哪条边 | 常规边距 900×600 下的像素 | 装什么 |
|---|---|---|---|
| 文字块 | 上（`title_placement` 可换到下） | 14–96 | 图号、标题、副标题、单位 |
| 图例块 | 下（`legend_edge` 可换到左或右） | 524–548 | 外置图例的色块与名字 |
| 页脚块 | 下（与文字块互换） | 556–590 | 出处、注 |
| 左沟 / 右沟 | 整条左、右边距 | 96 / 80 像素 | 刻度标签、轴标题、第二条值轴 |
| 面板标题条 | 每个面板上方 22 像素 | | 多面板时的面板标题 |

绘图区 `[96, 132, 820, 480]`——**默认摆放算出来的几何与它取代的那套边距逐像素相同**，这是这次改动必须过的一关。块的厚度写成它所在那条边预算的份额，不写成像素：边距是一个维度，写成像素的块会在边距变窄时原样留着，最窄的那一档就会把某一个块挤成零高。

**为什么不是固定的两条带**：真实报表每一页的答案都不一样。一份报告的图例走右侧，下一份走底部；实测 100 页里 **9 页**的图例在侧边，三家模型一致。写死成两条带就是把这个问题的答案钉在一种上。

**换到侧边的块要自带厚度。** 左右两条边默认全是沟，没有可以按份额切的带。侧边图例的宽度**从名字量出来**，不是给个固定宽度再把名字截断——图例是键的来源，裁短一个条目就是丢一个键。量出来放不下（超过图像宽度的 28%）就退回底部，而**退回这件事进记录**：`legend_edge` 是请求，`Layout` 里那条边是结果。

**拼装发生在画任何东西之前。** 唯一需要量的厚度就是侧边图例那一个，它量的是文字而不是已经画好的图元，在建第一个面板之前就问完。

**每个块的位置与有没有内容无关。** 一条只在需要时才出现的留白，会在某张图长出一个副标题、或者叠上第二条值轴的时候把绘图区推走，而那时这张图已经记下的每个框都失效了——并且不报错。冻结布局与冻结留白是同一条理由。

**块放不下的时候，让步的是字号与角度，不是版式。**文字块按块回流：装不下就换行，一行装不下就整组缩号；类别标签挤在一起时先斜排再缩号；刻度标签缩号把位置让给轴标题；两级类目标签的第二行与第一行一起缩号——它标的是每个刻度属于哪一组，按这里在意的每一条规则它都是一个刻度标签；刻度缩到下限之后还不够，先把斜度压平，再缩轴标题；图例按可用宽度与块高度两头定字号。**刻度与图例的字只缩不裁**——键是从它们身上读出来的，裁短一个刻度标签，它就不再指认它标的那个键，而写到图外或压在别的字上的一块字，记录会给它一个谁也读不出来的框。

**斜度换宽度、花高度，这笔交易在网格上不成立。** 一块画区下面是整条边距，斜排总是划算的；网格上，第一行面板下面就是第二行的面板标题条，45° 的名字够得到它。所以收缩的次序里多了一档「压平」（45° → 30° → 0°），排在缩字号之后、缩轴标题之前。

**轴标题是让位的那一样。** 底边距不够时它曾经被往上钳进刻度那一行，写在刻度标签上——那要付出一个键。刻度标签下面放不下轴标题，就不画轴标题：轴标题上读不到任何轴上没有的东西，而刻度标签是键的出处。

**可辨下限按像素定，不按点定。** 字号是点，边距与带子是像素，而 dpi 是一个维度：同一个字号在 150 dpi 下画出来是 72 dpi 下的两倍高。写成点的下限于是在每一档 dpi 上都是一条不同的可辨线——在细的那一头它会让缩号在字还没排下时就停住，两级类目标签的第二行因此曾经被写到图题上。下限写成「字形有多少像素高」：`7.6 像素`，在默认的 100 dpi 上正好是原来的 5.5 点。图例同理，它的字号既受带子的宽度约束，也受带子的高度约束。

**页面上的每一行字都按它那一行的宽度裁。** 页眉是一行，而场景标题有多长取决于它讲的是什么；不裁的话长标题会越过右边距跑到页面外，记录随之带上一个谁也看不见的框。裁过的那一行末尾带省略号，**记录里存的是画出去的那一串，不是要求画的那一串**。

**类别标签先斜排后缩号。** 真实报表在类目名挤到一起时先把它们斜过来，缩号是之后的事；只会缩号的话长名字会一路缩到最小可辨字号，而轴还是平的。风格向量里的 `label_rotation` 是**下界**——一批图要求斜排就一定斜排——排不下时抬到 30° 或 45°。**90° 只能由风格要求，排版永远不会自己抬到那里**：竖着的名字读得出来但读得费劲。实际画上去的角度记在 `Axis.tick_rotation` 上，因为风格说的是"这一批要什么"，记录说的必须是"画出来的是什么"。

## 2. 只有一个渲染器

几何只有一个来源：一个 matplotlib 渲染器。

多个后端会把项目最难的部分乘以后端数量——每加一个就要重写一遍图元记录，两套实现的坐标约定还必须逐像素对齐。因此：

- 风格差异来自**渲染器内部的参数**、**渲染后的图像退化**、**页面合成**这三处，不来自换后端。
- 企业报表的观感（粗边框、投影、伪三维、低对比配色）在 matplotlib 内部实现。
- 第二个后端是可选扩展，只有当 [05 §7](05_output.md#7-消融) 的风格消融显示后端差异确实影响真实基准上的表现时才做。

## 3. 风格向量

**[规则]** 每个维度独立按种子采样，不做联合分布。风格向量随记录一起存，供消融时按维度分组。

### 3.1 它是一张声明式的表

40 个维度写在一张表里（`interfaces/style.py` 的 `STYLE_DOMAINS`），每行四列：

| 列 | 内容 |
|---|---|
| 值域 | 这个维度能取哪些值 |
| 默认值 | 不采样时取哪个 |
| 谁画它 | 实现它的那个函数，写成 `文件::函数` |
| 会不会改可读性 | 它变了之后，哪些值还量得出来会不会跟着变 |

另有一列采样权重，给那些**不该等概出现**的维度：对数轴、伪三维是真实存在但罕见的形态，按等概抽会抽出一份没有哪份真实报表长成那样的语料。

**两个元测试直接读这张表：**

```
每个声明出来的取值都要有一个绘制分支   把每行的「文件::函数」逐个解析出来。
                                        否则记录会声称一件从没发生过的事
标了"不改可读性"的维度逐值各渲一次      「键 → 值」的映射必须逐位相同
```

40 个维度里有 9 个标着"会改可读性"：数值标注、面板类型、横排还是竖排、起点是否为零、对数轴、第二条值轴，再加上画布那三个。**改的只是"哪些值量得出来"，从来不是"值是多少"**——轴起点变了，值到像素的换算就变了；数值写在了图上，那个值就从估读变成精确。两者都不改任何一个值本身。

### 3.2 维度分组

| 组 | 维度数 | 取值 |
|---|---|---|
| 数值标注 | 4 | 全不画 / 全画 / 部分画 / 画在图元外侧 / 外侧带引线；标注旋转 0 / 45 / 90；单位写在轴标题 / 副标题 / 刻度标签 / 数值标注；是否带脚注星号 |
| 版面细节 | 7 | 图例外置 / 每面板一个 / 内嵌；面板间距四档；共享轴是否重复画刻度；系列名是否写在线旁；是否加注释框；面板底色 白 / 淡色 / 横条带；标题在上还是在下 |
| 面板类型 | 1 | 各面板同类型（small multiples）/ 混类型 |
| 数字格式 | 3 | 原样 / 千分位 / 货币符号 / 百分比 / K,M,B 后缀 / 括号负数；小数位 0 / 1 / 2；时间刻度 ISO / 短 / 紧凑 |
| 配色 | 2 | 企业报表低对比 / 同色系 / 渐变 / 灰度打印；是否只高亮一项 |
| 图形细节 | 11 | 边框粗细 / 投影 / 伪三维 / 填充纹理 / 网格线 / 字体 / 字号 / 条宽 / 饼是否中空 / 竖排还是横排 / 点系列画成什么 marker（默认圆点 / 圆 / 菱形 / 三角 / 竖线 / 线与圆交替） |
| 轴 | 9 | 起点是否为零 / 是否画零线 / 刻度密度 / 标签旋转 / 对数轴 / 第二条值轴 / 轴标题是否移到轴上方 / 两级类别标签 / 类别标签是否折行 |
| 画布 | 3 | 图像尺寸六档（横版四、方版一、竖版一）；dpi 72 / 100 / 150；边距 常规 / 紧 / 宽 |

**同一套条件的视觉变体归风格，不归类型表。** 中空的饼（donut）与实心的饼的四类条件逐格相同、图元形状相同、值字典相同，因此它是「图形细节」里的一个取值，不是 [chart_types.md](chart_types.md) 里的一行。新的视觉变体照此处理。

**marker 换的是 marker，不是图元形状。** 菱形与圆点都是点，都还能按位置量出来；换成扇形或格子会改变这个值还能不能读出来，那就是[另一个图表类型](chart_types.md#2-条件清单)，不是另一种风格。

### 3.3 版面的分工

哪些视图进同一张图、彼此什么关系、共享哪条轴、键的哪一段写在哪里，由 [02](02_figure.md#6-figurespec) 的 FigureSpec 决定；风格只管视觉细节。各面板同类型还是混类型是风格维度，但**共享图例要求各面板共用同一个系列列**，这条是 FigureSpec 的硬约束，风格改不动，见 [02 §4.4](02_figure.md#44-共享图例的硬约束)。多面板图逐面板绘制，每个面板各自记一份框与轴的值域像素域，图元的 `panel_id` 指向它所在的面板。

轴起点是否为零直接改变值与像素的换算关系，因而影响 [04 §5](04_record.md#5-值能不能读出) 的判定结果——这是风格影响标注集大小、但不影响标注内容的唯一途径。

**逐维钉住**：`render.style_overrides` 把任意一维固定成某个取值，其余照采样。钉一维是问
这一维值多少，钉满是把风格向量整体固定住——两者都是消融，写法是同一个。名字不在取值域表里、
或取值不在那一维的域里，都直接报错：一个没跑起来的消融比一个跑失败的消融更糟。

## 4. 图上的字

绘图区之外的每一段字都是一等对象，不是别处的附属品：

```
TextBlock(角色, 内容, 归属, 位置)
角色  图号 · 标题 · 副标题 · 单位 · 出处 · 注 · 轴标题 · 图例标题
归属  页面 / 图 / 面板
位置  上 / 下 / 左 / 右 / 内
```

一个类八个角色，而不是一个标题类外加一堆散落的风格维度：一行出处与一个图号的差别在于说什么、放在哪儿，不在于它们是不同种类的东西。

> **记下来的是画出来的那个字符串，不是要求画的那个。**

折行、截断、加脚注星号都会把它改掉，而页面上那份才是 ground truth。这也是页面元素的类别不止五个粗类的原因：五个页面级类别（Text、Table、Picture、Page-Header、Page-Footer）之外，还有上面八个文字角色，因此一个框携带的是它装着哪一种字，而不只是"这里有字"。

**键的每一段画在哪儿，照它记下来的来源画：**

| 记的来源 | 画在哪儿 |
|---|---|
| 轴刻度 | 类别轴或时间轴的刻度标签 |
| 图例 | 图例项。**图例列哪些名字，是按记下来的来源挑出来的**，不是按图表类型挑的 |
| 面板标题 | 面板上方那条固定高度的标题条 |
| 图元旁 | 印在图元自己旁边（扇形） |
| 图题 | 只写在图题里 |
| 不写 | 页面上一个字都没有 |

按来源挑，绘制与记录才不会走岔：记录说某一段键是从图例读出来的，页面上就一定有一个为它画的图例项。

## 5. 图像退化

只允许几何变换写得出解析式的退化，框按同一个变换映射，标注保持精确。

| 退化 | 几何变换 | 框怎么处理 |
|---|---|---|
| JPEG 压缩 / 扫描噪声 / 模糊 | 恒等 | 不变 |
| 降采样 | 缩放 | 按比例缩放 |
| 轻微旋转 | 仿射 | 四个顶点变换后取外接框 |
| 透视形变 | 单应 | 四个顶点变换后取外接框 |

写不出解析变换的退化不进管线。旋转与透视之后外接框会比原图元略大，这是已知且可控的偏差，记录里注明施加过哪个变换。

**一张图像只退化一次。** 排在同一页上的几张图共享一张图像，逐份记录各退一次会把这一页退化"页上有几张图"那么多遍，而除第一份以外的每份记录都会把自己的框过一个已经施加过的变换。

**退化后的图像写在原图旁边，不覆盖原图。** 几何记录是对着未退化的那张记下来的；覆盖掉它，退化两次就会悄悄叠加。

## 6. 页面合成

图表不直接输出为裸图像，而是嵌进一张含正文、页眉、页脚、图注的版面。

由此得到：

- 页面元素的框与类别标签，即 [04](04_record.md) 的 L0 层
- 非平凡的定位任务——裸图像里图表占满整幅画面，定位没有信息量
- 单页多图、跨栏、图注与图表分开这些真实版面现象，且可控

合成器把图表贴进页面时，对已记录的框施加一次平移加缩放，用的是与 [§5](#5-图像退化) 相同的变换机制。**页面尺寸同样写死**（1000 × 1400）：一张会随内容伸缩的页面会挪动贴进去的每一个框。两张图并排占一行，这正是[同页两图](02_figure.md#12-派生图--从锚点推导)那种版面。

**同一页上的两张图，谁也不掌握整页。** 每张图带着自己的文字块，也各带一份页眉、页脚与正文，因此单看任何一份记录，页面元素目标都缺另一半——看起来像标漏了，其实是拆开看的。所以导出时按页号先并再写，见 [05 §2](05_output.md#2-训练目标)。

## 7. 数值标注

单独提出来，因为它决定 [05](05_output.md) 的容差：

| 标注状态 | 容差 |
|---|---|
| 图上写出了数值 | 0，要求精确匹配 |
| 图上没写数值 | 1% 相对容差，且要通过 [04 §5](04_record.md#5-值能不能读出) 的判定 |

渲染器只负责记下每个图元的 `labeled` 与标注框；判定值能不能量出来是 [04](04_record.md) 的事，判据只在 [chart_types.md §4](chart_types.md#4-值的画法) 定义一次，那 1% 是判据的一个参数而不是判据本身。

**写不下的标注不写。**画满之后量一遍，一个标注要留得出空隙才画：它的框往四周各放两个像素，碰到已经在页面上的东西就不画，它那个图元也就没有印出来的答案，退回按几何估读的那一类。印出来的值是零容差的答案，而认领它的正是标注框。

**判据是「留不留得出空隙」，不是「压掉了百分之几」**，因为按比例算看不见最需要看见的那一种：两个标注紧挨着，压盖面积是零，读出来却是一串——`2 USD million2 USD millions` 是两个答案一串字。要留空隙的对象有两类：**已经画上去的别的标注**，以及**刻度标签**——刻度是键的出处，一个数字压在刻度上，赔进去的是一个键加一个值。

**写在图元外的标注带一圈背景色描边。**「在图元外」不等于「在底色上」：带状图、面积图、密散点上，紧挨着一个图元的位置正落在另一个图元上。印出来的值被当成精确答案，读不出来的那一个是写进数据里的错答案，不是一处不好看。

**一个画区里叠了两个视图时，写在图元外的标注取它所属系列的颜色。** 一个画区里只画一个视图，一种墨色就够了，每个标注旁边只有一种图元。叠了两个视图之后，两套数字落在同一批图元之间，一种墨色只剩位置可以用来分辨归属——条上的数与线上的数并排落着，谁也说不清哪个归谁。这不是观感问题：印出来的值是精确匹配的答案，一个归属不明的标注等于给两个图元各发了一个谁也证明不了归它的答案。系列色太浅读不出来时按同一色相压暗，引线也取同一种墨色。压盖那条 15% 的规则管的是"叠在一起"，管不了"不叠但分不清归谁"，所以两条都要有。

**渲染不回头。** 一份 FigureSpec 配一份风格向量只画一次：判定不通过的点直接从值目标里去掉，不调轴范围，不补画标注，不重画。被去掉的图元仍然贡献"键 + 区域"的定位目标。

同一份 FigureSpec 配**不同**的风格向量各画一次是另一回事：它是[风格配对样本](05_output.md#4-同一份记录还能派生什么)，也是 [04 §6](04_record.md#6-三项自检) 第三项自检的输入。两份记录的键与值必须完全相同，因此记录里存着这是第几个风格版本——同一份 FigureSpec 被有意画了不止一次，版本号是它身份的一部分，不是文件名的细节。
