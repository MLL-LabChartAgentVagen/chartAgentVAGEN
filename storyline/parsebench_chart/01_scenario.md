## 1. 领域池

一次性构建、之后反复复用的 200+ 细粒度子领域池。两级：Topic → Sub-topic。

**怎么建**

```
1  生成 topic          一次调用产出 N 个互不重叠的行业级大类，把已有的 topic 一并传入避免重复
2  逐 topic 生成 sub-topic   每个 topic 下产出若干个具体的分析情境，附实体、指标、时间粒度提示
3  去重                对名称做 embedding 相似度检查，余弦 ≥ 0.80 的成对标出，删掉或重生成
4  补齐                统计复杂度三档与 topic 覆盖，缺哪档补哪档，直到 200+ 且三档大致均衡
```

第 3 步的检查器只有一个实现，topic、sub-topic、[§2](#2-场景实例化) 的场景三处共用，区别只是传进去的字符串列表和阈值。

**怎么采**：按复杂度分档，档内无放回随机抽。某档抽掉 80% 后把该档标记重置，避免长期偏向后进池的条目。抽样由随机种子决定，同一个种子给出同一串子领域。

## 2. 场景实例化

抽一个子领域 → 一次 LLM 调用产出场景描述。输入是该子领域的全部字段（名称、复杂度、实体提示、指标提示、时间粒度提示），提示词里带一个完整的输入-输出样例来固定格式。

| 字段 | 内容 |
|---|---|
| `scenario_title` | 含时间段、机构、分析焦点的具体标题 |
| `data_context` | 谁收集、为何收集、何时收集 |
| `key_entities` | 3–8 个具名实体，用真实世界的名字，不用「实体 A」 |
| `key_metrics` | 2–5 个可量化指标，每个带正确单位与合理取值范围 |
| `temporal_granularity` | hourly / daily / weekly / monthly / quarterly / yearly |
| `target_rows` | simple 200–500 · medium 500–1000 · complex 1000–3000 |
| `analytical_intent` | 见下节 |

子领域给的提示是软约束：具体场景需要时可以改写或替换，但不能越出该子领域的范围与复杂度档位。

**场景去重**：对 `data_context` 做 embedding 检查，余弦 ≥ 0.85 判为重复，保留先生成的那条。两个语义相邻但不同名的子领域（「急诊等待时间」与「门诊分诊延迟」）会产出几乎一样的场景，这一步专门挡它。

## 3. 分析意图

2–4 条，每条是一个分析动作：这份数据被收集来回答什么问题。

它是 [03](03_figure.md) 选图的输入，也是 caption 的来源。意图不指定图表类型，只描述要看什么。

| 意图 | 蕴含的视图形态 |
|---|---|
| 找出表现最差的 / 识别瓶颈 | 排序比较 → 条形族 |
| 优化高峰时段 | 时间 × 实体 → 趋势族 / 热力图 |
| 理解构成变化 | 部分与整体随时间 → 构成族 |
| 检验两个指标是否相关 | 双数值 → 关系族 |

---

## 4. 约束

- 本阶段不出现任何图表类型词汇。数据源于业务需求，图表是数据的投影，选择权在 [03](03_figure.md)。
- 所有数字、实体、时间窗口须落在合理的真实世界范围内。
- 严格 JSON 输出，无附加说明。

## 5. 示例

抽到的子领域：

```json
{"name": "急诊科运营分析", "topic": "Healthcare", "complexity_tier": "medium",
 "typical_entities_hint": ["医院", "科室", "分诊等级"],
 "typical_metrics_hint": [{"name": "wait_time", "unit": "分钟"}],
 "temporal_granularity_hint": "daily"}
```

产出的场景：

```json
{"scenario_title": "2024 上半年 A 市三家三甲医院急诊科就诊与等待时间记录",
 "data_context": "A 市卫健委为评估急诊分流政策的效果，汇总了三家三甲医院 2024 年 1 至 6 月的逐次就诊记录。",
 "key_entities": ["协和", "华山", "瑞金", "内科", "外科", "儿科", "创伤", "轻", "中", "重"],
 "key_metrics": [{"name": "wait_minutes", "unit": "分钟", "range": [5, 120]},
                 {"name": "cost", "unit": "元", "range": [80, 3000]},
                 {"name": "satisfaction", "unit": "分", "range": [1, 5]}],
 "temporal_granularity": "daily",
 "target_rows": 900,
 "analytical_intent": ["哪家医院、哪个科室的等待时间最长",
                       "等待时间在半年内怎么变化",
                       "等待越久是不是满意度越低"]}
```

三条意图分别会在 [03](03_figure.md) 落到条形图、折线图、散点图上——但这是 03 的判断，本阶段不涉及。

## 附录：领域条目

```json
{
  "id": "dom_001",
  "name": "ICU 床位周转分析",
  "topic": "Healthcare",
  "complexity_tier": "complex",
  "typical_entities_hint": ["医院", "ICU 病区", "患者类别"],
  "typical_metrics_hint": [
    {"name": "occupancy_rate", "unit": "%"},
    {"name": "length_of_stay", "unit": "天"}
  ],
  "temporal_granularity_hint": "daily"
}
```

池文件另存版本号、生成时间、复杂度分布与 topic 覆盖统计，用于检查均衡性。

| 复杂度 | 含义 |
|---|---|
| simple | 单一实体类型，1–2 个指标，直接的时间序列 |
| medium | 多个相关指标，2 个以上实体类型 |
| complex | 嵌套层级，3 个以上相互依赖的指标 |
