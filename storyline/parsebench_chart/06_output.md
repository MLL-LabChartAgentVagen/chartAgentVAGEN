# 06 · 输出与评测

## 1. 输出格式

模型的输出单位是 **`(键, 值, 区域)`** —— 抽取每个值的同时给出读它的那块像素区域。

它对既有任务优雅降级：

| 丢掉 | 得到 | 对应基准 |
|---|---|---|
| 区域 | `(键, 值)` | chart-to-table |
| 值 | `(键, 区域)` | chart grounding |
| 都保留 | 带位置的转录 | 目标能力 |

L2 在此基础上多一列：`(键, 值, 区域, 行数)`。

带位置的输出**能自己验自己**：区域里没有图元、或者区域的像素几何与声称的值对不上，这两件事在没有 ground truth 的条件下也能查出来，可以直接用作强化学习的可验证奖励。这与 [05 §6](05_provenance.md) 的前两项自检是同一段计算，实现一次、两处使用。

## 2. 训练目标

| 目标 | 依赖层 | 内容 |
|---|---|---|
| 带位置的表 | L1 | 所有图元的 (键, 值, 区域) 全集 |
| 抽查标注集 | L1 | ≤10 个点，从 `readable` 为真的图元里取；写了标注容差 0，否则 1% |
| 页面元素框 | L0 | 框 + 类别 |
| 图元定位 | L1 | 数据描述 → 区域。所有图元都可用，含读不出值的 |
| 图元读值 | L1 | 区域 → 值。只用 `readable` 为真的 |
| 图例绑定 | L1 | 图例项 → 它管哪几个面板 |
| 下钻 | L2 | 数据描述 → 背后有多少行 |
| caption | — | 由 [01](01_scenario.md) 的场景与分析意图得到 |

"值能不能读出"由 [05 §5](05_provenance.md) 逐图元判定并写在记录里，这里只做筛选。

抽查标注集的形式对齐 ParseBench Charts 维度的评测方式：每图 ≤10 个点、写出的值精确匹配、需要估读的值 1% 相对容差。

## 3. 数据构成

合成负责位置、来源、风格配对；真实图表负责风格分布。不做纯合成——合成与真实的风格差距是对任何纯合成工作的既定反对意见。

真实图表没有"值 + 区域"的配对标注，因此**只参与它的标注支持的那些目标**：

| 来源 | 能参与哪些目标 |
|---|---|
| 本流水线合成 | 全部八项 |
| 真实图表（现有 chart-to-table 数据集） | 带位置的表的 `(键, 值)` 部分、caption |
| 真实文档版面（现有版面数据集） | 页面元素框 |

混合比例是一个超参数，在 [§5](#5-消融) 的风格消融里一并测。

## 4. 评测

**主目标**

| 基准 | 维度 | 当前水平 |
|---|---|---|
| ParseBench | Charts（`ChartDataPointMatch`） | 最好 78.1%；多数专用 parser < 6% |
| ParseBench | Visual Grounding（Element Pass Rate） | 版面感知流水线 70–81%；纯 VLM 6–7% |
| ChartREG++ | point / bbox F1 | 最好 < 50% |
| ChartAB | grounding 与密集对齐 | — |
| LongChart VQA | grounding / pointing | 要求输出 bbox 时最好模型 85.5% → 57.6%，所有模型 mDIoU 为负 |

**边界条件**（要求不退化）：ChartQA、CharXiv-Reasoning、ChartQAPro

**鲁棒性**（检验风格向量）：CHART NOISe 扰动集

**覆盖度**（检验图表类型的广度）：ChartArena 的八个图表族、ChartX 的多模态对照

---

## 5. 消融

| 消融 | 检验什么 |
|---|---|
| 去掉区域输出，只训表 | **主张的失败判据**。若加上区域后数值精度低于对照，主张不成立 |
| 关掉 L2 | 一行一件事是否有实验支撑。若 grounding 指标不变，则在论文中降级 |
| 固定风格向量 | 风格多样性对真实基准迁移的贡献 |
| 全部写数值标注 | 从像素几何估读的能力贡献了多少 |
| 只用 Tier 1 图表类型 | 类型广度的边际收益 |
| 去掉真实图表 | 合成与真实的风格差距的实际影响 |

---

## 6. 主张

> 带位置的转录——抽取每个值的同时给出读它的区域——可以由单个 VLM 完成，而它的训练数据只能在渲染时记录产生：大规模的「值 + 区域」配对无法靠标注真实图表获得。这样训练出的模型在 chart-to-table 上持平专用 parser，同时达到版面感知流水线级别的视觉 grounding。

现状是没有任何单一方法在这两项上同时强：商业多阶段流水线两项都高，纯 VLM 在 grounding 上是个位数。

## 7. 示例

接[标注记录](05_provenance.md#7-示例)。同一张条形图导出的目标：

**带位置的表**

```
("协和",)  42.3  [168, 196, 278, 520]
("华山",)  35.8  [423, 245, 533, 520]
("瑞金",)  28.1  [678, 305, 788, 520]
```

**抽查标注集**（三个图元 `readable` 都为真，且都没写标注，因此容差 1%）

```
("协和",)  42.3 ± 0.42
("华山",)  35.8 ± 0.36
("瑞金",)  28.1 ± 0.28
```

**图元定位**：`"协和的平均等待时间" → [168, 196, 278, 520]`

**图元读值**：`[168, 196, 278, 520] → 42.3`

**下钻**：`"协和的平均等待时间背后有多少次就诊" → 372`

**caption**：由意图① "哪家医院、哪个科室的等待时间最长" 与场景标题生成。

**页面元素框**：来自 L0，图表本身是一个 `Picture`，上方正文是 `Text`，下方图注是 `Text`。

如果这张图的 y 轴值域被风格采样成 `[0, 6000]`，三个图元的 `readable` 变为假，则**抽查标注集与图元读值两项为空，其余六项不变**。图仍然有用，只是不再要求模型报数。
