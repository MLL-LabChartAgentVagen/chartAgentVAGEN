把渲染时记下的东西拼成一份完整记录，判断每个值能不能从图上量出来，并做三项自检。

**这一阶段全部由程序执行，不调用 LLM。**

## 0. 示例

输入是 [03](03_render.md#0-示例) 渲染出的条形图与它的几何。

### 第一步 · 拼接三层

三份记录各由知道它的组件写出，按 `(figure_id, panel_id, key)` 对齐拼起来：

```
L0  来自页面合成器与文字块   图表是一个 Picture，页眉是 Page-Header，正文与图注是 Text；
                     图号、标题、副标题、单位、出处、两个轴标题各自是一个带角色的框
L1  来自渲染器       三个条的框、键、值、靠哪条轴按哪种形状量；绘图区与两条轴的值域像素域
L2  来自 02 的投影   Mercy General 372 行 · St. Luke's 315 行 · Riverside 213 行
```

拼完的 Mercy General 那个条：

```json
{"mark_id": "m0", "panel_id": "p0",
 "key": ["Mercy General"], "key_src": ["axis_tick"],
 "values": {"value": 42.3},
 "box": [165, 186, 269, 480],
 "channel": "length", "mark_shape": "rect", "value_axis": "y",
 "labeled": false,
 "rows": 372}
```

```json
{"panel_id": "p0", "box": [96, 132, 820, 480], "chart_types": ["bar"],
 "axes": [{"role": "y", "value_range": [0, 50], "pixel_range": [480, 132],
           "scale": "linear", "column": "wait_minutes"},
          {"role": "x", "value_range": [-0.5, 2.5], "pixel_range": [96, 820],
           "scale": "linear", "column": "hospital"}]}
```

### 第二步 · 判断值能不能量出来

这张图没写数值标注，条形的画法是长度，所以要算精度够不够。用的是这个图元自己说的那条轴（`value_axis` 是 `y`）：

```
每像素代表    50 分钟 / 348 像素 = 0.14 分钟
42.3 的 1%    0.42 分钟  =  0.42 / 0.14 ≈ 2.9 像素
2.9 ≥ 2       →  readable = true
```

三个条都通过，各自加上 `"readable": true`。

三个读不出的对照：

- 若风格采样让这张图与另一个面板共享 y 轴、值域变成 `[0, 6000]`，每像素代表 17.2 分钟，42.3 的 1% 只有 0.02 像素 → `readable = false`。图仍然产出三个条的位置，只是不产出它们的值。
- 同一批里的 `pie(department × SUM(wait_minutes))`，画法是角度，半径 125 像素给出步长 `ε = 0.0076`。没写标注时，1% 容差下四个扇区全部 `readable = false`，5% 容差下份额超过 1/7 的读得出，问的是 `share`；写了标注则全部为 true、容差为 0，问的是 `value`。
- 散点的键最后一段是行标识，`key_src` 记的是"页面上不写"。这个点仍然找得到，但没有哪个问题的答案是它的值，所以它也退出值目标。

**这里的 1% 是调用方传进来的。** 抽查标注集传基准自己的口径，自检与奖励传像素能分辨的量，见 [chart_types.md §4.1](chart_types.md#41-容差是参数不是判据的一部分)。

### 第三步 · 三项自检

```
框里有没有东西   取 [165,186,269,480] 内的像素，与这个面板自己的底色比，非底色占 97%   通过
量出来的值对不对  (480 − 186) × 0.1437 = 42.25，与记录的 42.3 差在这条轴的松弛内   通过
换风格答案变不变  另一份风格向量渲出的记录里，三个键对应的值仍是 42.3 / 35.8 / 28.1   通过
```

任何一项不过就丢掉这张图并记原因。

### 多面板与叠放的差别

[02](02_figure.md#0-示例) 的图④是两个面板并排共享 y 轴，`grouped_bar` 的第二段键写在图例里。记录里多出来的是：

```json
{"legend": [{"box": [265, 524, 338, 546], "maps_to_category": "Surgery",
             "applies_to_panels": ["p0", "p1"]}]}
```

单面板图上 `applies_to_panels` 恒为一个元素，是平凡的；一个图例项同时管两个面板时它才有信息量，这是`图例绑定`训练目标的全部来源。两个面板各自记一份 `panels[]`，图元用 `panel_id` 指向自己所在的面板。

图⑤ 把两个视图叠进同一块绘图区，于是这一个面板的 `chart_types` 有两项、`axes` 有 `y` 与 `y_right` 两条，每个图元用 `value_axis` 说自己靠哪条量、用 `mark_shape` 说自己按哪种形状量。**这两样不能让下游从图表类型反推**——这个面板有两个图表类型。

一份完整记录：三层数据 + 每个图元的 `readable`。[05](05_output.md) 只读这份记录，不需要知道事实表和渲染器。

## 1. 三层

```
L0  几何    页面上有哪些框、框是什么类别、里面写着什么字   纯像素事实，无数据语义
      ▲
L1  编码    框对应哪个键、哪个值，键的每一段从哪读出来   图 → 数据
      ▲
L2  来源    这个值由多少行原始记录聚合而来               数据 → 来源
```

| | 给谁用 | 前提 |
|---|---|---|
| **L0** | 页面级定位 | 任何渲染器 |
| **L1** | 带位置的转录、图例绑定、键的来源 | 边画边记的渲染器 |
| **L2** | 下钻 | 一行一件事的事实表 |

三层各自可以单独关掉。L2 关掉重训是 [05](05_output.md#7-消融) 的关键消融。

## 2. 谁产出哪一层

每层由知道该信息的那个组件直接写出，没有哪个组件需要反推另一个组件的内部状态。

| 层 | 谁产出 | 什么时候 |
|---|---|---|
| L2 | [02](02_figure.md) 的投影器 | 聚合时顺带返回每组的 `COUNT(*)` |
| L1 | [03](03_render.md) 的渲染器 | 画每个图元时记下框、键、值、靠哪条轴按哪种形状量 |
| L0 | [03](03_render.md) 的页面合成器与文字块 | 排页面元素时记下框、类别与**画出来的那个字符串** |

拼接是查表连接，不做任何推断。

## 3. 记录字段

一条记录对应一张图像。

```
figure_id, scenario_id, image_path, image_size, style_vector, degradation
page_id     与哪些图共享同一张页面图像
variant     这是第几个风格版本
caption     这张图是干什么的，一句话。它不画在图上

L0  elements[]     box, category, text, panel_id
                   category ∈ {Text, Table, Picture, Page-Header, Page-Footer}
                              ∪ {图号, 标题, 副标题, 单位, 出处, 注, 轴标题, 图例标题}
                              ∪ {刻度标签}
    layout         绘图区，以及围着它切出来的每个块：名字、在哪条边、框

L1  panels[]       panel_id, box, chart_types[],
                   axes[]  → role ∈ {x, y, y_right}, value_range, pixel_range, scale, column
    marks[]        mark_id, panel_id, key, key_src[], values{}, box,
                   channel, mark_shape, value_axis, labeled, label_box, readable
    legend[]       box, maps_to_category, applies_to_panels[]

L2  marks[].rows   该图元背后的原始行数
```

- **`key` 是有序字符串元组**，例如 `("Mercy General",)`、`("Mercy General", "Surgery")`、`("2024-03", "Mercy General")`。它唯一确定这个图元对应表里的哪一组，也是 [05](05_output.md) 输出格式里的"键"。
- **`key_src` 与 `key` 平行**，一段一个来源，取值见 [02 §5](02_figure.md#5-键的每一段从哪读出来)。记一个图级的来源回答不了任何一个问题：同一个键，医院名可能在面板标题上，也可能在图例里。
- **`value_axis` 与 `mark_shape` 是"这个值是怎么读出来的"**：靠面板的哪条轴量、按哪种几何量。单视图的面板上两者都能从图表类型反推，但一块绘图区里可以叠两个视图，而导出程序不许回头去读 FigureSpec。
- **`axes` 的 `value_range` 与 `pixel_range`** 是 [§5](#5-值能不能读出) 与几何自检的全部输入。叠放两个测度的面板有 `y` 与 `y_right` 两条，各绑一个测度。
- **`elements[].text` 是画出来的那个字符串**，不是 FigureSpec 里要求画的那个：折行、截断、脚注星号都会改它，页面才是 ground truth。属于某个面板的元素（面板标题）另带 `panel_id`。
- **`legend[].applies_to_panels`**：共享图例下"这个图例项管哪几个面板"是模型的已知失败模式，这里零成本产出它的答案。
- **L2 存行数不存行**：需要真实的行时用 `key` 回去过滤事实表即可确定性还原，记录体积小一个量级。
- **`variant` 是身份的一部分**：同一份 FigureSpec 被有意画了不止一次，两份的键与值必须相同、像素不同，它们既是配对样本，也是第三项自检的输入。

## 4. 图元形状

不同图表类型的图元形状不同：条形是矩形带一个值，箱线是箱体带五个值，折线是点，散点是点带两个值，热力图与表格图是格子，风筒图是一条带。

**用组合表达，不用继承**：图元带一个值字典而不是一个标量。条形填一个键，箱线图填五个。下游对图元做的事完全一样——取框、取值——所以不存在需要多态的行为。

17 种类型共 6 种形状，各形状的值字典键见 [chart_types.md §3](chart_types.md#3-图元形状)。形状还决定[几何自检](#62-几何自检量的是哪两条边)量的是哪两条边。

## 5. 值能不能读出

逐图元判定，输入只有 L1 里的实际几何与该图元的画法。判据在 [chart_types.md §4](chart_types.md#4-值的画法) 定义，本阶段只是执行它，结果写成 `readable` 字段。**容差由调用方给**：抽查标注集问的是"基准的口径下这个值该不该要求报出来"，自检与奖励问的是"像素能不能分辨到这一步"，两者是不同的问题，答案也不同。

两种情况让一个图元丢掉值目标：

```
画法到不了这个容差   颜色一律到不了；角度看份额与半径；长度与位置看容差折算成几个像素
键找不回来           key_src 里有一段是"页面上不写"
```

第二条是把来源逐段记下来的用处：散点的每个点由一个行标识指认，而页面上一个字都没写它——这个点仍然找得到，但没有哪个问题的答案是它的值。

**刻度标签也记一个框。** 它是键的出处：一个图元已经记下自己的键读自刻度，框说的是**哪一个**刻度——这与 `(值, 框)` 对值的主张是同一件事，只是主语换成了键。它不进页面元素目标：那份目标说的是基准的词表，在那套词表里整张图就是一个 `Picture`；键从哪读是键出处目标的问题。

记下来当场就抓住了两处版面缺陷：底边距不够时轴标题被钳进刻度那一行、写在刻度标签上；网格上一行面板的斜排刻度伸进下一行的面板标题条。两处都是丢一个键，两处在框记下来之前都看不见。

**画区怎么切也记下来**，写成 `Record.layout`：绘图区，加上每个块的名字、它占了哪条边、它的框。图例在右边和图例在底部把同一批名字放在不同的地方，而一个从图例读出来的键，它的位置是答案的一部分。样式说的是请求，记录说的是结果——侧边装不下退回底部，退回这件事在这里。

**问哪个数也在这里定**，写成 `Mark.value_key`。它与"读不读得出"是同一个决定：扇区带着值和份额两个数，角度只给得出份额，一个被问了值的扇区会同时是"可读"和"错的"。

**带五个数的图元问的是框跨过的那一对里远的那一端**——箱线问上四分位，误差棒与风向标问最大值。中位数不在框的任何一条边上：读回时没有锚点能确认它，一个问中位数的值目标是奖励路径查不了的目标。这一对来自读回自己那张表，所以问的和能查的从构造上不会分家。改之前实测：箱线 28 个图元、误差棒 10 个，值目标 0 个。

读不出的图元从 [05](05_output.md) 的值目标里去掉，**仍保留在定位目标里**。饼图、热力图整张图的值目标可能全空，密度档抬高之后各类图的值目标占比都会往下走——这是判据的预期结果，不是缺陷，见 [chart_types.md §4.2](chart_types.md#42-密度上去了值目标占比就会下来)。

## 6. 三项自检

记录写盘前必须通过，任何一项失败就丢掉这张图并记下原因。这三项是整个流水线的正确性底线——边画边记依赖绘图库内部的坐标变换，错了不会抛异常，只会安静地产出偏移的框。

| 检查 | 怎么做 | 挡住什么 |
|---|---|---|
| **框里有没有东西** | 回读渲染出的 PNG，取框内像素，看非底色的占比够不够 | 框整体偏移、自动布局挪动了绘图区、dpi 换算错 |
| **量出来的值对不对** | 用框的像素位置与该图元所依那条轴的值域、像素域反算出值，与记录的值比对 | 轴映射错误、对数轴处理错误、负值与堆叠基线错误 |
| **换风格答案变不变** | 同一 FigureSpec 的两份风格版本，记录里的「键 → 值」集合必须完全相同 | 某个风格参数意外改了数据 |

前两项逐图元跑，第三项按图抽样跑。三项都在生产路径上，不是测试——边画边记的错误只会在真实数据上暴露，测试里的固定样例覆盖不到。

**允许少数图元不过**：超过 5%（至少一个）才丢图。绘图区边缘裁掉一个图元不该让整张图报废，而系统性的偏移会在所有图元上一起出现。

第三项不需要额外渲染。风格配对样本本来就要对同一份 FigureSpec 渲两份，这两份记录既是[消融与配对数据](05_output.md#4-同一份记录还能派生什么)，也是这项自检的输入——渲一次，两处用。

**前两项只用图像与模型自己的输出，不用 ground truth，因此同一段代码可以直接当作可验证奖励用在训练上。** 见 [05 §3](05_output.md#3-输出能自己验自己)。

### 6.1 底色是读出来的，两种情况没有可判的东西

**底色从面板自己的像素里读，不假定是白的。** 读的是面板顶端那一条与左右两侧那两列，不是整个面板：绘图区是从基线往上填的，堆叠面积图可以铺满大半个面板而顶上那条仍然空着；拿整个面板里最常见的颜色当底色，会把填充当成底色，于是画在填充里的每个图元都被判成"框里什么都没有"。

两种情况下这一项没有可判的东西，直接放行并写明理由：

| 情况 | 为什么 |
|---|---|
| 图元没有内部（不到 2 像素宽或高） | 一个不含任何行的直方图箱就是一个零高的矩形。里面什么都没有，因为本来就没有东西可放 |
| 面板被铺满（热力图） | 它把整块绘图区都涂上了颜色，没有底色可比，"框里有没有东西"在这里问不出有区分度的答案 |

数值印出来的图元（表格图）另算：要看的是那几个字，不是装它们的格子——所以看的是标注框，占比门槛也低得多，字永远填不满一个格子。

**点图元也另算**，理由一样。一个点的框是画在那里的记号周围一个固定大小的方块，这是有意的：值从框心读出来，框就不能随风格挑了哪种记号而变。于是记号填掉方块的多少是记号形状的性质，不是"画没画出来"的性质——实心圆填掉大半，竖线只填中间一道。逐记号逐 dpi 在散点上量过（散点的点没有折线穿过去添墨），最薄的一种是 72 dpi 下的竖线，填 6%；框挪到空白处填 0%。门槛取 3%。

### 6.2 几何自检量的是哪两条边

只有落在框的边上的那些值能拿去和像素比。哪几个值落在边上，是**图元形状**的性质，不是数字的性质：

| 形状 | 量哪里 |
|---|---|
| 普通矩形 | 离基线远的那条边上的 `value`（直方图量 `count`） |
| 堆叠段 | 它的两个累计值之间 |
| 箱体 | 两个四分位之间——须线伸到极值，但框画的是四分位矩形 |
| range_bar / error_bar | 两个极值之间 |
| 散点 | 同时量两条轴：纵向是 `y`，横向是 `x` |
| 扇形 | 不从框上量。沿着面板记下的圆走一圈，一色的一段就是一个扇区，量的是它的份额 |
| 格子 | 不量。颜色本来就不是从框的边上读的 |

**留在外面的那些值不是漏掉的。** 堆叠段的 `value` 是两条边之差，本身不在任何一条边上；直方图的箱边界量出来的是条宽而不是计数。把它们纳进来，只会让自检因为一些它的几何本来就够不着的量而丢掉好图。

**扇形走的是另一条路，不是不走。** 它的值是一个角度，量角度要有圆心，而绘图区的矩形给不出圆心——所以面板把它的圆（圆心、内半径、外半径）记下来，和它记下值轴的值域与像素域是同一件事。分段靠的是"扇区之间的界线是径向的"：沿六个半径各走一圈，六个半径在同一个角度上都变色才算一条边界，纹理、描边与标注都不是径向的因而不算。量出来的份额只用像素与这个圆，与被检查的那个数无关。认不准就返回"量不了"而不是"判错"。判据、算式与实测数字见 [chart_types.md §4.3](chart_types.md#43-判得出还要验得了)。

从两条边之间量出来的值，读了两次数，因此松弛加倍。记录的值本身若落在某个步长上（整数、半个、0.1、0.01），半个步长是松弛的下限：一个保留一位小数的列，误差可以到 0.05，而在一个接近 4 的评分上这比 1% 还大。
