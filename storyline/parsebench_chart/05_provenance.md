# 05 · 溯源记录

渲染器在输出图像的同时，输出一份描述"画了什么"的结构化记录。三层，逐层信息严格增加，各自独立开关。

**本文**
1. [三层](#1-三层) → 2. [L0 几何](#2-l0-几何) → 3. [L1 编码](#3-l1-编码) → 4. [L2 溯源](#4-l2-溯源) → 5. [Mark 的形状](#5-mark-的形状)

---

## 1. 三层

```
L0  几何    有哪些框、框属于什么类别         纯像素事实，无语义
      ▲
L1  编码    框编码哪个 (键, 值)、图例映射      视觉 → 数据
      ▲
L2  溯源    值由多少行原子事件聚合而来          数据 → 来源
```

| | 消费者 | 前提 |
|---|---|---|
| **L0** | 页面级 grounding | 任何渲染器 |
| **L1** | grounded transcription、图例绑定 | 插桩渲染器 |
| **L2** | drill-down | 原子粒度事实表 |

分层边界同时对应不同的消费者、不同的渲染器能力要求、以及不同的可证伪性——L2 可单独关掉重训，构成 [06](06_output.md) 的关键消融。

---

## 2. L0 几何

页面上所有元素的框与类别，类别取自 `{Text, Table, Picture, Page-Header, Page-Footer}`。不含数据语义。

依赖 [04 §3](04_render.md) 的页面合成；不渲染进页面时这一层退化为平凡。

---

## 3. L1 编码

视觉到数据的映射，三类对象：

**Mark** — 框、所属面板、代表的键、承载的值、图上是否画出了该数值（及标注框）

**Panel** — 框、纵轴值域、纵轴像素域

> 值域与像素域这两组数供 [03](03_figure.md) 的值可恢复性判据计算。

**LegendEntry** — 色块框、映射到哪个类别、**适用于哪些面板**

> 共享图例下"该图例项适用于哪些面板"是模型的已知失败模式，此处零成本产出其 ground truth。

---

## 4. L2 溯源

每个 mark 对应多少行原子事件。

**存键不存行**：只记录行数；需要真实行时用 mark 的键去过滤事实表即可确定性还原。记录体积小一个量级，信息不丢。

---

## 5. Mark 的形状

不同图表类型的 mark 在形状上有差异：条形是矩形带一个值，箱线图是矩形带五个值，折线是点，散点是点带两个值。

**用组合表达，不用继承**：mark 携带一个值字典而非单个标量。条形填一个键，箱线图填五个键。所有消费者对 mark 做的事情完全一致——取框、取值——因此不存在需要多态的行为。
