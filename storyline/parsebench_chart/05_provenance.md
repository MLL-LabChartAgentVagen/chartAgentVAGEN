# 05 · 溯源记录

流水线在输出图像的同时，输出一份描述"画了什么"的结构化记录。三层，逐层信息严格增加，各自独立开关。

**本文**
1. [三层](#1-三层) → 2. [谁产出哪一层](#2-谁产出哪一层) → 3. [L0 几何](#3-l0-几何) → 4. [L1 编码](#4-l1-编码) → 5. [L2 溯源](#5-l2-溯源) → 6. [Mark 的形状](#6-mark-的形状) → 7. [可恢复性判定](#7-可恢复性判定) → 8. [校验闸门](#8-校验闸门)

---

## 1. 三层

```
L0  几何    有哪些框、框属于什么类别         纯像素事实，无语义
      ▲
L1  编码    框编码哪个 (键, 值)、图例映射      视觉 → 数据
      ▲
L2  溯源    值由多少行原子事件聚合而来          数据 → 来源
```

| | 消费者 | 前提 |
|---|---|---|
| **L0** | 页面级 grounding | 任何渲染器 |
| **L1** | grounded transcription、图例绑定 | 插桩渲染器 |
| **L2** | drill-down | 原子粒度事实表 |

分层边界同时对应不同的消费者、不同的渲染器能力要求、以及不同的可证伪性——L2 可单独关掉重训，构成 [06](06_output.md) 的关键消融。

---

## 2. 谁产出哪一层

每层由知道该信息的那个组件直接产出，没有组件需要反推另一个组件的内部状态。

| 层 | 产出者 | 时机 |
|---|---|---|
| L2 | [03](03_figure.md) 的视图投影器 | 聚合时顺带返回每个分组的 `COUNT(*)` |
| L1 | [04](04_render.md) 的插桩渲染器 | 绘制每个 mark 时记录框、键、值 |
| L0 | [04](04_render.md) 的页面合成器 | 排布页面元素时记录框与类别 |

三份记录按 `(figure_id, panel_id, key)` 合并成一条溯源记录。合并是纯连接操作，不做任何推断。

---

## 3. L0 几何

页面上所有元素的框与类别，类别取自 `{Text, Table, Picture, Page-Header, Page-Footer}`。不含数据语义。

依赖 [04 §4](04_render.md) 的页面合成；不渲染进页面时这一层退化为平凡。

---

## 4. L1 编码

视觉到数据的映射，三类对象：

**Mark** — 框、所属面板、代表的键、承载的值、图上是否画出了该数值（及标注框）、编码通道

**Panel** — 框、纵轴值域、纵轴像素域、绑定的轴（compound 图有左右两个）

> 值域与像素域这两组数供 [§7](#7-可恢复性判定) 计算。

**LegendEntry** — 色块框、映射到哪个类别、**适用于哪些面板**

> 共享图例下"该图例项适用于哪些面板"是模型的已知失败模式，此处零成本产出其 ground truth。

---

## 5. L2 溯源

每个 mark 对应多少行原子事件。

**存键不存行**：只记录行数；需要真实行时用 mark 的键去过滤事实表即可确定性还原。记录体积小一个量级，信息不丢。

---

## 6. Mark 的形状

不同图表类型的 mark 在形状上有差异：条形是矩形带一个值，箱线图是矩形带五个值，折线是点，散点是点带两个值。

**用组合表达，不用继承**：mark 携带一个值字典而非单个标量。条形填一个键，箱线图填五个键。所有消费者对 mark 做的事情完全一致——取框、取值——因此不存在需要多态的行为。

各类型的值字典键见 [registry.md §3](registry.md)。

## 7. 可恢复性判定

**图上标的那个数，能不能从图上量出来。** 渲染完成后逐 mark 计算，输入只有 L1 的实际像素几何与 [registry.md §4](registry.md) 的编码通道。

```
画出了数值标注        → 可恢复，容差 0
未画且通道为 angle / area / color  → 不可恢复
未画且通道为 length / position     → 1% 的值域跨度 ≥ 2 像素时可恢复
```

> 纵轴 0–6000、绘图区高 400 像素 → 1 像素约 15 个单位。值 4521 的 1% 是 45 个单位约 3 像素，量得出来。
> 若纵轴改为 0–600000 → 1 像素约 1500 个单位，4521 的 1% 只有 0.03 像素，量不出来。

不可恢复的 mark 从 [06](06_output.md) 的值目标集中排除，仍保留在定位目标集中。判定结果作为一个布尔字段写进 mark 记录，因此 06 的目标导出是溯源记录的纯函数。

---

## 8. 校验闸门

溯源记录写盘前必须通过三项检查。任何一项失败则丢弃该图并记录原因。这三项检查是整个流水线的正确性基线——L1 插桩依赖后端内部的坐标变换，是最容易出错的一环。

| 检查 | 做法 | 拦截什么 |
|---|---|---|
| **像素一致性** | 回读渲染出的 PNG，验证每个 mark 的框内确实有该 mark 声称的颜色的像素 | 框错位、`tight_layout` 或 dpi 造成的坐标漂移 |
| **几何一致性** | 用 mark 框的像素高度与 panel 的值域/像素域反解出值，与声称的值比对 | 轴映射错误、对数轴与负值处理错误、堆叠基线错误 |
| **风格不变性** | 同一 FigureSpec 用两个不同风格向量各渲染一次，两份记录的 `(键, 值)` 集合必须完全相同 | 风格参数意外影响了数据 |

前两项逐 mark 执行，第三项按图抽样执行。
