# Grounded Transcription — Chart Data Generation

程序化生成图表数据，产出的每个数值都带着它被画在哪里的坐标。目标能力是 **grounded transcription**：把图表转成结构化表的同时，给出每个值读取自哪块像素区域。

---

## 流水线

四个执行阶段，两个契约。

```
 01  域池与场景     领域 → 场景上下文 + 分析意图                    [LLM]
      ▼
 02  原子事实表     LLM 写 DGP 程序 → 行级事件表 + Schema Metadata   [LLM 写程序]
      ▼
 03  选图           枚举 → 确定性过滤 → LLM 在候选中选择 → FigureSpec  [LLM 选择]
      ▼
 04  渲染           风格向量独立采样 → 页面图像 + 几何记录            [无 LLM]
- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
 05  溯源记录       三层记录的格式、可恢复性判定、校验闸门            契约
 06  输出与评测     溯源记录 → 训练目标 → 基准                       契约
```

05 与 06 不是执行阶段：05 定义三层记录的数据格式与它必须通过的检查，06 定义从记录到训练目标的纯函数。

## 不变式

1. **原子粒度** — 事实表每行是一个不可分事件；聚合只发生在 SQL 投影里。
2. **LLM 不生产数值** — LLM 只做两件事：写 DGP 程序、在确定性枚举出的选项中做选择。进入图表的每个数字都来自引擎计算。
3. **标注零成本且精确** — 所有 ground truth 由渲染器内部状态导出，不经过估计或人工标注。
4. **风格与真值分离** — ground truth 由 FigureSpec 决定，对风格向量不变。同一 FigureSpec 可渲染 N 个视觉版本共享一份答案。
5. **单向流水线** — 每个阶段是 `(输入, seed) → 输出` 的纯函数，阶段之间没有回环，没有重试后重渲染。
6. **几何单一来源** — 只有一个插桩后端产出像素几何，只有一套坐标约定。

## 相对上一版的改动

| 改动 | 原设计 | 现设计 |
|---|---|---|
| 03 的三步顺序 | 枚举 → LLM 选择 → 过滤 | 枚举 → 过滤 → LLM 选择。LLM 只在候选清单里挑序号，选不出不可行的图，取消验证-重选回环 |
| 语义适当性 | 由 LLM 判断"真人会不会画这张图" | 查表：测度可加性与维度有序性在 [02](02_fact_table.md) 声明，[03](03_figure.md) 只做匹配 |
| 值可恢复性 | 在 03 预测，与 04 形成回环 | 移到渲染之后按实际像素几何判定，并按编码通道分类（角度/面积/颜色通道无标注时一律不可恢复） |
| 溯源记录的产出者 | 渲染器同时输出三层 | 各层由知道该信息的组件产出：投影器→L2，插桩渲染器→L1，页面合成器→L0，再做一次纯连接 |
| 渲染后端 | matplotlib / plotly / 企业模板三选一 | 单一插桩后端；风格多样性来自后端内参数、图像退化、页面合成 |
| 图表类型 | 16 型平铺 | 分三层交付，Tier 1 九型对齐 ParseBench Charts 的实际构成 |
| 正确性保证 | 未定义 | [05 §8](05_provenance.md) 三项校验闸门：像素一致性、几何一致性、风格不变性 |
