# 带位置的图表转录 — 数据生成

程序化生成图表数据，产出的每个数值都带着它被画在哪里的坐标。目标能力是 **grounded transcription（带位置的转录）**：把图表转成结构化表的同时，给出每个值读取自哪块像素区域。

---

## 流水线

四个执行阶段，两份数据接口定义。**LLM 只出现在 01 和 02**，且只产出声明与绑定，不产出任何数值。

```
 01  场景        领域 → 场景描述 + 分析意图                         用 LLM
      ▼
 02  事实表      LLM 写生成程序 + 意图绑定 → 事实表 + 表结构说明      用 LLM
      ▼          声明期即可枚举出这套 schema 能画的全部图
 03  选图        枚举 → 投影 → 数据过滤 → 挑图 → FigureSpec          全确定性
      ▼
 04  渲染        独立采样风格 → 页面图像 + 边画边记的几何             全确定性
- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
 05  标注记录    三层记录的字段、值能否读出的判定、三项自检            数据接口
 06  输出        标注记录 → 训练目标                                数据接口
```

05 与 06 不是执行阶段：05 规定 04 产出的那份记录长什么样、必须通过哪些检查，06 规定怎么把记录变成训练目标。

## 贯穿示例

六个阶段文档末尾都有「示例」一节，用的是同一份数据，从场景一路走到训练目标。

**急诊科等待时间**——A 市三家医院急诊科 2024 上半年的就诊记录。

| | |
|---|---|
| 维度 | `hospital` 协和 / 华山 / 瑞金 → `department` 内科 / 外科 / 儿科 / 创伤；`severity` 轻 / 中 / 重（ordinal） |
| 时间 | `visit_date` 2024-01-01 至 2024-06-30，按天 |
| 测度 | `wait_minutes` 分钟（可加）、`cost` 元（可加）、`satisfaction` 1–5 分（不可加） |
| 一行 | 一次就诊。共 900 行 |
| 分析意图 | ① 哪家医院等待最久 ② 等待时间随时间怎么变 ③ 等待时间与满意度是否相关 |

跟着这份数据可以看到：层级维度怎么声明、不可加的测度怎么在声明期就排除掉饼图、几百个候选怎么筛到八张、一个条形的框怎么算出来、值能不能从图上量出来。

## 不变式

1. **一行一件事** — 事实表每行是一次不可再分的事件；聚合只发生在 [03](03_figure.md) 的投影里。
2. **LLM 不生产数值** — LLM 只做两件事：写数据生成程序、把分析意图绑到列上。进入图表的每个数字都由引擎算出。
3. **可行性是查表，不是判断** — 能画什么图由列声明决定，[02](02_fact_table.md) 在生成数据之前就能算出来。
4. **标注零成本且精确** — 所有 ground truth 从渲染过程中直接记下来，不靠估计，也不靠人工标注。
5. **风格与真值分离** — ground truth 由 FigureSpec 决定，与风格无关。同一份 FigureSpec 可以渲染 N 个外观不同的版本，共享一份答案。
6. **单向流水线** — 每个阶段是"给定输入与随机种子就得到确定输出"，阶段之间没有回环，不存在重试后重新渲染。
7. **几何只有一个来源** — 只有一个渲染器产出像素坐标，全流水线只有一套坐标约定。
8. **元数据一次产出，多次投影** — 训练目标、问答对、风格配对、图表代码都是同一份记录的不同导出函数。
