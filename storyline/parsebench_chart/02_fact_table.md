# 02 · 事实表

LLM 写一段调用四个声明方法的 Python，描述数据是怎么产生的；确定性引擎执行它，产出行级事件表与表结构说明。

## 1. 四个声明方法

列声明在前，行产出在后。整段脚本没有循环，没有条件语句，只有这四个调用。

| 方法 | 作用 |
|---|---|
| `dim(name, values, weights, parent, ordered)` | 类别列。`parent` 表达层级，`weights` 可以是一个向量，也可以是按父值给出的条件分布；`ordered` 取 `None` / `"ordinal"`（取值有大小顺序，如轻/中/重）/ `"stage"`（取值是流程里依次经过的阶段，如分诊→就诊→住院） |
| `time(name, start, end, freq)` | 时间列。星期、月、季度、是否周末四个日历字段自动派生 |
| `measure(name, expr, unit, additive)` | 数值列。`expr` 是一个表达式字符串 |
| `emit(n)` | 产出 n 行 |

`unit`、`additive`、`ordered` 不影响数值生成，只服务下游：`unit` 决定 [04](04_render.md) 的轴标签与数字格式；`additive` 与 `ordered` 决定能画哪些图，见 [§3](#3-声明期就知道能画什么)。计数、金额、时长可加；比率、百分比、温度、评分不可加。流程类图表要求 `ordered="stage"`——有大小顺序不等于是流程阶段，把严重程度画成漏斗图没有意义。

**硬约束**

1. 每行是一件不可再分的事，不铺类别叉积
2. ≥2 个维度组、≥2 个数值列
3. 依赖关系必须无环
4. 表达式里每个符号都有显式数值定义
5. 每个数值列只声明一次，不靠后续调用打补丁
6. 每个数值列必须给出 `unit` 与 `additive`

## 2. 表达式

表达式描述一个数值列怎么算出来，可以用四种成分：

| 成分 | 写法 | 例 |
|---|---|---|
| 分布 | `gaussian` `lognormal` `gamma` `beta` `uniform` `poisson` `exponential` `mixture` | `lognormal(mu=2.8, sigma=0.35)` |
| 类别效应 | `[列=取值]` 作为 0/1 指示，或 `{取值: 数}[列]` 作为查表 | `0.9*[severity=重]`、`{轻:80, 中:260}[severity]` |
| 其他数值列 | 直接写列名 | `wait_minutes * 12` |
| 算术与裁剪 | `+ - * /`、`clip`、条件分段 | `clip(..., 1, 5)` |

**依赖从表达式里读出来，不用声明。** 解析表达式取出自由变量，凡是引用了另一个数值列就连一条边。`cost` 的表达式里出现 `wait_minutes`，边就建好了。

**统计模式也是表达式的一部分**，不是单独的注入接口。离群值是一个乘性条件项，趋势断点是一个关于时间的分段项，季节性是一个关于月份的正弦项。

## 3. 声明期就知道能画什么

声明解析完成、一行数据都还没生成时，**这套 schema 能画出哪些图已经完全确定**。[chart_types.md §1](chart_types.md) 的四类条件里，结构条件与语义条件只看列声明：`dim` 的取值列表给出基数，`time` 的 start/end/freq 给出时间点数，`additive` 与 `ordered` 是声明字段。

枚举器是一个查表函数：`列声明 → 候选视图清单`。它在这里跑一次，在 [03](03_figure.md) 拿实际数据再跑一次同样的规则，两次结果的差别只来自数据条件。

这带来两件本阶段独有的事。

### 3.1 覆盖度反馈

枚举结果直接反映 schema 设计得好不好，可以在同一个错误反馈环里回喂：

| 情况 | 原因 | 回喂内容 |
|---|---|---|
| 一个可加测度都没有 | 全是比率、评分 | 画不出任何构成类图（pie、stacked_bar、area、treemap） |
| 没有 `ordered="stage"` 的维度 | 只有无序或仅有大小顺序的类别 | 画不出流程类图（waterfall、funnel） |
| 类别基数全部 < 3 或 > 30 | 维度设计过窄或过宽 | 画不出比较类图 |
| 候选总数或覆盖的族数低于阈值 | schema 太单薄 | 一个场景只能产出少量图 |

这把"这套数据能撑起多少种图"变成了写脚本时就能看到的反馈，而不是跑完全程才发现。也可以反过来用：要求 schema 必须支撑指定的几个族，LLM 就会主动补一个可加测度或一个有序维度。

### 3.2 意图绑定

[01](01_scenario.md) 的分析意图是用场景自己的词汇写的自然语言，此时列还不存在。列是本阶段定义的，因此**把意图绑到具体列上只能在这里做**。

LLM 在输出脚本的同一次调用里，为每条意图给出：

```
目标列   这条意图关心哪个维度、哪个测度
视图类   比较 / 趋势 / 构成 / 关系 / 分布 / 流程
```

[03](03_figure.md) 拿到「目标列 + 视图类」后，在候选清单里做确定性匹配，不需要再调用 LLM。

### 3.3 数据条件只能算期望

变异系数与区分度依赖实际数值，声明期算不出来。每格支撑行数可以按 `emit(n)` 与声明的权重算期望值，用于覆盖度粗筛；精确判定在 [03](03_figure.md)。

## 4. 生成引擎

给定「声明 + 随机种子」逐位可复现，不调用 LLM。

```
构建全列依赖图 → 拓扑排序 → 三步执行

α  非数值列
   根维度按 weights 抽 n 次
   子维度按父值对应的条件分布抽
   时间列在 [start, end] 上按 freq 抽，再派生四个日历字段
β  数值列
   按拓扑序逐列整体求值，每列一次向量运算，不逐行循环
γ  后处理
   按声明的取值范围裁剪，按单位定小数位
```

**结构检查**（只有这一层，检查执行是否成功，不检查统计性质）

| 检查 | 判据 |
|---|---|
| 行数 | 在目标值 10% 以内 |
| 基数 | 每个类别列的实际取值数与声明一致 |
| 数值 | 每个数值列有限、非空、非常数 |
| 依赖 | 无环 |

基数这一条是 [§3](#3-声明期就知道能画什么) 成立的前提：声明期按声明的基数枚举，执行后必须对得上，否则候选清单就是错的。

不通过时换种子重掷，或把失败反馈给 LLM。**任何情况下都不改声明**——表结构说明必须始终描述实际生成出来的数据。

## 5. 错误反馈

```
LLM 输出脚本 + 意图绑定 → 隔离执行
  执行失败      → 声明方法抛出带语义的异常，代码 + 报错回喂
  覆盖度不足    → 枚举结果与缺口原因回喂
  结构检查不过  → 检查项与实际值回喂
  三者都过      → 进入 03
  重试上限 3 次，仍失败则跳过这个场景
```

异常必须指出具体违反了哪条约束，例如"`cost` 与 `revenue` 互相引用，环路为 cost → revenue → cost"、"表达式里的 `base_fee` 没有定义"、"lognormal 的 sigma 为 0"。只说"执行失败"的异常对重试没有帮助。

高频异常类型进提示词的约束段，不靠加大重试次数来解决。

## 6. 表结构说明

给 [03](03_figure.md) 用的那份数据接口。内容：

- **维度组**：每组有哪些列、层级链是什么、每列是否有序
- **列清单**：名称、类型（类别 / 时间 / 数值）、所属组、父列、基数；数值列另含单位与可加性
- **依赖图**：数值列的拓扑序与边
- **意图绑定**：每条分析意图对应的目标列与视图类
- **总行数**

---

## 7. 示例

LLM 为[急诊科场景](README.md#贯穿示例)写出的脚本：

```python
dim("hospital", ["协和", "华山", "瑞金"], weights=[0.40, 0.35, 0.25])
dim("department", ["内科", "外科", "儿科", "创伤"], parent="hospital",
    weights={"协和": [0.35, 0.25, 0.15, 0.25],
             "华山": [0.40, 0.20, 0.20, 0.20],
             "瑞金": [0.30, 0.30, 0.15, 0.25]})
dim("severity", ["轻", "中", "重"], weights=[0.50, 0.35, 0.15], ordered="ordinal")

time("visit_date", start="2024-01-01", end="2024-06-30", freq="daily")

measure("wait_minutes",
        "lognormal(mu = 2.8 + 0.4*[severity=中] + 0.9*[severity=重] + 0.2*[hospital=协和],"
        "          sigma = 0.35)",
        unit="分钟", additive=True)
measure("cost",
        "wait_minutes * 12 + {轻: 80, 中: 260, 重: 700}[severity] + gaussian(0, 30)",
        unit="元", additive=True)
measure("satisfaction",
        "clip(5.2 - wait_minutes / 32 + gaussian(0, 0.3), 1, 5)",
        unit="分", additive=False)

emit(900)
```

依赖图从表达式读出：`wait_minutes → cost`、`wait_minutes → satisfaction`，`wait_minutes` 是根。

**覆盖度检查**（此时还没生成任何数据）：

```
可加测度    wait_minutes, cost       → 构成类可画
基数        hospital 3 · department 4 · severity 3 · day_of_week 7 · month 6  → 比较类可画
时间点      182 天                   → 趋势类可画
两个数值列                           → 关系类可画
行数 900，每组行数充足                → 分布类可画
stage 维度  无                       → 流程类画不出，severity 只是 ordinal
最大二维叉积 7×6=42 格，期望每格 21 行 → 热力图可画
```

六族覆盖五族，高于阈值 3，通过。流程类缺一个 `ordered="stage"` 的维度——本场景里没有天然的流转阶段，不强行补。

**意图绑定**，与脚本在同一次调用里产出：

```
意图① 哪家医院、哪个科室的等待时间最长   目标列 hospital × wait_minutes    视图类 比较
意图② 等待时间在半年内怎么变化           目标列 visit_date × wait_minutes  视图类 趋势
意图③ 等待越久是不是满意度越低           目标列 wait_minutes × satisfaction 视图类 关系
```

执行后的事实表，每行一次就诊：

| visit_date | day_of_week | hospital | department | severity | wait_minutes | cost | satisfaction |
|---|---|---|---|---|---|---|---|
| 2024-01-03 | 周三 | 协和 | 外科 | 中 | 38.4 | 1002 | 4.0 |
| 2024-01-03 | 周三 | 瑞金 | 内科 | 轻 | 19.7 | 316 | 4.6 |
| 2024-02-11 | 周日 | 协和 | 创伤 | 重 | 92.1 | 1805 | 2.3 |
| … | | | | | | | 共 900 行 |

表结构说明：

```
维度组  entity = hospital(3) → department(4)      triage = severity(3, ordinal)
时间列  visit_date, daily, 182 天;  派生 day_of_week / month / quarter / is_weekend
数值列  wait_minutes  分钟  可加   根
        cost          元    可加   ← wait_minutes
        satisfaction  分    不可加 ← wait_minutes
意图绑定  ①比较 hospital×wait_minutes  ②趋势 visit_date×wait_minutes  ③关系 wait_minutes×satisfaction
总行数  900
```

`satisfaction` 标为不可加，这一条在声明期就排除了「按科室画满意度饼图」这类候选。
