# 02 · 事实表

把场景变成一张行级事件表，同时算出这张表能画出哪些图。

**子阶段**

| # | 子阶段 | 谁做 | 产出 |
|---|---|---|---|
| [2](#2-四个声明方法) | 写四个声明 + 意图绑定 | **LLM ×1** | 一段声明脚本、每条意图的绑定 |
| [3](#3-表达式) | 解析声明，从表达式读出依赖 | 规则 | 依赖图 |
| [4](#4-声明期枚举) | 枚举候选视图、检查覆盖度 | 规则 | 候选数与族覆盖。**不需要数据** |
| [5](#5-生成引擎) | 执行脚本生成数据 | 规则 | 900 行事实表 |
| [5](#5-生成引擎) | 结构检查 | 规则 | 通过 / 触发重试 |
| [7](#7-表结构说明) | 产出表结构说明 | 规则 | 给 03 的数据接口 |

整个阶段只有第一行调用 LLM。参考：[1 谁做什么](#1-谁做什么) · [6 错误反馈](#6-错误反馈)

先看 [§0 示例](#0-示例)，只看那一节就能明白这个阶段在干什么。

## 0. 示例

输入是 [01](01_scenario.md#0-示例) 的急诊科场景。

### 第一步 · **[LLM ×1]** 写脚本与意图绑定

一次调用，输出两样东西。第一样是脚本：

```python
dim("hospital", ["协和", "华山", "瑞金"], weights=[0.40, 0.35, 0.25])
dim("department", ["内科", "外科", "儿科", "创伤"], parent="hospital",
    weights={"协和": [0.35, 0.25, 0.15, 0.25],
             "华山": [0.40, 0.20, 0.20, 0.20],
             "瑞金": [0.30, 0.30, 0.15, 0.25]})
dim("severity", ["轻", "中", "重"], weights=[0.50, 0.35, 0.15], ordered="ordinal")

time("visit_date", start="2024-01-01", end="2024-06-30", freq="daily")

measure("wait_minutes",
        "lognormal(mu = 2.8 + 0.4*[severity=中] + 0.9*[severity=重] + 0.2*[hospital=协和],"
        "          sigma = 0.35)",
        unit="分钟", additive=True)
measure("cost",
        "wait_minutes * 12 + {轻: 80, 中: 260, 重: 700}[severity] + gaussian(0, 30)",
        unit="元", additive=True)
measure("satisfaction",
        "clip(5.2 - wait_minutes / 32 + gaussian(0, 0.3), 1, 5)",
        unit="分", additive=False)

emit(900)
```

第二样是意图绑定——把 01 那三句自然语言接到刚定义出来的列上：

```
意图① 哪家医院、哪个科室的等待时间最长   →  hospital × AVG(wait_minutes)    比较
意图② 等待时间在半年内怎么变化           →  visit_date × AVG(wait_minutes)  趋势
意图③ 等待越久是不是满意度越低           →  wait_minutes × satisfaction     关系
```

绑定里带聚合方式，因为规则分不出这一层：`wait_minutes` 可加，`SUM` 与 `AVG` 都合法，但"三家医院的总等待分钟数"不是意图①问的东西。定义列的人顺手说清楚，比让下游猜便宜。

LLM 的工作到此结束。它没有写出任何一个数据值，只写了"数据该怎么产生"。

### 第二步 · **[规则]** 解析声明，还不执行

从表达式里读出依赖：`cost` 引用了 `wait_minutes`，`satisfaction` 也引用了它，所以 `wait_minutes → cost`、`wait_minutes → satisfaction`，`wait_minutes` 是根。无环，通过。

### 第三步 · **[规则]** 枚举能画的图，检查覆盖度

**这一步不需要数据。** 基数从声明直接读：`dim` 的取值列表长度、`time` 的起止与频率。

```
可加测度    wait_minutes, cost                                  → 构成类可画
基数        hospital 3 · department 4 · severity 3 · day_of_week 7 · month 6   → 比较类可画
时间点      182 天，可重采样为 weekly 26 / monthly 6            → 趋势类可画
两个以上数值列                                                  → 关系类、分布类可画
stage 维度  无（severity 只是 ordinal）                          → 流程类画不出
二维叉积    最大 7×6 = 42 格，900 行摊下去期望每格 21 行         → 热力图可画

候选 214 条，覆盖 6 族中的 5 族
```

阈值是至少 3 个族，通过。流程类缺一个 `ordered="stage"` 的维度，本场景没有天然的流转阶段，不强行补。

### 第四步 · **[规则]** 执行脚本，生成 900 行

| visit_date | day_of_week | hospital | department | severity | wait_minutes | cost | satisfaction |
|---|---|---|---|---|---|---|---|
| 2024-01-03 | 周三 | 协和 | 外科 | 中 | 38.4 | 1002 | 4.0 |
| 2024-01-03 | 周三 | 瑞金 | 内科 | 轻 | 19.7 | 316 | 4.6 |
| 2024-02-11 | 周日 | 协和 | 创伤 | 重 | 92.1 | 1805 | 2.3 |
| … | | | | | | | 共 900 行 |

结构检查：行数 900 ✓ · 三个类别列的实际取值数与声明一致 ✓ · 三个数值列有限非常数 ✓ · 无环 ✓。

### 第五步 · **[规则]** 产出表结构说明

```
维度组  entity = hospital(3) → department(4)      triage = severity(3, ordinal)
时间列  visit_date, daily, 182 天;  派生 day_of_week / month / quarter / is_weekend
数值列  wait_minutes  分钟  可加   根
        cost          元    可加   ← wait_minutes
        satisfaction  分    不可加 ← wait_minutes
意图绑定  ①比较 hospital×AVG(wait_minutes)  ②趋势 visit_date×AVG(wait_minutes)  ③关系 wait×satisfaction
总行数  900
```

### 出错时

第三步或第四步任何一项不通过，**[规则]** 组装一段说明原因的反馈文本，**[LLM]** 拿着它改脚本重来，最多三次。例如覆盖度只剩 2 个族时，反馈是"没有可加测度，画不出任何构成类图（pie、stacked_bar、area、treemap），请加一个计数或金额类的测度"。

## 1. 谁做什么

| 步骤 | 谁做 | 内容 |
|---|---|---|
| 写四个声明 + 意图绑定 | **[LLM]** | 整个阶段唯一一次调用 |
| 解析声明、建依赖图 | **[规则]** | 从表达式的自由变量推断依赖 |
| 枚举候选视图 | **[规则]** | 查 [chart_types.md](chart_types.md) 的条件表 |
| 覆盖度检查 | **[规则]** | 数候选数与族数，与阈值比 |
| 执行脚本、生成数据 | **[规则]** | 引擎，给定种子逐位可复现 |
| 结构检查 | **[规则]** | 行数、基数、数值有效性、无环 |
| 判定是否重试、组装反馈文本 | **[规则]** | 循环控制在程序手里 |
| 按反馈改脚本 | **[LLM]** | 与第一行是同一个调用，最多三次 |

**LLM 在本阶段唯一的产出是一段声明代码和一组绑定。** 数据、候选清单、检查结论全部由程序算出。

## 2. 四个声明方法

列声明在前，行产出在后。整段脚本没有循环，没有条件语句，只有这四个调用。

| 方法 | 作用 |
|---|---|
| `dim(name, values, weights, parent, ordered)` | 类别列。`parent` 表达层级，`weights` 可以是一个向量，也可以是按父值给出的条件分布；`ordered` 取 `None` / `"ordinal"`（有大小顺序，如轻/中/重）/ `"stage"`（流程里依次经过的阶段，如分诊→就诊→住院） |
| `time(name, start, end, freq)` | 时间列。星期、月、季度、是否周末四个日历字段自动派生 |
| `measure(name, expr, unit, additive)` | 数值列。`expr` 是一个表达式字符串 |
| `emit(n)` | 产出 n 行 |

`unit`、`additive`、`ordered` 不影响数值生成，只服务下游：`unit` 决定 [04](04_render.md) 的轴标签与数字格式；`additive` 与 `ordered` 决定能画哪些图。计数、金额、时长可加；比率、百分比、温度、评分不可加。流程类图表要求 `ordered="stage"`——有大小顺序不等于是流程阶段，把严重程度画成漏斗图没有意义。

**硬约束**

1. 每行是一件不可再分的事，不铺类别叉积
2. ≥2 个维度组、≥2 个数值列
3. 依赖关系必须无环
4. 表达式里每个符号都有显式数值定义
5. 每个数值列只声明一次，不靠后续调用打补丁
6. 每个数值列必须给出 `unit` 与 `additive`

## 3. 表达式

| 成分 | 写法 | 例 |
|---|---|---|
| 分布 | `gaussian` `lognormal` `gamma` `beta` `uniform` `poisson` `exponential` `mixture` | `lognormal(mu=2.8, sigma=0.35)` |
| 类别效应 | `[列=取值]` 作为 0/1 指示，或 `{取值: 数}[列]` 作为查表 | `0.9*[severity=重]`、`{轻:80, 中:260}[severity]` |
| 其他数值列 | 直接写列名 | `wait_minutes * 12` |
| 算术与裁剪 | `+ - * /`、`clip`、条件分段 | `clip(..., 1, 5)` |

**依赖从表达式里读出来，不用声明。** 解析取出自由变量，凡是引用了另一个数值列就连一条边。

**统计模式也是表达式的一部分**，不是单独的注入接口。离群值是一个乘性条件项，趋势断点是一个关于时间的分段项，季节性是一个关于月份的正弦项。

## 4. 声明期枚举

**[规则]**。声明解析完、一行数据都还没生成时，**这套 schema 能画出哪些图已经完全确定**。[chart_types.md §1](chart_types.md) 的四类条件里，结构条件与语义条件只看列声明。

枚举器是一个查表函数：`列声明 → 候选视图清单`。它在这里跑一次，在 [03](03_figure.md) 拿实际数据再跑一次同样的规则，两次结果的差别只来自数据条件。

### 4.1 覆盖度检查

枚举结果直接反映 schema 设计得好不好，缺口进反馈文本：

| 情况 | 回喂内容 |
|---|---|
| 一个可加测度都没有 | 画不出任何构成类图（pie、stacked_bar、area、treemap） |
| 没有 `ordered="stage"` 的维度 | 画不出流程类图（waterfall、funnel） |
| 类别基数全部 < 3 或 > 30 | 画不出比较类图 |
| 候选总数或族数低于阈值 | 这套 schema 一个场景只能产出少量图 |

也可以反过来用：要求 schema 必须支撑指定的几个族，LLM 就会主动补一个可加测度或一个 stage 维度。

### 4.2 意图绑定

[01](01_scenario.md) 的意图是用场景词汇写的自然语言，此时列还不存在。列是本阶段定义的，因此**把意图绑到具体列上只能在这里做**。LLM 在输出脚本的同一次调用里给出「目标列 + 聚合 + 视图类」三样，[03](03_figure.md) 拿到后做确定性匹配。

聚合要写进绑定，是因为可加的测度 `SUM` 与 `AVG` 都合法，而哪个是这条意图要的、规则判断不了。这与 `unit`、`additive`、`ordered` 是同一类事情：**领域知识在定义的时候一次性交出来，下游全是查表。**

### 4.3 数据条件只能算期望

变异系数与区分度依赖实际数值，声明期算不出来。每格支撑行数可以按 `emit(n)` 与声明权重算期望值做粗筛；精确判定在 [03](03_figure.md)。

## 5. 生成引擎

**[规则]**。给定「声明 + 随机种子」逐位可复现。

```
构建全列依赖图 → 拓扑排序 → 三步执行

α  非数值列   根维度按 weights 抽 n 次；子维度按父值对应的条件分布抽；
              时间列在 [start, end] 上按 freq 抽，再派生四个日历字段
β  数值列     按拓扑序逐列整体求值，每列一次向量运算，不逐行循环
γ  后处理     按声明的取值范围裁剪，按单位定小数位
```

**结构检查**（只查执行是否成功，不查统计性质）

| 检查 | 判据 |
|---|---|
| 行数 | 在目标值 10% 以内 |
| 基数 | 每个类别列的实际取值数与声明一致 |
| 数值 | 每个数值列有限、非空、非常数 |
| 依赖 | 无环 |

基数这一条是 [§4](#4-声明期枚举) 成立的前提：声明期按声明的基数枚举，执行后必须对得上。

不通过时换种子重掷，或反馈给 LLM。**任何情况下都不改声明**——表结构说明必须始终描述实际生成出来的数据。

## 6. 错误反馈

```
[LLM]  输出脚本 + 意图绑定
[规则] 解析 → 枚举 → 覆盖度检查 → 执行 → 结构检查
       全过        → 进入 03
       任一不过    → 组装反馈文本 → 回到 [LLM]，最多三次 → 仍失败则跳过这个场景
```

反馈文本必须指出具体违反了哪条约束，例如"`cost` 与 `revenue` 互相引用，环路为 cost → revenue → cost"、"表达式里的 `base_fee` 没有定义"、"lognormal 的 sigma 为 0"。只说"执行失败"对重试没有帮助。

高频失败类型进提示词的约束段，不靠加大重试次数来解决。

## 7. 表结构说明

给 [03](03_figure.md) 用的那份数据接口：

- **维度组**：每组有哪些列、层级链是什么、每列的 `ordered` 取值
- **列清单**：名称、类型（类别 / 时间 / 数值）、所属组、父列、基数；数值列另含单位与可加性
- **依赖图**：数值列的拓扑序与边
- **意图绑定**：每条意图对应的目标列、聚合与视图类
- **总行数**
