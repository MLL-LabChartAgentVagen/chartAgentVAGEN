## 1. 三步结构

```
枚举（确定性）  →  选择（依分析意图）  →  过滤（确定性）
  保证覆盖率         提供判断力            保证可读
```

**枚举**沿用现有的 `VIEW_EXTRACTION_RULES` 与列角色匹配，产出所有满足 registry 结构约束的 `(chart_type, column_binding)`。这一步保证覆盖率与多样性，不做任何取舍。

**选择**由一次 LLM 调用完成，输入是 Schema Metadata、[02](02_scenario.md) 的 `analytical_intent`、以及枚举出的合法视图清单。**它只在给定选项中做选择，从不接触原始数据，也从不产生任何数值**——这符合 [README §5](README.md) 的第二条不变式。

**过滤**由两个确定性判据完成，即下面两节，外加 [03 §4](03_fact_table.md) 的三条视图级质量检查。

## 2. 判据一：语义适当性

> **这张图是不是一个真人分析师会画的图。**

反例：按月份画温度的饼图。它完全满足 registry 约束（3–8 个类别、一个数值列），枚举器一定会产出它。但没有分析师会这么画——饼图表示部分与整体，而 12 个月的温度加起来没有意义。

现有 pipeline 中没有任何环节会挡住这类视图。其他工作靠"让 LLM 直接写绘图代码"绕过（LLM 的先验代行了选择），而本 pipeline 刻意在 Phase 1 隔离了图表类型，于是没有任何环节持有图表选择的判断力。

这正是选择步骤存在的理由，也是 `analytical_intent` 承重的地方：意图为选择提供依据，使得选出的图是"为了回答某个具体分析问题而画的"，而不是从枚举结果中截取的前 N 个。

## 3. 判据二：值可恢复性

> **图上标的那个数，到底能不能从图上量出来。**

这是 ParseBench 容差模型的直接对应物：显式画出数值的点要求精确匹配，未画出的点给 1% 相对容差——那么这个值必须能从像素几何估读到 1% 以内。

举例说明：纵轴 0–6000、图高 400 像素，则 1 像素约等于 15 个单位。某个值是 4521，它的 1% 是 45 个单位，约 3 像素——量得出来，1% 容差成立。若同一张图因为另一根柱子特别高而把纵轴改成 0–600000，则 1 像素约 1500 个单位，4521 的 1% 只有 0.03 像素——量不出来。

这个点因此不能作为"不画标注"的 ground truth，三条出路：给它画上数值标注（容差变为精确匹配）、调整轴范围、或把它排除出标注集。

**这个判据是 [03](03_fact_table.md) 移除的统计验证的真正替代品**，且对 ParseBench 任务是比原 L1/L2/L3 加起来更强的保证。它必须在渲染参数确定之后才能计算，因此选图与渲染之间存在一次回环。

**两条判据的分工**：语义适当性挡的是"不该画的图"，值可恢复性挡的是"不该问的点"。

## 4. FigureSpec：选图的产出

选图阶段的产出不再是单个 ViewSpec，而是 **FigureSpec ——一张最终图像的完整描述**。它必须能表达多面板，因为 ParseBench 的多图困难是"一张图里多个面板共享坐标轴与图例"，而不是"跨多张独立图像推理"。

FigureSpec 承载的信息：

| 内容 | 说明 |
|---|---|
| 面板列表 | 每个面板一个 ViewSpec |
| 版面 | 单图 / 网格 / 同面板双轴（compound） |
| 共享关系 | 是否共享 x 轴、y 轴、图例 |
| 选择依据 | 对应哪条分析意图，用于生成 caption 与事后审查 |

风格与退化不进 FigureSpec——它们独立采样，见 [05_render.md](05_render.md)。这个分离是关键：**ground truth 由 FigureSpec 决定，对风格向量不变**，因此同一个 FigureSpec 可以渲染出 N 个视觉版本而共享同一份答案。

> **原有的算子代数与多跳 QA 并未删除，只是降优先级。** 它们作用于同一批视图，等感知与 grounding 跑通后可直接接回，届时新增的区域类型（R）与三个算子（Locate / Read / Rows）与 [06_provenance.md](06_provenance.md) 的三层模型一一对应。
