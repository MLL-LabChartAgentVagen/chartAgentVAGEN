## 1. 保留什么

- **Code-as-DGP**：LLM 写可执行 Python 调用类型安全 SDK，而非写脆弱的 JSON 配置
- **原子粒度**：每行一个不可分事件，不物化类别叉积
- **DAG 序生成**：拓扑排序决定生成顺序
- **执行错误反馈环**：SDK 抛出带语义的异常，代码与 traceback 回喂给 LLM，最多重试 3 次
- **Schema Metadata 契约**：Phase 2 与下游的接口，内容不变
- **确定性**：`(声明, seed)` → 逐位可复现

## 2. SDK 精简：8 个方法到 4 个

现有 SDK 表面：`add_category`、`add_temporal`、`add_measure`、`add_measure_structural`、`declare_orthogonal`、`add_group_dependency`、`inject_pattern`、`set_realism`。

精简后：

| 方法 | 作用 |
|---|---|
| `dim` | 类别列。层级通过 `parent` 表达 |
| `time` | 时间列，日历派生自动 |
| `measure` | 数值列。表达式可引用维度、时间、其他数值列、噪声 |
| `emit` | 产出 n 行原子事件 |

三处合并的理由：

- **`add_measure` 与 `add_measure_structural` 的二分取消。** 判据「是否引用了其他数值列」可以从表达式的自由变量直接推断，不需要 LLM 自己判断并选对方法。measure DAG 随之自动得出。这消除了一整类 LLM 混淆（root vs non-root）和对应的文档负担。
- **`inject_pattern` 取消。** pattern 就是表达式里的条件分支——离群值是一个乘性条件项，趋势断点是一个关于时间的分段项。作为独立 API 时它在生成之后修改数据，这正是它与统计验证冲突的根源。
- **`set_realism` 取消。** 数据层的缺失值与脏值远不如渲染层的真实感重要，见 [05_render.md](05_render.md)。

**`declare_orthogonal` 与 `add_group_dependency` 的处置**：这两者的实际功能是控制交叉格子的占用率（防止 grouped bar / heatmap 出现近乎空的格子）。改为在视图层直接检查格子计数，比"声明 → 传播 → 卡方校验"简单一个数量级，而且正是真正需要的东西。维度组这个抽象本身保留，用于表达层级与投影。

## 3. 为什么移除三层验证与 auto-fix

**判据：三层全过仍可能渲染出所有柱子等高的图；三层全挂也可能渲染出完全正常的图。** 检验应放在 ground truth 被消费的地方。

**L2 统计验证**
- 引擎本来就是从声明的分布采样的，KS 检验实际在检验 numpy 的随机数发生器
- 与 L3 直接冲突：pattern injection 在生成后故意破坏声明的分布，而 L3 要求这个破坏存在。同一张表无法同时满足两者
- 500 行按 predictor cell 切开后每格约 30 行，KS 检验在此样本量下功效极低，通过与否接近噪声

**L1 的正交性卡方检验**
- 真正独立采样时 `p > 0.05` 本身就有约 5% 概率随机失败，即会随机拒绝 5% 的正确表
- `p > 0.05` 不是独立性的证据——「未能拒绝」不等于「接受」。若要测应使用效应量而非 p 值

**auto-fix 循环**
- 它静默改写 DGP 直到检查通过，于是 Schema Metadata 不再描述数据，而下游把它当契约读
- 直接违反「closed-form measures：每个 measure 声明一次，不通过successive override 修补」
- **保留意图，更换机制**：失败时换 seed 重掷，或将失败反馈给 LLM。两者都确定，都不破坏契约

L1 中与结构有关的部分（行数、基数、数值有限、DAG 无环）保留——这些检查的是执行是否成功，不是统计性质。

## 4. 替代品：视图级质量检查

数据层的方差与图上的可分辨性不是一回事。反例：某数值列整体标准差很大，但按实体分组求均值后五个实体挤在极窄区间内——数据层通过，条形图上五根柱子等高。

因此检查移到视图层，对每个候选视图检查三件事：

| 检查 | 含义 |
|---|---|
| 区分度 | 聚合后的不同取值数量足够 |
| 变异 | 变异系数超过阈值，不是一条平线 |
| 格子占用 | 二维视图（grouped bar、heatmap）每个格子的支撑行数足够 |

这三条跑在 [04_figure_selection.md](04_figure_selection.md) 的过滤步骤里，取代原 L1 的正交检验、整个 L2、以及 auto-fix。原 L3（pattern 是否可见）同理并入——pattern 的意义本来就是"在图上看得见"。
