# 04 · 渲染

FigureSpec 加上一份独立采样的风格，画成页面图像，同时把画的过程记下来。项目的工作量重心。

## 1. 边画边记

渲染器每画一个图元，就在同一处把它的**框、键、值**写进记录。框由绘图库自己的坐标变换算出：数据坐标 →（轴变换）→ 像素坐标。

不做"先画完图，再回头解析图像里有哪些图形"。理由是只有在画的那一刻，框、键、值三者才同时在手；事后解析要重新把像素和数据对应起来，而这正是要消除的误差来源。

**坐标约定**：像素坐标，原点在图像左上角，框写成 `[x0, y0, x1, y1]`，随图像宽高一并记录。全流水线只有这一套约定，页面合成与图像退化都在它上面做变换。

**布局参数冻结**：图像尺寸、dpi、绘图区矩形三项写死，不用自动布局。自动布局会在画完之后挪动绘图区，此时已经记下的框全部失效，而且不报错。

## 2. 只有一个渲染器

几何只有一个来源：一个 matplotlib 渲染器。

多个后端会把项目最难的部分乘以后端数量——每加一个就要重写一遍图元记录，两套实现的坐标约定还必须逐像素对齐。因此：

- 风格差异来自**渲染器内部的参数**、**渲染后的图像退化**、**页面合成**这三处，不来自换后端。
- 企业报表的观感（粗边框、投影、伪三维、低对比配色）在 matplotlib 内部实现。
- 第二个后端是可选扩展，只有当 [06 §5](06_output.md) 的风格消融显示后端差异确实影响真实基准上的表现时才做。

## 3. 风格向量

风格与 FigureSpec 正交采样：同一份 FigureSpec 配 N 个不同的风格，得到 N 张外观不同、答案相同的图，构成配对数据。风格向量本身随记录一起存下，供消融时按维度分组。

### 3.1 渲染参数

| 维度 | 取值 |
|---|---|
| 数值标注 | 全画 / 全不画 / 部分画 |
| 版面 | 单图 / 网格面板 / 共享轴 / 外置共享图例 / 每面板独立图例 |
| 图表族 | 含 compound（同面板 bar + line 双轴） |
| 数字格式 | 千分位 / 货币符号 / 百分比 / K,M,B 后缀 / 括号负数 |
| 配色 | 企业报表低对比 / 同色系 / 渐变填充 / 灰度打印 |
| 图形细节 | 边框粗细 / 投影 / 伪三维 / 网格线 / 字体与字号 / 条宽 / 填充纹理 |
| 轴 | 起点是否为零 / 刻度密度 / 标签旋转 / 对数轴 |

每个维度独立采样，不做联合分布。轴起点是否为零直接改变值与像素的换算关系，因而直接影响 [05 §5](05_provenance.md) 判定的结果——这是风格影响标注集大小、但不影响标注内容的唯一途径。

### 3.2 图像退化与页面合成

见 [§4](#4-图像退化) 与 [§5](#5-页面合成)。

## 4. 图像退化

只允许几何变换写得出解析式的退化，框按同一个变换映射，标注保持精确。

| 退化 | 几何变换 | 框怎么处理 |
|---|---|---|
| JPEG 压缩 / 扫描噪声 / 模糊 | 恒等 | 不变 |
| 降采样 | 缩放 | 按比例缩放 |
| 轻微旋转 | 仿射 | 四个顶点变换后取外接框 |
| 透视形变 | 单应 | 四个顶点变换后取外接框 |

写不出解析变换的退化不进管线。旋转与透视之后外接框会比原图元略大，这是已知且可控的偏差，记录里注明施加过哪个变换。

## 5. 页面合成

图表不直接输出为裸图像，而是嵌进一张含正文、页眉、页脚、表格的版面。

由此得到：

- 页面元素的框与类别标签，类别取自 `{Text, Table, Picture, Page-Header, Page-Footer}`，即 [05](05_provenance.md) 的 L0 层
- 非平凡的定位任务——裸图像里图表占满整幅画面，定位没有信息量
- 单页多图、跨栏、图注与图表分开这些真实版面现象，且可控

合成器把图表贴进页面时，对已记录的框施加一次平移加缩放，用的是与 [§4](#4-图像退化) 相同的变换机制。

---

## 6. 数值标注

单独提出来，因为它决定 [06](06_output.md) 的容差：

| 标注状态 | 容差 |
|---|---|
| 图上写出了数值 | 0，要求精确匹配 |
| 图上没写数值 | 1% 相对容差，且要通过 [05 §5](05_provenance.md) 的判定 |

同一份数据、同一份 FigureSpec 渲染两次——写标注与不写标注——ground truth 完全相同，构成一组配对消融。

**判定不通过的点直接从值目标里去掉**，不回头调轴范围，也不补画标注。渲染是单向的一遍，不存在重渲染。被去掉的图元仍然贡献"键 + 区域"的定位目标。

## 7. 示例

接[意图①的 FigureSpec](03_figure.md#7-示例)：单面板 bar，三个条，值为 42.3 / 35.8 / 28.1 分钟。

采样到的风格：

```
数值标注  全不画
配色      企业报表低对比（三条同色系蓝）
轴        y 轴起点为零，刻度每 10 分钟
版面      单图
图像      900 × 600
退化      JPEG 质量 75
页面      嵌入单栏版面，图表居中，上方一段正文，下方图注
```

渲染时记下的几何（页面合成前）：

```
绘图区    [96, 60, 860, 520]        宽 764，高 460
y 轴      值域 [0, 60] 分钟   像素域 520 (值 0) → 60 (值 60)
```

三个条的框，由 `y_px = 520 − 值 / 60 × 460` 算出：

| 条 | 值 | 条顶像素 | 框 |
|---|---|---|---|
| 协和 | 42.3 | 520 − 324 = 196 | `[168, 196, 278, 520]` |
| 华山 | 35.8 | 520 − 275 = 245 | `[423, 245, 533, 520]` |
| 瑞金 | 28.1 | 520 − 215 = 305 | `[678, 305, 788, 520]` |

JPEG 压缩是恒等变换，框不变。页面合成把图表缩放 0.8 倍后贴到 `(120, 340)`，三个条的框各自过一遍同样的平移加缩放。

这三个框、三个键、三个值，就是 [05](05_provenance.md) 的 L1 层。
