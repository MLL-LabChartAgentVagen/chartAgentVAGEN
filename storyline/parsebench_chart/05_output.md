## 0. 示例

输入是 [04](04_record.md#0-示例) 那份记录。整份记录的核心是一组元组，每个图元一条：

```
键                   值     区域                   readable  labeled  行数  键从哪读出来
("Mercy General",)   42.3   [165, 186, 269, 480]   true      false    372   [轴刻度]
("St. Luke's",)      35.8   [406, 231, 510, 480]   true      false    315   [轴刻度]
("Riverside",)       28.1   [647, 284, 751, 480]   true      false    213   [轴刻度]
```

九类训练目标都是这组元组（外加面板、图例、页面元素三份几何）的投影。

**A · 转录**

```
带位置的表   全部三条元组的 (键, 值, 区域)
抽查标注集   三个图元 readable 都为真、都没写标注，因此容差 1%
             ("Mercy General",) 42.3 ± 0.42   ("St. Luke's",) 35.8 ± 0.36   ("Riverside",) 28.1 ± 0.28
```

**B · 定向探针** —— 同一组元组，三个查询方向。定位与下钻的问法是同一句，差别在要的是区域还是行数

```
图元定位   "Mercy General wait_minutes"   →  [165, 186, 269, 480]
图元读值   [165, 186, 269, 480]           →  42.3
下钻       "Mercy General wait_minutes"   →  背后 372 行
```

**C · 版面、图例与键的来源**

```
页面元素框   Picture 图表 · Page-Header 页眉 · Text 正文与图注 ·
             图号 / 标题 / 副标题 / 单位 / 出处各一框 · 轴标题两框
图例绑定     本图单面板无图例，此项为空
键的来源     ("Mercy General",) → [轴刻度]
```

图例绑定要有内容得靠多面板加图例：[02 §0](02_figure.md#0-示例) 的图④ 那里是「Surgery → {p0, p1}」。

**caption**

```
"Average emergency-department wait time at three metro hospitals, shown to answer which hospital and department waits longest. The county health department compiled per-visit records from three hospitals for January through June 2024 to assess a new triage diversion policy."
```

**换个风格会怎样**：若 y 轴值域被采样成 `[0, 6000]`，三个图元 `readable` 变为假，则抽查标注集与图元读值两项为空，其余七项不变。图仍然有用，只是不再要求模型报数。

## 1. 输出格式

模型的输出单位是 **`(键, 值, 区域)`** —— 抽取每个值的同时给出读它的那块像素区域。

它对既有任务优雅降级：

| 丢掉 | 得到 | 对应基准 |
|---|---|---|
| 区域 | `(键, 值)` | chart-to-table |
| 值 | `(键, 区域)` | chart grounding |
| 都保留 | 带位置的转录 | 目标能力 |

L2 在此基础上多一列：`(键, 值, 区域, 行数)`。

## 2. 训练目标

**一组元组，多个投影。** 九个目标不是九套机制：A 与 B 共七项全部读同一组图元元组，差别只在查询方向与筛选条件；C 读的是同一份记录里的另外两份几何与键的来源。

| 组 | 目标 | 依赖层 | 内容 |
|---|---|---|---|
| **A 转录** | 带位置的表 | L1 | 所有图元的 (键, 值, 区域) 全集 |
| | 抽查标注集 | L1 | ≤10 个点，从 `readable` 为真的图元里取；没写标注的按 1%，写了标注的把那串字一并交出去按字精确匹配，比数时容差正好是那次取整留下的余地 |
| **B 探针** | 图元定位 | L1 | 数据描述 → 区域。所有图元都可用，含读不出值的 |
| | 图元读值 | L1 | 区域 → 值。只用 `readable` 为真的 |
| | 下钻 | L2 | 数据描述 → 背后有多少行 |
| **C 版面** | 页面元素框 | L0 | 框 + 类别 + 框里那段字。**刻度标签不进这一份**：这份目标说的是基准的词表，在那套词表里整张图就是一个 `Picture`；刻度标签有自己的框，但键从哪里读是键出处目标的问题 |
| | 图例绑定 | L1 | 图例项 → 它管哪几个面板 |
| | **键的来源** | L1 | 键的每一段 → 读者从哪儿读到它（轴刻度 / 图例 / 面板标题 / 图元旁 / 图题 / 只有颜色 / 页面上没有） |
| **caption** | caption | — | 意图图用 [01](01_data.md) 的意图与场景（图像里读不出的信息）；其余的图用视图本身的描述 |

抽查标注集的形式对齐 ParseBench Charts 维度的评测方式：每图 ≤10 个点、写出的值精确匹配、需要估读的值 1% 相对容差。写出来的那串字是答案本身，所以它随目标一起交出去；**按数比的时候容差是那次取整留下的余地**——标签写着 `5` 的那根条，图上给得出来的答案就是 5，要求 4.86 等于把唯一读得出来的答案判成错的。

加一个目标只是加一个投影函数，不需要重新生成数据，也不需要改前四个阶段。**少要一个目标就是消融**：记录不变，那个投影不取而已。

**键的来源总是写出来的**，不受目标开关控制。模型交回来的键必须能落回某一个图元，而落不落得回，取决于它是在哪个范围下被问的——见下一节。

### 2.1 四个导出参数，都写进产物

导出这件事有四个选择项。它们不是记录的性质，而是"要问模型什么、答案写成什么样"的选择，所以是参数；都写进产物文件，否则一个键回来之后无从判断它该落在哪里。

**键的范围**：一个图元的地址给到多细。

| 取值 | 键里有什么 |
|---|---|
| `mark` | 只有绘图区里那几段：轴刻度、图例项、图元旁的标注、图题，外加页面上根本没写的那一段（散点的行标识——它要在键里唯一指认这个图元，而这个图元本来就不进值目标） |
| `panel` | 再加上这个图元所在面板的标题——**面板有标题才加**，页面上没写的东西不能进键 |
| `full` | 再加上只由外观带着的那几段：颜色、marker 形状、填充纹理 |

面板标题取的是**页面上实际画出来的那个字符串**，所以"键必须能从页面上抄下来"这件事不用谁去安排，它自然成立。

**导出粒度**：一个文件装多少东西。

| 取值 | 一个文件装什么 |
|---|---|
| `figure` | 一张图（连同它是第几个风格版本） |
| `page` | 同一页上的所有图 |
| `batch` | 整批 |

**导出形态**：那个文件写成什么。`json` 是结构化的九类目标；`markdown` 是一份文档；`both` 两样都写。**形态与粒度是两个问题**：一页写成文档和一页写成结构化载荷，是同一份记录投影了两次，谁也不蕴含谁。

markdown 那一份长这样——一个页标题，然后每张图一个二级标题加一张长表，最后一张页面元素表：

```markdown
# pg01

## Figure 8. Average Claim Turnaround Time by Processing Center

| key 1 | key 2 | value | box | rows | readable |
|---|---|---|---|---|---|
| Apex Operations | Inpatient Medical | 4.862 | [114.1, 310.8, 258.9, 480.0] | 108 | yes |
```

三件事各有理由：

- **二级标题是分开两张图的唯一凭据**：并排的两张图类别名一模一样，一张没有标题的表会和旁边那张撞在一起，谁也说不清某一行来自哪张图。
- **标题写的是画在图上的图号与图题，不是文件标识，也不带说明文字**。`f08_v0` 是一个文件名，页面上一个字都没写它——一个看着图的人产不出这个字符串，也就不能拿它当地址；说明文字是另一类目标，说的正是图上读不到的那部分，折进标题就等于要求这份文档由读者没见过的东西产生。
- **键的每一段单独占一列**。折进一个格子的键读起来是一个名字，而一个由面板、类目、颜色分组三段指认的图元是三个名字——长表存在的理由正是装得下这三段。

**页面元素按页号先并再写。** 同一页上的两张图各自只知道自己的那些文字块，分开导出会让每一份的页面元素目标都缺另一半——看起来像标漏了，其实是拆开看的。

### 2.2 预设：一把尺子要的那一组参数

一个基准要的是一种答案形态。把这四个参数打包成一个具名预设，**预设改的只是"取哪个投影、写成什么样"，永远不改记录里有什么**——这是同一条流水线能服务不止一把尺子而不被任何一把塑形的原因。任何一项单独写明就盖过预设，于是"取这个预设、改其中一项"不用把整组抄一遍。

| 预设 | 粒度 | 形态 | 键的范围 | 目标 | 为什么是这一组 |
|---|---|---|---|---|---|
| `parsebench` | `page` | `markdown` | `full` | 只要带位置的表 | 一页就是一张图像、一次回答；回答里的每一张表都会被搜；一个抽查点可能要三个键才定位得到 |

预设的名字随产物落盘，与键的范围、粒度、形态一起。

## 3. 输出能自己验自己

带位置的输出有一条别的格式没有的性质：**在没有 ground truth 的条件下也能查出它错了。**

给定图像和模型输出的一条 `(键, 值, 区域)`：

```
区域里有没有东西      取区域内的像素，没有图元就是编造的位置
区域几何配不配这个值   用该图元所依那条轴的值域与像素域把区域反算成值，与模型报的值比
```

这正是 [04 §6](04_record.md#6-三项自检) 前两项自检的计算，输入从"生成器写的记录"换成"模型写的输出"，别的什么都不用改。

**一份实现，三处使用**：

| 用在哪 | 输入是谁的输出 | 失败时怎么办 |
|---|---|---|
| 生成期 | 渲染器 | 丢掉这张图并记原因 |
| 训练期 | 模型 | 作为可验证奖励的一项 |
| 评测期 | 模型 | 报告一个不需要标注就能算的一致性指标 |

有一类图第二项本来就没得可查：表格图把数字印出来，几何上没有可量的东西，这时它返回"量不了"，而不是返回一个判决。

纯 `(键, 值)` 的输出没有这条通路：报错一个数值，除了对答案没有别的办法发现。区域一旦进了输出，像素本身就成了裁判。

## 4. 同一份记录还能派生什么

流水线攒下的元数据比上面九项需要的多得多：场景与意图、事实表、表结构与依赖图、FigureSpec 与聚合结果、三层记录、风格向量。**每一种下游产物都是这份元数据的一次投影**，加一种产物只是加一个导出函数，不需要重新生成数据。

| 产物 | 需要什么 | 状态 |
|---|---|---|
| 上面九类训练目标 | L0 / L1 / L2 | 当前主线 |
| 风格配对样本 | 同一 FigureSpec 的多个风格版本 | 条件已具备，且是[自检③](04_record.md#6-三项自检)的输入 |
| 版面配对样本 | 同一视图既作意图图、又作某张派生图的一个面板 | 条件已具备，由锚点规则保证 |
| 问答对 | ViewSpec 的聚合结果 + L2 行数 + 事实表 | 条件已具备，不在当前主线 |
| 图表代码与复现脚本 | FigureSpec + 风格向量 | 条件已具备 |
| 表格重建 | ViewSpec 的聚合结果 | 条件已具备 |
| 多图一致性样本 | 同一事实表投影出的多张图 | 条件已具备 |

**关于问答对**：一个问题就是一条算子链，在视图上求值得到答案，因此答案永远正确，难度等于算子个数。跨图问题靠一个桥接算子把 A 图取出的实体或数值带到 B 图，而两张图共享同一份底层算术，所以跨图答案也一定自洽。这套机制不在本流水线实现，但记录里保留了它需要的全部信息——`key`、聚合结果、行数、依赖图都在。

**同一批渲染，产出多少种数据取决于写多少个导出函数，而不取决于重跑多少次流水线。**

## 5. 数据构成

合成负责位置、来源、风格配对；真实图表负责风格分布。不做纯合成——合成与真实的风格差距是对任何纯合成工作的既定反对意见。

真实图表没有"值 + 区域"的配对标注，因此**只参与它的标注支持的那些目标**：

| 来源 | 能参与哪些目标 |
|---|---|
| 本流水线合成 | 全部九项 |
| 真实图表（现有 chart-to-table 数据集） | 带位置的表的 `(键, 值)` 部分、caption |
| 真实文档版面（现有版面数据集） | 页面元素框 |

混合比例是一个超参数，在 [§7](#7-消融) 的风格消融里一并测。

## 6. 评测

**主目标**

| 基准 | 维度 | 当前水平 |
|---|---|---|
| ParseBench | Charts（`ChartDataPointMatch`） | 最好 78.1%；多数专用 parser < 6% |
| ParseBench | Visual Grounding（Element Pass Rate） | 版面感知流水线 70–81%；纯 VLM 6–7% |
| ChartREG++ | point / bbox F1 | 最好 < 50% |
| ChartAB | grounding 与密集对齐 | — |
| LongChart VQA | grounding / pointing | 要求输出 bbox 时最好模型 85.5% → 57.6%，所有模型 mDIoU 为负 |

**边界条件**（要求不退化）：ChartQA、CharXiv-Reasoning、ChartQAPro

**鲁棒性**（检验风格向量）：CHART NOISe 扰动集

**覆盖度**（检验图表类型广度）：ChartArena 的八个图表族、ChartX 的多模态对照

**无标注一致性**（[§3](#3-输出能自己验自己)）：在上述任一测试集上都能算，不需要该集提供区域标注

## 7. 消融

| 消融 | 检验什么 |
|---|---|
| 去掉区域输出，只训表 | **主张的失败判据**。若加上区域后数值精度低于对照，主张不成立 |
| 关掉 L2 | 一行一件事是否有实验支撑。若 grounding 指标不变，则在论文中降级 |
| 固定风格向量 | 风格多样性对真实基准迁移的贡献 |
| 全部写数值标注 | 从像素几何估读的能力贡献了多少 |
| 去掉可验证奖励 | [§3](#3-输出能自己验自己) 那条通路的实际收益 |
| 只用 Tier 1 图表类型 | 类型广度的边际收益 |
| 只用意图图、去掉轮转图与派生图 | 类型覆盖面与版面形态各贡献多少 |
| **键的范围** `mark` / `panel` / `full` | 面板标题与只由颜色带着的那一段该不该进键。给多了模型只需抄，给少了同名的两个图元分不开 |
| **导出粒度** `figure` / `page` / `batch` | 同一页上的两张图分开问还是合起来问 |
| **导出形态** `json` / `markdown` / `both` | 答案是结构化的九类目标，还是一份文档 |
| **族权重预设** `uniform` / `parsebench` | 按真实报表的族比例生成，与固定轮转比，哪个迁移得更好 |
| **密度档** | 每张图的图元数量抬上去之后，值目标占比与真实基准表现各变多少 |
| **点系列的 marker** | 点的框就是 marker 的框。某些取值让一条序列只有线、不画 marker，框还在但图上没有可单独指认的形状；而灰度图只能靠形状分系列 |
| 去掉真实图表 | 合成与真实的风格差距的实际影响 |

## 8. 主张

> **带位置的转录可以由单个 VLM 完成**——抽取每个值的同时给出读它的那块区域，在 chart-to-table 上持平专用 parser，同时达到版面感知流水线级别的视觉 grounding。

现状是没有任何单一方法在这两项上同时强：商业多阶段流水线两项都高（78.1 / 80.6），纯 VLM 在 grounding 上是个位数（6–7%）。

**为什么数据只能这样产**：大规模的「值 + 区域」配对标注无法靠标注真实图表获得——值要人读，区域要人框，两者还必须逐个对齐。渲染时记录把这份标注的成本降到零，而且精确。

**失败判据**：加上区域输出后，数值精度低于只训表的对照。
