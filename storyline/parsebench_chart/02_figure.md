# 02 · 选图

把事实表投影成视图，决定画哪几张图、哪些视图放进同一张图、每张图上写什么字。

**选图这件事不调用 LLM。** 本阶段末尾有一次模型调用，只用来写图上要画的字——标题、副标题、单位、每个列的可读名。它不判可行性、不选视图，也不产出任何值、键或框，见 [§7](#7-标题从哪来)。

**三类图，三种产出方式**

| 类别 | 怎么产出 | 几张 | 它的价值 |
|---|---|---|---|
| **意图图** | 从 [01](01_data.md) 的意图绑定**直接构造** | 每条意图一张 | caption 含有图像里读不出的信息 |
| **派生图** | 从已单独出图的视图**推导**出第二个视图：六条面板关系把它放进另一块绘图区，三条叠放关系把它放进同一块 | 每种关系最多一张 | 版面形态；与锚点构成配对样本 |
| **轮转图** | 按图表族**采样 + 拒绝** | 收到干或到预算 | 图表类型覆盖面 |

只有轮转图需要随机数。先看 [§0 示例](#0-示例)。

## 0. 示例

输入是 [01](01_data.md#0-示例) 的 900 行事实表与表结构说明。

### 第一步 · 意图图：三条绑定，三条 ViewSpec

绑定已经写死了列、聚合与族，直接拼出来查条件表即可，不需要搜：

```
意图① hospital × AVG(wait_minutes) 比较  →  比较族里 grouped_bar 要两个类别角色，淘汰
                                            剩 bar   →  ① bar(hospital × AVG wait)
意图② visit_date × AVG(wait_minutes) 趋势 →  ② line(月 × AVG wait)，单系列
意图③ wait_minutes × satisfaction 关系    →  ③ scatter(wait_minutes × satisfaction)
```

意图②只绑了 `visit_date` 与 `wait_minutes` 两列，所以候选池里没有 `hospital`，画出来是一条线而不是三条。

投影一遍，三条都通过[准入检查](#3-准入检查)。`bar(hospital × AVG wait)` 的结果，聚合值与行数一起出来：

```
Mercy General 42.3 (372 行)   St. Luke's 35.8 (315 行)   Riverside 28.1 (213 行)
```

### 第二步 · 派生图：以意图图为锚点，推出第二个视图

第二个视图是**算出来的**，不是搜出来的。以 ① 为锚点，九条关系各推一次：

```
面板关系（第二个视图进另一块绘图区）
  同一切面重复  按 severity 的三个取值各筛一次行 → 三个 bar(hospital)，面板标题是取值
  不同切面      分组键换成不相交的类别列        → bar(severity)、bar(day_of_week)…
  下钻          hospital 有子列 department      → grouped_bar(hospital × department × AVG wait)
  时间对照      行过滤切成 1–3 月 / 4–6 月       → 两个 bar(hospital × AVG wait)
  双指标        下一个合法测度是 cost           → bar(hospital × SUM cost)
  整体与部分    比较族换成构成族                → pie(hospital × AVG wait)

叠放关系（第二个视图进同一块绘图区）
  双指标叠放    条形之上叠 category_line(hospital × SUM cost)，分钟与美元，两条纵轴
  双切面叠放    同一个测度两次：前后两个时间窗，或 AVG 配 MAX
  值与散布叠放  同一分组的五数：无时间列用 error_bar，有时间列用 windsock
```

面板关系与叠放关系各有自己的预算，**本节挑各一张来讲**；默认配置留三张面板关系与两张叠放关系，
再加一对合成到同一页上的时间对照图，所以这个场景默认出 16 张，而不是这里数的 8 张。

```
④ 下钻        bar(hospital) ‖ grouped_bar(hospital × department)   并排，共享 y 轴
⑤ 双指标叠放  bar(hospital × AVG wait) + category_line(hospital × SUM cost)  同一块绘图区，两条纵轴
```

图④ 是这批里唯一产出非平凡`图例绑定`目标的图：`grouped_bar` 的第二段键（四个科室名）记成"从图例读出"，外置图例里那四项同时管两个面板。

图⑤ 的两个视图分组键完全一样，所以各自的键前面要加一段序列名——图例上写的就是这两段：`AVG(wait_minutes) [minutes]` 与 `SUM(cost) [USD]`。没有这一段，两个视图的图元会落在同一个 `(面板, 键)` 上，数字却不同，记录接不起来。

### 第三步 · 轮转图：按族采样，逐条判进出

按图表族轮转，先补批次里还没有的族；同一族里也先抽批次里还没出现的类型。每抽一条就投影一次、判一次，不通过就重抽：

```
构成族  抽 pie(hospital × SUM wait)      键 {Mercy General, St. Luke's, Riverside} + 扇形，不撞 → 本可收
                                         但同族继续抽到键更新的一条，取后者
        抽 pie(department × SUM wait)    键 {四个科室} + 扇形         → 收 ⑥
分布族  抽 box(department × wait)        键 {四个科室} + 箱体，形状不同 → 收 ⑦
流程族  该族为空                          没有 ordered="stage" 的维度   → 跳过，记日志
关系族  抽 heatmap(day_of_week × month × AVG wait)  42 个新键 + 格子             → 收 ⑧
```

被拒的两个例子：

```
bar(hospital × SUM cost)      键 {Mercy General,St. Luke's,Riverside} + 矩形，与 ① 完全撞 → 拒
heatmap(department × day_of_week)    28 格，但 Trauma 在周末只有 2 行，低于下限 → 拒
```

本次运行共抽了 14 条，收下 3 条。

### 第四步 · 一次调用，把八张图的字一起写出来

八张图选定之后，把它们的列绑定（**不含任何数值**）一起交给模型，要回每张图的标题、副标题、单位，外加每个列的可读名：

```
f01  title "Emergency department wait times by hospital"
     subtitle "Average per visit, Jan-Jun 2024"    unit "minutes"
列名  wait_minutes → "Average wait"   hospital → "Hospital"   cost → "Cost per visit"
```

答案要过一道检查：**标题里不许出现数字**（年份与季度除外）。标题会被画到图上，在那里它就是 ground truth，"等待时间大幅下降"是一句关于数据的断言，而不是对画了什么的命名。

### 输出

8 份 FigureSpec。意图①那份：

```
面板   1 个
视图   bar，x = hospital，y = AVG(wait_minutes)
键的来源  hospital 写在类别刻度上
数据   Mercy General 42.3 (372 行)   St. Luke's 35.8 (315 行)   Riverside 28.1 (213 行)
版面   单图
文字   标题 / 副标题 / 单位 / 图号 / 出处
来源   意图① "Which hospital and department waits longest"
```

图④那份：

```
面板   2 个
  p0   bar，x = hospital，y = AVG(wait_minutes)          Mercy General 42.3 · St. Luke's 35.8 · Riverside 28.1
  p1   grouped_bar，x = hospital，分组 = department，y = AVG(wait_minutes)   12 个值
键的来源  p1 的 hospital 写在类别刻度上，department 写在图例里
版面   并排两面板
共享   共享 y 轴（0–50 分钟）
关系   下钻
来源   派生，锚点是意图①——p0 就是图① 的那个视图
```

`bar(hospital × AVG wait)` 同时出现在图① 和图④ 的 p0 里：键与值完全相同、像素坐标不同，**这本身就是一组配对样本**。

八张图共享同一份底层算术，因此**跨图一致性由构造保证**。

## 1. 三类图怎么产出

### 1.1 意图图 · 构造

绑定给了「目标列 + 聚合 + 族」三样，剩下的只是查表：

```
族 → 该族的类型清单 → 逐个查结构与语义条件 → 通过的按确定顺序取第一条
```

整族都不通过则该意图不产图，记录原因。这一步不搜索、不采样。

**它的价值是 caption**：只有意图图的 caption 含有图像里读不出的信息，见 [01 §2](01_data.md#分析意图有什么用)。

### 1.2 派生图 · 从锚点推导

**锚点必须是同一批里已经单独出图的视图**，因此只取意图图。锚点若是独立采样出来的，它在别处不出现，[版面配对样本](05_output.md#4-同一份记录还能派生什么)就没了。

第二个视图由关系规则算出，见 [§4](#4-一个视图怎么带出第二个)。关系逐条试，每条关系整个场景最多出一张，取第一个支持它的锚点。**面板关系与叠放关系各有各的预算**：它们排在同一张清单上，共用一份预算会被前面的面板关系花光，批次里就永远不会出现两个视图共处一块绘图区的图。

**从清单的哪一条开始，随场景号轮转。** 起点写死在声明顺序上时，预算短于清单，后面几条就一次都试不到：六条面板关系配预算三，第六条在九十六张图里被抽中过零次。轮转之后一个批次仍然走遍整张清单，而派生图仍然是**算出来的**——起点由场景号决定，不由种子决定，只有轮转图可以随种子动。

**第三种排法：把第二个视图放到同一页的另一张图上。** 一条关系把第二个视图放到某个地方，同一块画区和同一张图像上的另一块画区是其中两处，这是第三处。哪些关系可以这样拆写在 `PAGE_RELATIONS` 里：时间对照、双度量、部分与整体、下钻、分面。**叠放关系不能**——两个视图共处一块画区说的是「这些数要对着读」，分成两张图就把这句话拆了；**小倍数也不能**——跨面板的共享图例是图例绑定目标的唯一来源，拆成独立图像之后它就没了。

同一页上的成员**要不要加一段区分，看键会不会撞，不看是哪条关系**：同一批类别在两个时间窗下的键一模一样，拆成两张图就没有任何东西能把它们连起来，那就从各自的图题里读出一段；分面与双度量的面板本来就按不同的列或不同的度量分开，再加一段就是一段什么也没说的键。撞了而页上又没有可读之处，这一页就不出，而不是出一页连不起来的。

### 1.3 轮转图 · 采样加拒绝

```
按族轮转，先补批次里还没有的族：
    重复至多 T 次：
        按种子抽 (类型, 列绑定, 聚合)——先从批次里还没出现的类型里抽
        条件表不通过    → 重抽
        投影 → 准入检查不通过 → 重抽
        通过            → 收下，换下一个族
    T 次没抽到 → 该族这个场景出不了图，记日志
到预算 K_max 或一整轮没收下任何一条为止
```

**先抽没出现过的类型**，理由与先补没出现过的族一样：这一路存在的目的就是拓宽覆盖面，而一个有四种类型的族否则会一直给出它碰巧抽中的那一种。

**抽之前先按语义条件收窄候选池**，不是抽完再拒。语义条件只看声明，在这里查一次不花代价，却能省掉整批注定被条件表拒掉的抽样——把一个不是流程阶段的列拿去画流程图，从一开始就过不了。

**为什么这一路要采样而不是枚举。** 枚举要把全部候选算出来再挑，代价与 schema 大小成多项式增长——本例几百条，一个 12 个类别列的 schema 就是几千条，而每条都要投影一遍才知道通不通过。采样只投影抽到的那十几条。轮转图没有指定目标，要的就是"再来一张不重复的"，采样正对上。

意图图与派生图不采样，因为它们的目标是指定的：意图图由绑定给定，派生图由锚点加关系规则给定。**全流水线只有轮转图这一路需要随机数。**

### 1.4 族的权重是一个具名预设

轮转走哪个族在先，由一份具名权重决定（`s02_figure/sampling.py`），写进日志：

| 预设 | 内容 |
|---|---|
| `uniform` | 不带权重，就是按声明顺序走的那趟固定轮转，逐位等同 |
| `parsebench` | 在一百页真实报表上数出来的比例：比较 187、趋势 186、构成 154、关系 5，分布与流程一次都没出现 |
| 一个文件 | 按族名给权重的 JSON |

`parsebench` 里一次都没出现的两个族保留一个很小的下限，不给零。一百页足以说明一个族罕见，不足以说明它不存在；给零等于用一个报告自己都说证据不足的比例，换掉永久的类型覆盖面。

**权重排的是顺序，不是配额。** 一个场景出几张图是采样与准入的结果，配额还会把预算耗在这套 schema 根本画不出的族上。权重也不按位置索引——那样加一个图表类型就会把每个权重悄悄挪到错误的族上。它同样不回头去改 [01](01_data.md#5-覆盖度检查) 的可行性判断：两个预设必须跑在同一张事实表上，数字才可比。

## 2. 投影

对每条候选求一次值：先按条件选行，再按该类型的形态求值，最后取列。**四种形态都是一条 SELECT，差别在分不分组、用什么归约。**

| 形态 | 类型 | SQL | 一个图元 | 值字典 |
|---|---|---|---|---|
| **分组标量** | bar 族、line、category_line、area、pie、heatmap、table_chart、waterfall、funnel | `SELECT dims, AGG(m), COUNT(*) FROM M [WHERE …] GROUP BY dims` | 一组行 | `value` |
| **分组五数** | box、range_bar、error_bar、windsock | `SELECT dim, MIN, PCT(.25), MEDIAN, PCT(.75), MAX, COUNT(*) … GROUP BY dim` | 一组行 | `min` `q1` `median` `q3` `max`；箱线图的离群点另一条 SELECT |
| **分箱计数** | histogram | 先取值域定箱边，再 `SELECT bucket(m), COUNT(*) … GROUP BY bucket(m)` | 一个箱 | `count` `bin_lo` `bin_hi` |
| **逐行** | scatter | `SELECT m1, m2 FROM M [WHERE …]`，**没有 GROUP BY** | **一行** | `x` `y` |

前三种一并返回每组行数，它就是 [04](04_record.md) 的 L2 层，不需要再算第二遍。

**逐行形态的两处后果**：原始行数超过该类型的点数上限时（本例 900 行 > scatter 的 500 点），按种子确定性抽样，抽样结果随 ViewSpec 一起存；L2 退化为平凡——scatter 每个图元 `rows = 1`，histogram 的 `rows` 等于它的 `count`。

**形态决定四件事**：值字典有几个键、聚合集是什么（`FIVE_NUM` / `BIN_COUNT` / `NONE` 都不是 SUM/AVG/COUNT）、准入检查查哪几项、L2 有没有信息量。绘制与记录的代码按图元形状分支，不按图表类型分支。

## 3. 准入检查

投影完逐条判，两组判据。

### 3.1 数据条件：这张图画出来有没有信息量

| 检查 | 判据 | 挡住什么 |
|---|---|---|
| 图元数量 | 落在该类型的图元数区间内，上限由[密度档](chart_types.md#23-密度档抬高上限)抬 | 只有一个箱的直方图；四百个点的条形图 |
| 区分度 | 求值后不同取值的数量足够 | 几个柱子高度完全一样的条形图 |
| 变异 | 变异系数超过阈值 | 一条平线的折线图 |
| 每格实际行数 | 达到该类型声明的下限 | 100 个格子、每格只有 1 行数据的热力图 |
| 单调 / 最小扇区 | 漏斗要求逐段不增，饼要求最小扇区不低于 2% | 中间凸起的漏斗；一条缝一样的扇区 |

逐行形态跳过每格行数（恒为 1），分箱形态查每箱计数。

声明期只能按权重算期望行数，这里算的是实际行数，分布偏斜时两者差很多。

**密度档在这里的作用只有抬上限。** 每格行数的下限不动——它是"这个格子上的数字有没有支撑"，与画多密无关。配置要的档若超过这张表的行数撑得起的档，降的是档，见 [chart_types.md §2.3](chart_types.md#23-密度档抬高上限)。

### 3.2 冗余：这张图与批次里已有的重不重

**判据是一对：`(键集合, 图元形状)`。批次里已有同样的一对就拒。** 没有阈值，不用调参。

```
bar(hospital × AVG wait)   已收        键 {Mercy General,St. Luke's,Riverside}  矩形
bar(hospital × SUM cost)   拒          键同、形状同——三个条、同样的标签，只有高度不同
pie(hospital × SUM wait)   收          键同、形状不同(扇形)，值字典与可读性通道都不同
box(department × wait)     收          键不同
```

判据取这一对，是因为训练目标的单位是 `(键, 值, 区域)`：键集合决定图上出现哪些实体，图元形状决定框长什么样、值字典有几个键、值能不能从像素读出。两者都相同的两张图，训练信号几乎完全重叠。

逐行形态按列签名而不是按键签名：它的键是行标识，两张画不同测度的散点图会共享一模一样的键，两张画相同测度的也会——键在这里什么都说明不了。

**两条豁免，按来源判，不按面板数判。**

| 谁免 | 为什么 |
|---|---|
| 派生图（来源是面板关系或叠放关系） | 它的价值是版面形态不是新数据。键重复正是[版面配对样本](05_output.md#4-同一份记录还能派生什么)的来源，而`图例绑定`目标只有多面板加图例才产得出 |
| 同页排在一起、各带各标题的两张图 | 拒掉第二张就等于排除"两张图并排、类别名完全相同"这种版面，而这正是导出必须分得开的那一种；分得开靠的是各自的标题 |

### 3.3 预算与多样性是两回事

- **K_max** 是渲染与存储的预算，只是上限。
- **[§3.2](#32-冗余这张图与批次里已有的重不重) 才是管多样性的那一条。** 拿数量当多样性的代理没有用：8 张全是 `bar(hospital × …)` 照样满足数量。

一个场景实际出几张图是这两条与"一整轮没收下任何一条"共同决定的结果，逐场景不同，进日志。

## 4. 一个视图怎么带出第二个

九条关系，都是构造规则：给定锚点，第二个视图算出来。前六条把它放进另一块绘图区，后三条把它放进同一块。

### 4.1 六条面板关系

| 关系 | 怎么算 | 面板数 | 版面 | 共享 |
|---|---|---|---|---|
| **同一切面重复** | 分组键与测度都不动，按锚点没用到的一个类别列的取值逐个筛行，一个取值一个面板，面板标题就是那个取值 | **2–4** | 网格 | y 轴、图例 |
| **不同切面** | 第一个面板就是锚点，其余面板把分组键换成锚点没用到的类别列 | 2–4 | 网格 | y 轴；各面板系列列相同时才共享图例 |
| **下钻** | 分组键加一层：优先加锚点里某列的子列，否则按声明顺序取下一个类别列；类型换成同族里吃两个类别列的那个 | 2 | 并排 | y 轴 |
| **时间对照** | 锚点不动，行过滤切成前后两半，面板标题是各自的时间窗 | 2 | 并排 | x 轴、y 轴、图例 |
| **双指标** | 分组键不动，测度换成下一个 | 2 | 并排 | x 轴 |
| **整体与部分** | 分组键与测度不动，族从比较换成构成，类型由条件表定 | 2 | 并排 | 图例 |

「同一切面重复」是唯一一条既能给出三个以上面板、又让每个面板都用同一个系列列的关系，因此三面板以上的共享图例只可能出自它——而横跨多个面板的图例就是`图例绑定`目标的全部内容。

**"下一个测度"按固定的偏好顺序取**：依赖图上与锚点测度有边的优先（一个量与由它算出来的量，是报表里最常画的一对）；其次是可加性相反的（总量配比率）；再次是单位不同的（第二条轴就是为这个存在的，同单位的两个测度用分组条形更合适）；最后按列顺序打破平局。

**行过滤只在这里出现。** 它唯一的用处是让同一视图看两个时间窗，服务「时间对照」一种关系，所以它不是 ViewSpec 的一个采样维度，是配对时从锚点现场切出来的。

### 4.2 三条叠放关系

第二个视图进**同一块绘图区**。

| 关系 | 怎么算 | 底层 + 叠层 |
|---|---|---|
| **双指标叠放** | 锚点画矩形；第二个测度按同样的偏好顺序取，画成点 | 矩形 + 点 |
| **双切面叠放** | 同一个测度画两次：前后两个时间窗，或同一列的 AVG 与 MAX | 矩形 + 点 |
| **值与散布叠放** | 锚点的值配上同一分组的五数：有时间列用 windsock，没有用 error_bar | 矩形或点 + 带或点 |

> **叠放的两个视图必须是不同的图元形状。**

两组点画进同一块绘图区会互相压住，框重合，事后记录里没有任何东西能把它们分开。「值与散布叠放」因此在两边形状相同时直接不出图。

**能被叠的底层只有矩形与点。** 叠上去的序列要靠底层那条值轴来量，而扇形与格子没有值轴，叠上去的东西无从量起。

**两个视图各自的键要加一段前缀。** 它们按同样的列分组，不加前缀两组图元会落在同一个 `(面板, 键)` 上而数字不同，记录接不起来。前缀写的就是组合图图例上写的那句——哪个测度、哪个时间窗、哪个统计量——记录里这一段标成"从图例读出"。

### 4.3 两条轴还是一条

叠放要不要第二条值轴，由数字决定，不由版面的名字决定：

```
两个视图的测度单位不同        → 两条
单位相同，但两者的量级差 20 倍以上 → 两条
其余                          → 一条
```

差 20 倍以上时，小的那条序列会被压平贴在轴上；压平的序列过不了[值自检](04_record.md#6-三项自检)，会把整张图一起带走。两条轴时面板记 `y` 与 `y_right` 两条，各绑一个测度，**同一像素高度对应两个不同的值**——真实报表里最常见也最容易读错的形态。

### 4.4 共享图例的硬约束

> **各面板必须共用同一个系列列（分色的那一列），图例才共享。**

这条不满足就退化成每面板一个图例，`applies_to_panels` 每项只管一个面板，多面板图的主要价值消失。

| 面板配置 | 图例 | `applies_to_panels` |
|---|---|---|
| 4 个 bar，都按 hospital 分色 | 一个共享图例 | `{p0,p1,p2,p3}` 有信息量 |
| bar + line，都按 hospital 分色 | 一个共享图例 | `{p0,p1}` 有信息量 |
| bar 按 hospital 分色 + line 按 severity 分色 | 每面板一个 | 退化 |

**各面板同类型还是混类型，是 [03](03_render.md#3-风格向量) 的风格维度**，两种都要：

- **同类型**（4 个 bar）：真实报表的 small multiples，共享 y 轴才有意义。
- **混类型**：风格采样到混类型时，第一个之后的面板换成一个分组方式与值字典都相同的伙伴类型（`bar` 换 `category_line`）——换的是值怎么画，不是有什么值可画。模型必须在同一张图里切换读法。

同一块绘图区里的混类型是 [§4.2](#42-三条叠放关系) 的叠放关系，它比跨面板混类型更极端：两条纵轴共用一段像素高度。

### 4.5 桥接算子不在这里

视图之间的关系是结构事实，本阶段只用它决定版面。用这些关系生成跨图问题属于问答对生成，见 [05 §4](05_output.md#4-同一份记录还能派生什么)，本流水线不实现，但关系已经写进 FigureSpec。

## 5. 键的每一段从哪读出来

键是一个有序的字符串元组，**它的各段来源不同**。同一批数字画成两个面板，医院名写在面板标题上、科室名写在类别刻度上、严重程度写在图例里；并成一个面板，医院名就挪进图例；排成同页两图，它就只在图题里。**键一个字都不变，变的是读者从哪儿找到它。** 因此来源逐段记，不是逐图记。

九个取值：

| 取值 | 读者在哪儿找到它 |
|---|---|
| `axis_tick` | 类别轴或时间轴的刻度标签 |
| `legend` | 图例项 |
| `panel_title` | 该图元所在面板的标题 |
| `inline_label` | 印在图元自己旁边 |
| `heading` | 只在图题里 |
| `colour_only` | 只由颜色带着，页面上没有对应文字 |
| `mark_shape` | 由 marker 的形状带着 |
| `hatch` | 由填充纹理带着 |
| `not_shown` | 页面上根本没有，这一段找不回来 |

规则：

```
逐行形态          分组列各记 legend，最后那一段行标识记 not_shown
                  （散点的行标识页面上一个字都没有）
其余形态逐段判
    这一段的列就是分面板用的那一列   → panel_title
    图元形状是扇形                   → inline_label
    它是最后一段且总共不止一段        → legend
    其余                            → axis_tick
颜色分组列不在分组列里 → 末尾再追加一段 colour_only
叠放的序列名前缀 → legend；同页两图的时间窗前缀 → heading
```

**这是图的性质，不是风格的性质。** 风格决定图例长什么样、放在哪里，不决定某个名字在不在图例里。记 `not_shown` 的那一段会让这个图元退出值目标、留在定位目标里，见 [04 §5](04_record.md#5-值能不能读出)。

### 5.1 颜色分组：一列被颜色带着，但不分组

有一种列既不进分组键、又必须进键：**当分组列的取值到它的取值是一个函数时**，它就是每个图元本来就有的第二个名字。一个处理中心只属于一个大区——大区不是另一种切分方式，报表把它做成颜色，名字放在图例里，轴上什么都不写。读者认不出它，就分不清两根同名的条。

```
每个分组值只对应一个取值   → 加进键，来源记 colour_only
一个分组值对应好几个取值   → 它真的是另一个分组维度，什么都不加
```

第二条是必须的：加进去会改变一个图元覆盖哪些行，而颜色分组的定义就是不改变这件事。急诊科这份 schema 加不上——每个科室在三家医院都有，`department → hospital` 不是函数。

颜色分组写在 Binding 里而不是风格向量里。风格若能选它，同一份 FigureSpec 换个风格重画一次键就变了，[风格自检](04_record.md#6-三项自检)也就没有可比的东西。

## 6. FigureSpec

| 字段 | 内容 |
|---|---|
| 面板列表 | 每面板一个或多个 ViewSpec；每个 ViewSpec 是图表类型、列绑定、聚合、行过滤、键的各段来源、求值结果、每组行数 |
| 版面 | 单图 / 并排 / 网格 / 同面板叠放 |
| 共享关系 | 是否共享 x 轴、y 轴、图例；共享图例时的系列列 |
| 关系 | 派生图记它是九条里的哪一条，单视图图为空 |
| 来源 | 对应哪条意图，或标为面板 / 叠放 / 轮转，并记下锚点是哪张图 |
| 文字块 | 图上要画的每段字：角色、内容、属于页面还是图还是面板、放在哪一侧 |
| 列名与单位 | 每个列的可读名与单位，抄进来，渲染器因此不必回头读表结构 |
| 页面号 | 与哪些图排在同一页 |
| caption | 一句话说这张图是干什么的。**不画在图上**，它是训练目标 |

FigureSpec 决定**哪些视图进同一张图、彼此什么关系、共享什么、上面写什么字**。图例位置、面板间距、各面板同类型还是混类型这些视觉细节由 [03](03_render.md#3-风格向量) 的风格向量采样。

值能不能从图上读出取决于轴范围与图像尺寸，因此在渲染之后判定，见 [04 §5](04_record.md#5-值能不能读出)。

## 7. 标题从哪来

**[LLM ×1]** 流水线的第二次、也是最后一次模型调用。它在图选完之后跑，而且什么都不选：不判可行性、不挑视图，也不产出任何一个值、键或框。它产出的是要画到页面上的字。

| 项 | 内容 |
|---|---|
| `title` | 这张图画的是什么：点出量与切分方式 |
| `subtitle` | 限定语：每个图元覆盖什么、时间跨度多长 |
| `unit` | 值的单位，按轴上会怎么写 |
| `column_names` | 每个列一个可读名，用在轴标题与图例上 |

**一个场景一次调用，把所有图放进去**，不是一图一次：这一批共用一个场景，列名必须跨图一致。

**输入给到声明这一层，越细越好，但一个数值都不给。** 起名这件事问的正是"这个列在轴上该叫什么"，能回答它的是列的声明：

| 送进去的 | 例子 | 少了它会怎样 |
|---|---|---|
| 场景标题与场景说明 | | |
| 每张图的图表类型、分组列、聚合、单位、面板标题、面板关系、意图句 | | |
| 类别列的取值列表 | `processing_center: Apex Operations, Summit Claims, …` | 只知道列叫 `processing_center`，不知道里面装的是四个理赔中心 |
| 时间列的起止与频率 | `report_week: 2023-01-02 → 2023-12-25, weekly` | 副标题的时间范围只能从场景说明的散文里推 |
| 测度列的单位与可加性 | `turnaround_days: days, additive` | `unit` 这一项少一半依据 |
| 层级组与派生来源 | `calendar ▸ report_week, month, quarter` | 同一条链上的列会被起成互不相干的名字 |
| 键的每一段从页面哪里读 | `processing_center ← 轴刻度`，`claim_type ← 图例` | 副标题该说"每个图元覆盖什么"，这一段直接回答它 |

**取值列表不算数值**：它是声明字段，与 `emit(n)` 跑出来的那些行无关，一行数据都不进提示词。「标题里不许有数字」那道检查一个字不改。

**为什么每张图都要，而不只是意图图。** 意图那条分界线管的是 caption：caption 是训练目标，说的是图上读不出来的事。标题是画在图上的，每张图都得有。三张图的标题来自意图、五张来自模板，会在语料里放进两种听得出差别的语气，教会模型"这种语气对应这种图"——那是我们自己造出来的信号。模板标题还从坐标轴上就猜得到，而记录标题块的意义恰恰在于：单位常常整页只写在这一个地方。

**回来的答案要过两道检查**：

```
标题与副标题里不许有数字      年份与季度除外。标题被画到图上，在那里它就是 ground truth，
                              "等待时间大幅下降"是一句关于数据的断言，可能根本不成立
必须交回一份列名表            没有它，轴上写的就是 wait_minutes，而轴刻度正是读者取键的地方
```

不过就带着理由回喂重写，最多两次。**没有模型也能跑**：按规则拼出的模板标题接上，开发与端到端测试因此不需要一个模型——但那不是一个批次该在其下生成的配置。

**标题不是 caption。** 标题画在图上，caption 不画：

| | 画在图上 | 谁写 | 内容 |
|---|---|---|---|
| 标题 / 副标题 / 单位 | 是 | 本节这次调用（无模型时用模板） | 这张图画的是什么 |
| caption | 否 | 规则 | 意图图取 [01](01_data.md) 的意图与场景（图上读不出的信息）；其余的图取视图本身的描述 |
