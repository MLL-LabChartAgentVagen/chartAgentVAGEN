# 02 · 选图

把事实表投影成视图，决定画哪几张图、哪些视图放进同一张图。

**这一阶段全部由程序执行，不调用 LLM。**

**三类图，三种产出方式**

| 类别 | 怎么产出 | 几张 | 它的价值 |
|---|---|---|---|
| **意图图** | 从 [01](01_data.md) 的意图绑定**直接构造** | 每条意图一张 | caption 含有图像里读不出的信息 |
| **多面板图** | 从意图图**推导**出第二个面板 | 每种关系最多一张 | 共享图例的版面形态；与意图图构成配对样本 |
| **轮转图** | 按图表族**采样 + 拒绝** | 收到干或到预算 | 图表类型覆盖面 |

只有轮转图需要随机数。先看 [§0 示例](#0-示例)。

---

## 0. 示例

输入是 [01](01_data.md#0-示例) 的 900 行事实表与表结构说明。

### 第一步 · 意图图：三条绑定，三条 ViewSpec

绑定已经写死了列、聚合与族，直接拼出来查条件表即可，不需要搜：

```
意图① hospital × AVG(wait_minutes) 比较  →  比较族里 grouped_bar 要两个类别角色，淘汰
                                            剩 bar   →  ① bar(hospital × AVG wait)
意图② visit_date × AVG(wait_minutes) 趋势 →  ② line(月 × hospital × AVG wait)
意图③ wait_minutes × satisfaction 关系    →  ③ scatter(wait_minutes × satisfaction)
```

投影一遍，三条都通过[准入检查](#3-准入检查)。`bar(hospital × AVG wait)` 的结果，聚合值与行数一起出来：

```
协和 42.3 (372 行)   华山 35.8 (315 行)   瑞金 28.1 (213 行)
```

### 第二步 · 多面板图：以意图图为锚点，推出第二个面板

第二个面板是**算出来的**，不是搜出来的。以 ① 为锚点，五种关系各推一次：

```
下钻      hospital 有子列 department  → grouped_bar(hospital × department × AVG wait)
双指标    下一个合法测度是 cost        → line(hospital × SUM cost)，同面板双轴
不同切面  不相交的类别列 severity      → bar(severity × AVG wait)
时间对照  行过滤切成 1–3 月 / 4–6 月   → 两个 bar(hospital × AVG wait)
整体与部分 比较族换成构成族            → pie(hospital × SUM wait)
```

每种关系整个场景最多出一张，按关系顺序取前两条：

```
④ 下钻    bar(hospital) ‖ grouped_bar(hospital × department)   并排，共享 y 轴与图例
⑤ 双指标  bar(hospital × AVG wait) + line(hospital × SUM cost)  同面板双轴 compound
```

图④ 是这批里唯一产出非平凡`图例绑定`目标的图：外置图例里的「协和 / 华山 / 瑞金」三项同时管两个面板。

### 第三步 · 轮转图：按族采样，逐条判进出

按图表族轮转，先补批次里还没有的族。每抽一条就投影一次、判一次，不通过就重抽：

```
构成族  抽 pie(hospital × SUM wait)      键 {协和,华山,瑞金} + 扇形，不撞 → 本可收
                                         但同族继续抽到键更新的一条，取后者
        抽 pie(department × SUM wait)    键 {四个科室} + 扇形         → 收 ⑥
分布族  抽 box(department × wait)        键 {四个科室} + 箱体，形状不同 → 收 ⑦
流程族  该族为空                          没有 ordered="stage" 的维度   → 跳过，记日志
关系族  抽 heatmap(星期 × 月 × AVG wait)  42 个新键 + 格子             → 收 ⑧
```

被拒的两个例子：

```
bar(hospital × SUM cost)      键 {协和,华山,瑞金} + 矩形，与 ① 完全撞 → 拒
heatmap(department × 星期)    28 格，但创伤科在周末只有 2 行，低于下限 → 拒
```

本次运行共抽了 14 条，收下 3 条。

### 输出

8 份 FigureSpec。意图①那份：

```
面板   1 个
视图   bar，x = hospital，y = AVG(wait_minutes)
数据   协和 42.3 (372 行)   华山 35.8 (315 行)   瑞金 28.1 (213 行)
版面   单图
来源   意图① "哪家医院、哪个科室的等待时间最长"
```

图④那份：

```
面板   2 个
  p0   bar，x = hospital，y = AVG(wait_minutes)          协和 42.3 · 华山 35.8 · 瑞金 28.1
  p1   grouped_bar，x = hospital，分组 = department，y = AVG(wait_minutes)   12 个值
版面   并排两面板
共享   共享 y 轴（0–60 分钟）、共享图例（系列列都是 hospital）
关系   下钻
来源   多面板，锚点是意图①——p0 就是图① 的那个视图
```

`bar(hospital × AVG wait)` 同时出现在图① 和图④ 的 p0 里：键与值完全相同、像素坐标不同，**这本身就是一组配对样本**。

八张图共享同一份底层算术，因此**跨图一致性由构造保证**。

## 1. 三类图怎么产出

### 1.1 意图图 · 构造

绑定给了「目标列 + 聚合 + 族」三样，剩下的只是查表：

```
族 → 该族的类型清单 → 逐个查结构与语义条件 → 通过的按确定顺序取第一条
```

整族都不通过则该意图不产图，记录原因。这一步不搜索、不采样。

**它的价值是 caption**：只有意图图的 caption 含有图像里读不出的信息，见 [01 §2](01_data.md#分析意图有什么用)。

### 1.2 多面板图 · 从锚点推导

**锚点必须是同一批里已经单独出图的视图**，因此只取意图图。锚点若是独立采样出来的，它在别处不出现，[版面配对样本](05_output.md#4-同一份记录还能派生什么)就没了。

第二个面板由关系规则算出，见 [§4](#4-多面板)。

### 1.3 轮转图 · 采样加拒绝

```
按族轮转，先补批次里还没有的族：
    重复至多 T 次：
        按种子抽 (类型, 列绑定, 聚合)
        条件表不通过    → 重抽
        投影 → 准入检查不通过 → 重抽
        通过            → 收下，换下一个族
    T 次没抽到 → 该族这个场景出不了图，记日志
到预算 K_max 或一整轮没收下任何一条为止
```

**为什么这一路要采样而不是枚举。** 枚举要把全部候选算出来再挑，代价与 schema 大小成多项式增长——本例几百条，一个 12 个类别列的 schema 就是几千条，而每条都要投影一遍才知道通不通过。采样只投影抽到的那十几条。轮转图没有指定目标，要的就是"再来一张不重复的"，采样正对上。

意图图与多面板图不采样，因为它们的目标是指定的：意图图由绑定给定，多面板图由锚点加关系规则给定。**全流水线只有轮转图这一路需要随机数。**

## 2. 投影

对每条候选求一次值：先按条件选行，再按该类型的形态求值，最后取列。**四种形态都是一条 SELECT，差别在分不分组、用什么归约。**

| 形态 | 类型 | SQL | 一个图元 | 值字典 |
|---|---|---|---|---|
| **分组标量** | bar 族、line、area、pie、heatmap、treemap、compound、waterfall、funnel | `SELECT dims, AGG(m), COUNT(*) FROM M [WHERE …] GROUP BY dims` | 一组行 | `value` |
| **分组五数** | box、violin | `SELECT dim, MIN, PCT(.25), MEDIAN, PCT(.75), MAX, COUNT(*) … GROUP BY dim` | 一组行 | `min` `q1` `median` `q3` `max`；离群点另一条 SELECT |
| **分箱计数** | histogram | 先取值域定箱边，再 `SELECT bucket(m), COUNT(*) … GROUP BY bucket(m)` | 一个箱 | `count` `bin_lo` `bin_hi` |
| **逐行** | scatter、bubble | `SELECT m1, m2 FROM M [WHERE …]`，**没有 GROUP BY** | **一行** | `x` `y`（bubble 另加 `size`） |

前三种一并返回每组行数，它就是 [04](04_record.md) 的 L2 层，不需要再算第二遍。

**逐行形态的两处后果**：原始行数超过该类型的点数上限时（本例 900 行 > scatter 的 500 点），按种子确定性抽样，抽样结果随 ViewSpec 一起存；L2 退化为平凡——scatter 每个图元 `rows = 1`，histogram 的 `rows` 等于它的 `count`。

**形态决定四件事**：值字典有几个键、聚合集是什么（`FIVE_NUM` / `BIN_COUNT` / `NONE` 都不是 SUM/AVG/COUNT）、准入检查查哪几项、L2 有没有信息量。绘制与记录的代码按形态分支，不按图表类型分支。

## 3. 准入检查

投影完逐条判，两组判据。

### 3.1 数据条件：这张图画出来有没有信息量

| 检查 | 判据 | 挡住什么 |
|---|---|---|
| 区分度 | 求值后不同取值的数量足够 | 几个柱子高度完全一样的条形图 |
| 变异 | 变异系数超过阈值 | 一条平线的折线图 |
| 每格实际行数 | 达到该类型声明的下限 | 100 个格子、每格只有 1 行数据的热力图 |

逐行形态跳过第三项（恒为 1），分箱形态查每箱计数。

声明期只能按权重算期望行数，这里算的是实际行数，分布偏斜时两者差很多。

### 3.2 冗余：这张图与批次里已有的重不重

**判据是一对：`(键集合, 图元形状)`。批次里已有同样的一对就拒。** 没有阈值，不用调参。

```
bar(hospital × AVG wait)   已收        键 {协和,华山,瑞金}  矩形
bar(hospital × SUM cost)   拒          键同、形状同——三个条、同样的标签，只有高度不同
pie(hospital × SUM wait)   收          键同、形状不同(扇形)，值字典与可读性通道都不同
box(department × wait)     收          键不同
```

判据取这一对，是因为训练目标的单位是 `(键, 值, 区域)`：键集合决定图上出现哪些实体，图元形状决定框长什么样、值字典有几个键、值能不能从像素读出。两者都相同的两张图，训练信号几乎完全重叠。

**多面板图不受这条管。** 它的价值是版面形态不是新数据：图⑤ 两个面板的键完全重复，但 compound 双轴是 ParseBench 明确收录的形态，而`图例绑定`目标只有共享图例的多面板图能产出。键重复正是[版面配对样本](05_output.md#4-同一份记录还能派生什么)的来源。

### 3.3 预算与多样性是两回事

- **K_max**（默认 12）是渲染与存储的预算，只是上限。
- **[§3.2](#32-冗余这张图与批次里已有的重不重) 才是管多样性的那一条。** 拿数量当多样性的代理没有用：8 张全是 `bar(hospital × …)` 照样满足数量。

一个场景实际出几张图是这两条与"一整轮没收下任何一条"共同决定的结果，逐场景不同，进日志。

## 4. 多面板

### 4.1 五种关系，都是构造规则

给定锚点，第二个面板算出来：

| 关系 | 怎么算 | 面板数 | 版面 |
|---|---|---|---|
| **同指标不同切面** | 测度与聚合不动，分组键换成不相交的类别列，要 N 个面板取 N−1 个 | **2–4** | 网格，共享 y 轴 |
| **下钻** | 分组键加一层：优先加锚点里某列的子列，否则按声明顺序取下一个类别列 | 2–3 | 并排，共享 y 轴与图例 |
| **时间对照** | 锚点不动，行过滤切成前后两半或四个季度 | 2 或 4 | 并排，共享 x 轴与 y 轴 |
| **双指标** | 分组键不动，测度换成声明顺序里下一个合法的 | 2 | 同面板双轴 compound，或并排共享 x 轴 |
| **整体与部分** | 分组键与测度不动，族从比较换成构成，类型由条件表定 | 2 | 并排，共享图例 |

「同指标不同切面」是 N 面板的主力形态——同一个量按不同维度切开，真实报表里的 small multiples。

**行过滤只在这里出现。** 它唯一的用处是让同一视图看两个时间窗，服务「时间对照」一种关系，所以它不是 ViewSpec 的一个采样维度，是配对时从锚点现场切出来的。

### 4.2 共享图例的硬约束

> **各面板必须共用同一个系列列（分色的那一列），图例才共享。**

这条不满足就退化成每面板一个图例，`applies_to_panels` 每项只管一个面板，多面板图的主要价值消失。

| 面板配置 | 图例 | `applies_to_panels` |
|---|---|---|
| 4 个 bar，都按 hospital 分色 | 一个共享图例 | `{p0,p1,p2,p3}` 有信息量 |
| bar + line，都按 hospital 分色 | 一个共享图例 | `{p0,p1}` 有信息量 |
| bar 按 hospital 分色 + line 按 severity 分色 | 每面板一个 | 退化 |

**各面板同类型还是混类型，是 [03](03_render.md#3-风格向量) 的风格维度**，两种都要：

- **同类型**（4 个 bar）：真实报表的 small multiples，共享 y 轴才有意义。
- **混类型**（bar + line）：模型必须在同一张图里切换读法——长度 / 位置 / 角度不能互相套用。`compound` 是它的极端情况，同一个面板里两条 y 轴，同一像素高度对应两个不同的值。

### 4.3 桥接算子不在这里

视图之间的关系是结构事实，本阶段只用它决定版面。用这些关系生成跨图问题属于问答对生成，见 [05 §4](05_output.md#4-同一份记录还能派生什么)，本流水线不实现，但关系已经写进 FigureSpec。

## 5. FigureSpec

| 字段 | 内容 |
|---|---|
| 面板列表 | 每面板一个 ViewSpec：图表类型、列绑定、聚合、行过滤、求值结果、每组行数 |
| 版面 | 单图 / 并排 / 网格 / 同面板双轴 |
| 共享关系 | 是否共享 x 轴、y 轴、图例；共享图例时的系列列 |
| 关系 | 多面板图记它是哪一种关系，单面板图为空 |
| 来源 | 对应哪条意图，或标为多面板 / 轮转 |

FigureSpec 决定**哪些视图进同一张图、彼此什么关系、共享什么**。图例位置、面板间距、各面板同类型还是混类型这些视觉细节由 [03](03_render.md#3-风格向量) 的风格向量采样。

值能不能从图上读出取决于轴范围与图像尺寸，因此在渲染之后判定，见 [04 §5](04_record.md#5-值能不能读出)。
