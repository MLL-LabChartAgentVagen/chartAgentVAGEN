# 06 · 溯源记录

> 新增阶段，本方案的核心产出。渲染器在输出图像的同时，输出一份描述"画了什么"的结构化记录。
> 所有训练目标都是这份记录的纯函数——**不需要 QA 引擎、不需要流水线采样器、不需要算子采样器**。

## 1. 三层模型

溯源记录分三层，逐层信息严格增加，每层可独立开关：

```
L0  几何    有哪些框、框属于什么类别            纯像素事实，无语义
      ▲
L1  编码    这个框编码哪个 (键, 值)、图例映射    视觉 → 数据
      ▲
L2  溯源    这个值由多少行原子事件聚合而来        数据 → 来源
```

三层的边界不是随意划的，它同时对应**三种不同的消费者**和**三种不同的渲染器能力要求**。

---

## 2. 为什么是分层而不是继承

一个自然的想法是给 mark 做基类加子类：`BarMark`、`SliceMark`、`VertexMark`。**这个方向是错的。**

各类 mark 之间的差异（条形是矩形带一个值、箱线图是矩形带五个值、折线是点、散点是点带两个值）是**数据形状**差异，不是**行为**差异。所有消费者对它们做的事情完全一样：取框、取值。做成子类之后，每个目标导出函数都要写类型分支或访问者模式——分支只是从定义处搬到了使用处，总量不减。

形状差异用**组合**解决：mark 携带一个值字典而非单个标量，条形填一个键，箱线图填五个键。

真正需要分层的是记录本身，理由是这三层有独立的存在意义：

| | 独立性体现在 |
|---|---|
| **消费者不同** | 只做 ParseBench Charts 维度需要 L0+L1；只做 Visual Grounding 只需要 L0；L2 只被 drill-down 任务消费 |
| **能力要求不同** | 任何渲染器都能产出 L0；L1 需要插桩渲染器（读取绘图库内部的 artist 层级）；**L2 需要底层存在原子事实表** |
| **可证伪性不同** | L2 是唯一别人结构上无法产出的层。把它单独隔开，消融实验就是"关掉 L2 重训" |

## 3. 每层的内容与消费者

### L0 · 几何

页面上所有元素的框与类别，类别取自 ParseBench 的标签集 `{Text, Table, Picture, Page-Header, Page-Footer}`。不含任何数据语义。

**消费者**：Visual Grounding 维度。
**依赖**：[05 §3](05_render.md) 的页面合成。不渲染进页面则这一层退化为平凡。

### L1 · 编码

视觉到数据的映射：

- 每个 mark 的框、所属面板、代表的键、承载的值、以及**图上有没有画出这个数值**
- 每个面板的框、纵轴的值域与像素域（[04 §3](04_figure_selection.md) 的值可恢复性靠这两组数算）
- 每个图例项的色块框、映射到哪个类别、**适用于哪些面板**

**消费者**：chart-to-table（ParseBench 主任务）、mark 级 grounding、共享图例绑定。
**依赖**：插桩渲染器。

> 图例项的"适用于哪些面板"是 ParseBench 点名的失败模式，而这项 ground truth 你能免费产出。

### L2 · 溯源

每个 mark 对应多少行原子事件。

**一处简化**：不存行 id 列表，只存行数。需要真实行时用 mark 的键去过滤事实表即可确定性还原——**存键不存行**。

**消费者**：drill-down 任务。
**依赖**：原子粒度的事实表。这是原子粒度唯一不可替代的用途，也是它在实验上唯一可证伪的地方。

## 4. 训练目标

所有目标都是溯源记录的纯函数，各自独立开关：

| 目标 | 依赖层 | 内容 |
|---|---|---|
| 结构化表 | L1 | 所有 mark 的 (键, 值) 全集 |
| spot-check 标注集 | L1 | ≤10 个点，画了标注则容差为 0，否则 1% |
| 页面元素框 | L0 | bbox + 类别 |
| mark 定位 | L1 | 给定数据描述 → 框 |
| mark 读值 | L1 | 给定框 → 值 |
| 图例绑定 | L1 | 给定图例项 → 适用面板集合 |
| drill-down | L2 | 给定数据描述 → 聚合行数 |
| caption | — | 由 [02](02_scenario.md) 的场景与分析意图直接得到 |

模块边界：**目标导出只消费溯源记录，不知道事实表，也不知道渲染器。**

## 5. 与算子代数的对应

现有 [`phase_3.md`](../data_generation/phase_3.md) 的算子代数定义了两个类型：V（视图）与 S（标量）。溯源记录引入第三个类型 **R（区域）** 和三个算子：

| 算子 | 签名 | 含义 | 对应层 |
|---|---|---|---|
| Locate | (V, S) → R | 这个数据画在图上什么位置 | L1 |
| Read | R → S | 这块区域编码的值是多少 | L1 |
| Rows | S → V | 下钻到这个 mark 背后的原子事件 | L2 |

加入之后 grounding 问题与推理问题共用同一条流水线定义，难度仍然是算子个数——不需要为 grounding 单开一个模块。

**但在当前阶段不实现成算子。** 上一节那三个目标（mark 定位、mark 读值、drill-down）就是这三个算子的直接展开，用三个导出函数即可。等推理优先级提上来、算子代数接回时，再把它们并入采样器。这是最省的路径。
