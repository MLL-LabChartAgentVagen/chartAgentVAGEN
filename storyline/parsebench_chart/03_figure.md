# 03 · 选图

从事实表投影出图表就绪的视图，决定画哪些图，产出 FigureSpec。

**本文**
1. [三步](#1-三步) → 2. [投影](#2-投影) → 3. [枚举](#3-枚举) → 4. [过滤](#4-过滤) → 5. [选择](#5-选择) → 6. [FigureSpec](#6-figurespec) → 7. [示例](#7-示例)

---

## 1. 三步

```
枚举（按规则）  →  过滤（按规则）  →  选择（LLM）
  要覆盖全            要能画            要有判断
```

过滤在选择之前。LLM 只从过滤后的候选清单里挑序号，因此它挑不出不可行的图，不存在"选完再验、验不过重选"的回环。

---

## 2. 投影

一个视图由三个操作复合得到：先按条件选行，再分组聚合，最后取需要的列。

```
视图 = 选行 → 分组聚合 → 取列
```

聚合时**一并返回每组的行数**。`COUNT(*)` 与聚合值一起算出来，它就是 [05](05_provenance.md) 的 L2 层内容，不需要再算第二遍。

同一张事实表投影出的所有视图共享同一份底层算术。两张图上的同一个数必然相等，**跨图一致性由构造保证**，不需要事后校对。

---

## 3. 枚举

枚举器遍历三个维度的组合：**图表类型 × 列绑定 × 聚合函数**，再乘以一个受限的行过滤集合。

### 3.1 列绑定

对 [registry.md](registry.md) 里的每个图表类型，取它声明的列角色要求，从表结构说明里找出所有能填进这些角色的列。

- 类别角色接受类别列与日历派生列（星期、月、季度、是否周末）
- 时间角色只接受时间列
- 数值角色接受数值列
- 同一个视图里一个列不能填两个角色

填好后立即查基数：聚合结果的取值数落在该类型声明的范围内才保留。`quarter` 只有 2 个取值，填进 `bar` 时基数下限是 3，直接淘汰，不必真去跑聚合。

### 3.2 聚合函数

聚合方式由测度的可加性决定，这是 [02](02_fact_table.md) 声明的：

| 测度 | 允许的聚合 |
|---|---|
| 可加 | SUM、AVG、MAX、MIN |
| 不可加 | AVG、MEDIAN、MAX、MIN |
| 任意（不需要测度） | COUNT(*) |

对不可加的测度求和永远不合法，因此不进入枚举——"三个科室的满意度加起来"这种视图从一开始就不存在。

### 3.3 行过滤

行过滤的组合是无穷的，而它对图表形态的贡献只有"同一视图看不同的时间窗"这一种。因此只枚举两类：

- 不加过滤
- 时间切片：前半段 / 后半段（仅当视图里有时间列）

其余任何过滤条件都不枚举。

### 3.4 上限

组合数随列数增长很快。按族与按场景设两道上限，超出时按确定性顺序（图表类型序 → 列序 → 聚合序）截断，并记录丢弃了多少。截断是确定的，同一个输入每次得到同一个候选清单。

---

## 4. 过滤

两组检查，全部通过才进候选清单。判据来自 [02](02_fact_table.md) 的列声明与实际聚合结果，不需要 LLM。

### 4.1 数据质量

| 检查 | 判据 |
|---|---|
| 区分度 | 聚合后不同取值的数量足够，不是几个格子取同一个数 |
| 变异 | 变异系数超过阈值，不是一条平线 |
| 格子占用 | 二维视图（grouped_bar、heatmap）每格支撑的行数达到 registry 声明的下限 |

格子占用这一条挡的是"看起来有 100 个格子、其实每格只有 1 行数据"的热力图——它的颜色不代表任何统计量，只是单个观测的噪声。

### 4.2 语义适当性

**这张图是不是一个真人分析师会画的图。**

反例：按月份画温度的饼图。它满足结构约束（3–8 个类别、一个数值列），枚举器一定会产出它；但饼图表示部分与整体，12 个月的温度加起来没有意义。

判据是查表，不是推断：

| 图表族 | 要求 |
|---|---|
| 构成（pie、donut、stacked_bar、area、treemap） | 测度可加 |
| 流程（waterfall、funnel） | 维度有序，waterfall 另要求可加 |
| 关系（radar） | 多个测度同量纲 |
| 其余 | 无要求 |

可加性与有序性在 [02](02_fact_table.md) 声明 measure 与 dim 时就给出了，此处只做匹配。

> 原设计把这一判断交给 LLM。改为查表后它是确定的、可复现的，也与 [04](04_render.md) 的风格采样无关。

## 5. 选择

一次 LLM 调用。输入：表结构说明、[01](01_scenario.md) 的分析意图、过滤后的候选视图清单（每条一行，带序号）。输出：选中的序号、每张图对应哪条意图、面板怎么组合。

**它只在给定选项中做选择，不接触原始数据，不产生任何数值。** 出口只查一件事：选中的序号在清单里。此外无需验证。

意图归属的用途是 [06](06_output.md) 的 caption 目标。

---

## 6. FigureSpec

一张最终图像的完整描述。

| 字段 | 内容 |
|---|---|
| 面板列表 | 每个面板一个 ViewSpec（含聚合后的值与每组行数） |
| 版面 | 单图 / 网格 / 同面板双轴 |
| 共享关系 | 是否共享 x 轴、y 轴、图例 |
| 依据 | 对应哪条分析意图，用于生成 caption |

风格与退化不进 FigureSpec，由 [04](04_render.md) 独立采样。

**值能不能从图上读出，不在本阶段判定**。它取决于轴范围与图像尺寸，而这两者由 [04](04_render.md) 决定，因此改为渲染之后按实际像素几何算，见 [05 §5](05_provenance.md)。原设计在这里预测，导致 03 与 04 之间要来回一次；移出后本阶段是纯前向的。

---

## 7. 示例

接[急诊科事实表](02_fact_table.md#6-示例)。可用列：

```
类别   hospital(3)  department(4)  severity(3, 有序)
派生   day_of_week(7)  month(6)  quarter(2)  is_weekend(2)
时间   visit_date(182 天)
数值   wait_minutes(可加)  cost(可加)  satisfaction(不可加)
```

枚举与过滤的结果，取其中八条：

| # | 视图 | 结果 |
|---|---|---|
| 1 | `bar(hospital × AVG(wait_minutes))` | 保留 |
| 2 | `bar(quarter × AVG(cost))` | 枚举时淘汰：quarter 基数 2，低于 bar 的下限 3 |
| 3 | `pie(department × SUM(cost))` | 保留 |
| 4 | `pie(department × SUM(satisfaction))` | 不枚举：satisfaction 不可加，SUM 不在允许的聚合里 |
| 5 | `pie(department × AVG(satisfaction))` | 过滤时淘汰：pie 属构成族，要求测度可加 |
| 6 | `line(visit_date × hospital × AVG(wait_minutes))` | 保留 |
| 7 | `heatmap(day_of_week × month × AVG(wait_minutes))` | 过滤时淘汰：7×6=42 格，900 行摊下去每格约 21 行，通过；若行数只有 200 则每格不足 3 行，淘汰 |
| 8 | `scatter(wait_minutes × satisfaction)` | 保留 |

第 4 条与第 5 条是同一件事在两个位置被挡住：SUM 在枚举阶段就不产生，AVG 能产生但过不了构成族的可加性要求。两道都要有——前者省算力，后者兜住"平均一下就不算求和了"这种绕过。

LLM 拿到过滤后的清单，按三条分析意图各选一张：

```
意图① 哪家医院等待最久      → #1  bar(hospital × AVG(wait_minutes))
意图② 等待时间怎么变化       → #6  line(visit_date × hospital × AVG(wait_minutes))
意图③ 等待与满意度是否相关   → #8  scatter(wait_minutes × satisfaction)
```

意图①对应的 FigureSpec：

```
面板   1 个
视图   bar，x = hospital，y = AVG(wait_minutes)
数据   协和 42.3 (372 行)   华山 35.8 (315 行)   瑞金 28.1 (213 行)
版面   单图
依据   意图① "哪家医院、哪个科室的等待时间最长"
```

括号里的行数直接来自聚合时的 `COUNT(*)`，它会成为 [05](05_provenance.md) 的 L2 层。
