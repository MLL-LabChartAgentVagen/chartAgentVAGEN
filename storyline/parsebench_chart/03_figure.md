# 03 · 选图

从事实表投影出图表就绪的视图，决定画哪些图，产出 FigureSpec。

**本文**
1. [三步](#1-三步) → 2. [SQL 投影与枚举](#2-sql-投影与枚举) → 3. [过滤](#3-过滤) → 4. [选择](#4-选择) → 5. [FigureSpec](#5-figurespec)

---

## 1. 三步

```
枚举（确定性）  →  过滤（确定性）  →  选择（LLM）
  覆盖率              可行性             判断力
```

过滤在选择之前。LLM 只从已过滤的候选清单里挑序号，因此它挑不出不可行的图，不存在"选完再验、验不过重选"的回环。

---

## 2. SQL 投影与枚举

视图由三个算子复合得到：行选择、分组聚合、列投影。

```
View = σ_filter ∘ γ_agg ∘ π_cols (M)
```

枚举器遍历 [Chart Registry](registry.md) 中每个图表类型的列角色规则，用 Schema Metadata 匹配出所有满足结构约束的 `(chart_type, column_binding)`。这一步不做取舍。

同一事实表投影出的所有视图共享同一份底层算术，因此**跨图一致性由构造保证**。

**聚合时一并产出行数**。每个分组的 `COUNT(*)` 与聚合值一起返回，它就是 [05](05_provenance.md) 的 L2 层内容——L2 不需要单独的一遍计算。

---

## 3. 过滤

两组确定性检查，全部通过才进入候选清单。判据全部来自 [02](02_fact_table.md) 的列声明与实际聚合结果，不需要 LLM。

### 3.1 数据质量

| 检查 | 含义 |
|---|---|
| 区分度 | 聚合后的不同取值数量足够 |
| 变异 | 变异系数超过阈值，不是一条平线 |
| 格子占用 | 二维视图（grouped_bar、heatmap）每格支撑行数达到 registry 声明的下限 |

### 3.2 语义适当性

**这张图是不是一个真人分析师会画的图。**

反例：按月份画温度的饼图。它满足结构约束（3–8 个类别、一个数值列），枚举器一定会产出它；但饼图表示部分与整体，12 个月的温度加起来没有意义。

判据是测度的**可加性**，它在 [02](02_fact_table.md) 声明 measure 时给出，不在此处推断：

| 图表族 | 要求 |
|---|---|
| composition（pie、donut、stacked_bar、area、treemap） | 测度可加 |
| flow（waterfall、funnel） | 测度可加且维度有序 |
| relationship（radar） | 多个测度同量纲 |
| 其余 | 无要求 |

计数、金额、时长可加；比率、百分比、温度、评分不可加。声明一次，此处只做查表。

> 原设计把语义适当性交给 LLM 判断。改为查表后，这一步是确定性的、可复现的，且与 [04](04_render.md) 的风格采样无关。

---

## 4. 选择

一次 LLM 调用。输入：Schema Metadata、[01](01_scenario.md) 的分析意图、过滤后的候选视图清单。输出：选中的视图序号、每张图对应哪条分析意图、面板组合方式。

**它只在给定选项中做选择，不接触原始数据，不产生任何数值。** 输出经过一次成员检查（选中的序号必须在候选清单内），此外无需验证。

意图归属的用途是 [06](06_output.md) 的 caption 目标。

---

## 5. FigureSpec

一张最终图像的完整描述。

| 字段 | 内容 |
|---|---|
| 面板列表 | 每个面板一个 ViewSpec（含聚合值与行数） |
| 版面 | 单图 / 网格 / 同面板双轴 |
| 共享关系 | 是否共享 x 轴、y 轴、图例 |
| 依据 | 对应哪条分析意图，用于生成 caption |

风格与退化不进 FigureSpec，由 [04](04_render.md) 独立采样。

**值可恢复性不在本阶段判定**。它依赖轴范围与图像尺寸，这两者由 [04](04_render.md) 决定，因此改为渲染后按实际像素几何计算，见 [05 §4](05_provenance.md)。原设计在此处预测可恢复性，导致 03 与 04 之间存在回环；移出后本阶段是纯前向的。
