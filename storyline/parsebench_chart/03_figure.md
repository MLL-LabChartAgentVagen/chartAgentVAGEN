# 03 · 选图

从事实表投影出图表就绪的视图，决定画哪些图，产出 FigureSpec。

**本文**
1. [三步](#1-三步) → 2. [SQL 投影与枚举](#2-sql-投影与枚举) → 3. [选择](#3-选择) → 4. [过滤](#4-过滤) → 5. [FigureSpec](#5-figurespec)

---

## 1. 三步

```
枚举（确定性）  →  选择（依分析意图）  →  过滤（确定性）
  覆盖率              判断力                可读性
```

---

## 2. SQL 投影与枚举

视图由三个算子复合得到：行选择、分组聚合、列投影。

```
View = σ_filter ∘ γ_agg ∘ π_cols (M)
```

枚举器遍历 Chart Registry 中每个图表类型的列角色规则，用 Schema Metadata 匹配出所有满足结构约束的 `(chart_type, column_binding)`。这一步不做取舍。

同一事实表投影出的所有视图共享同一份底层算术，因此**跨图一致性由构造保证**。

---

## 3. 选择

一次 LLM 调用。输入：Schema Metadata、[01](01_scenario.md) 的分析意图、枚举出的合法视图清单。输出：一组 FigureSpec。

**它只在给定选项中做选择，不接触原始数据，不产生任何数值。**

---

## 4. 过滤

三组确定性检查，全部通过才保留。

### 视图质量

| 检查 | 含义 |
|---|---|
| 区分度 | 聚合后的不同取值数量足够 |
| 变异 | 变异系数超过阈值，不是一条平线 |
| 格子占用 | 二维视图（grouped bar、heatmap）每格支撑行数足够 |

### 语义适当性

**这张图是不是一个真人分析师会画的图。**

反例：按月份画温度的饼图。它满足结构约束（3–8 个类别、一个数值列），枚举器一定会产出它；但饼图表示部分与整体，12 个月的温度加起来没有意义。

判据来自分析意图：选出的图必须对应某条具体意图。

### 值可恢复性

**图上标的那个数，能不能从图上量出来。**

显式画出数值的点要求精确匹配；未画出的点给 1% 相对容差，因此该值必须能从像素几何估读到 1% 以内。

> 纵轴 0–6000、图高 400 像素 → 1 像素约 15 个单位。值 4521 的 1% 是 45 个单位约 3 像素，量得出来。
> 若纵轴改为 0–600000 → 1 像素约 1500 个单位，4521 的 1% 只有 0.03 像素，量不出来。

不满足时三条出路：给该点画上数值标注、调整轴范围、或将该点排除出标注集。

> 此判据依赖轴范围与图像尺寸，因此选图与 [04](04_render.md) 之间存在一次回环。

**分工**：语义适当性挡"不该画的图"，值可恢复性挡"不该问的点"。

---

## 5. FigureSpec

一张最终图像的完整描述。

| 字段 | 内容 |
|---|---|
| 面板列表 | 每个面板一个 ViewSpec |
| 版面 | 单图 / 网格 / 同面板双轴 |
| 共享关系 | 是否共享 x 轴、y 轴、图例 |
| 依据 | 对应哪条分析意图，用于生成 caption |

风格与退化不进 FigureSpec，由 [04](04_render.md) 独立采样。
