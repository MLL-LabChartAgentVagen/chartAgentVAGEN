## 2. F1 — M1 偏差来源：上游 conditional 传播，**不是**单变量 noise

> **⚠️ 更正（2026-05-30）**：本节「真正的偏差源 = 乘性公式的乘积方差」这一归因**有误**——residual validator 用实测因子列重算公式，乘积方差被减掉、进不了 residual（自第一版起就如此）。M1 `residual_*` 失败的真因是 **Phase γ pattern 污染 + P3-8 排除泄漏**，σ 无关。本节关于「clip 不能修 M1」的结论仍成立，但理由应以 [mechanisms/M1_RESIDUAL_RECONCILIATION.md](mechanisms/M1_RESIDUAL_RECONCILIATION.md) 为准。

### 现状

加性 noise 在 [`pipeline/phase_2/engine/measures.py:276-279`](../../pipeline/phase_2/engine/measures.py#L276-L279) 实现：

```python
if noise_config:
    sigma = noise_config.get("sigma", 0.0)
    if sigma > 0:
        values = values + rng.normal(0, sigma, size=n_rows)
```

- 分布：Gaussian（硬编码）
- 均值：0
- σ：由 LLM 在 spec 中声明
- 无任何 clip

### 真正的偏差源

| 层级 | 来源 | 量级 |
|---|---|---|
| 单变量 noise（附加层）| LLM 声明的 `N(0, σ)` | 与 σ 同阶 |
| **conditional / 上游传播（主因）** | 结构性公式如 `A × B × C` 把上游 stochastic 方差乘性叠加 | 可达 σ × **10 ~ 60 倍**（pingyue 实测 66×, 29×）|
| ratio operator 子类 | 除法 `A/B` 自带不可消除的下限方差 `(E[A]/E[B])² · ((σ_A/E[A])² + (σ_B/E[B])²)` | 与 σ 无关 |

变量乘积的方差公式：

```
Var(XY) = Var(X)·Var(Y) + Var(X)·E[Y]² + Var(Y)·E[X]²
```

LLM 在声明 `noise.sigma` 时只看到「附加 noise」那一层，无法估算上游随机链的累积方差——这是 M1 系统性失败的根因。

### 参考

- [`archive/MECHANISM_1_DEEP_DIVE.md`](archive/MECHANISM_1_DEEP_DIVE.md)
- [`mechanisms/M1_RATIO_OPERATOR_STRAGGLER.md`](mechanisms/M1_RATIO_OPERATOR_STRAGGLER.md)

### 含义

**Clip 单变量 noise 到 variable 的 1% 不能修 M1 主失败模式**——这只是把已经很小的附加层再压一压；主要方差源在乘积公式本身。本轮因此不动 measures.py:279。修复 M1 真因属于后续轮次。

## 3. F2 — M3 中 n<30 的真相：被 validator **跳过**，没真进 KS

### Phase 1 没有硬性 n≥30 guardrail

在 [`pipeline/phase_1/scenario_contextualizer.py`](../../pipeline/phase_1/scenario_contextualizer.py)（生成 scenario context 的位置）里没有 cell-count / n_cell 相关计算。

### Prompt 层：软约束

[`pipeline/phase_2/orchestration/prompt.py:119-130`](../../pipeline/phase_2/orchestration/prompt.py#L119-L130) 的 **Constraint 13 "KS-CELL DENSITY"**：

> `target_rows ≥ 30 × cell_count`（K=∏ categorical levels）

这是 prompt 给 LLM 的建议，**LLM 可能不遵守**。

### Validator 层：硬 gate

[`pipeline/phase_2/validation/statistical.py:357-359`](../../pipeline/phase_2/validation/statistical.py#L357-L359)：

```python
if len(sample) < KS_MIN_CELL_SIZE:   # KS_MIN_CELL_SIZE = 30
    skipped_small += 1
    continue
```

n<30 的 cell **不会**被传入 `scipy.stats.kstest`。它们只是被记入 `skipped_small` 计数，并在 detail 字符串里报告（statistical.py:374-375）：

```python
detail=f"... {skipped_small} small-n, {skipped_no_cdf} no-CDF"
```

### 用户看到的「大量 n<30 出现」= 哪里来的

最可能的来源：detail 字符串里的 `skipped_small` 计数。**这些 cell 实际上没有被 KS 测试**——它们是被跳过的报告项，不是失败原因。

### Phase D.2 没改 KS 密度

[commit `fad9d8b`](../../) 的 row-count guardrail 是针对 **Constraint 17 (seasonal_anomaly)** 的 `expected_rows = target_rows × (window_days / temporal_range_days) × P(filter)` ≥ 5 / 10，与 KS cell density 无关。详见 `BACKLOG.md §4.6`（Phase D.4 候选）。

### 暴露出的另一个 observability 盲区（**本轮不修**）

当**所有** cell 都因 n<30 被跳过时，validator 仍返回 `passed=True`（statistical.py:368-376），相当于「沉默通过」。这是覆盖率盲区，不是误报，但用户在 detail 里看到「全部 skip」时容易产生误解。

## 4. F3 — 当前支持的 distribution

[`pipeline/phase_2/engine/distributions.py:31-34, 113-148, 197`](../../pipeline/phase_2/engine/distributions.py#L31)：

| family       | 入口行 | 实现 |
|--------------|------:|------|
| `gaussian`   | 132 | `rng.normal(mu, sigma)` |
| `lognormal`  | 134 | `rng.lognormal(mu, sigma)` |
| `gamma`      | 136 | `rng.gamma(shape=mu, scale=sigma)` |
| `beta`       | 138 | `rng.beta(mu, sigma)` |
| `uniform`    | 140 | `rng.uniform(low=mu, high=sigma)` |
| `poisson`    | 142 | `rng.poisson(mu)` |
| `exponential`| 144 | `rng.exponential(1/mu)` |
| `mixture`    | 197 | 递归混合上述任意组合（IS-1）|

KS validator 经 [`expected_cdf()`](../../pipeline/phase_2/engine/distributions.py#L165-L199) 给出对应 scipy frozen distribution；`poisson` 返回 `None`（离散，KS 不适用），`uniform` 在 `high <= low` 时返回 `None`。

**Noise 注入是硬编码 Gaussian**（measures.py:279），不可按 measure 配置 family。如果未来需要让 noise 也支持非 Gaussian（如 lognormal noise），需要在 `noise_config` 增加 family 字段并改 measures.py。

## 5. F4 — Validation 不准确是否是根因？

**部分是，但不是唯一**。

### 已识别的 fragility 点

| Validator | 文件:行 | 问题 |
|---|---|---|
| `check_structural_residuals` | [statistical.py:456-572](../../pipeline/phase_2/validation/statistical.py#L456-L572) | 硬编码 0.2 ratio 阈值，在乘性域天然不可达；pattern eval 用 `except: pass` 静默吞错 |
| `check_stochastic_ks` | [statistical.py:270-421](../../pipeline/phase_2/validation/statistical.py#L270-L421) | n<30 跳过 cell 后若全部跳过仍 `passed=True`，沉默盲区 |
| `check_marginal_weights` | [structural.py:226-314](../../pipeline/phase_2/validation/structural.py#L226-L314) | rare 类别 (p<5%) 的 Wald 余量过严，一次缺席观测就触发 fail |
| `check_group_dependency_transitions` | [statistical.py:575-710](../../pipeline/phase_2/validation/statistical.py#L575-L710) | 不跳过单个 child level；rare child (p̂=0.05) 在小 cell 上 binomial 噪声主导 |
| L3 pattern checks | `pattern_checks.py` | 多处 `except: pass` 静默吞 target eval 错误，区分不开「target 命中 0 行」与「target 表达式无效」|

### 结论

validator 准确性问题主要表现为「**沉默通过 / observability gap**」（小样本跳过仍 pass、错误被吞），**不是**误报。

更根本的源头在上游：**noise spec 与 multiplicative 公式失配**——残差膨胀后被 validator 报告，validator 本身的阈值机制只是把这个失配显性化（且在某些域天然不可达）。

**修 validator 不能根治 M1**；修上游 noise 模型才能。
