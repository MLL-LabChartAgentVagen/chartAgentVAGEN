# KS n<30 — 裁定:无需修复 (Verdict, 2026-05-31)

> 配套测量:[KS_N30_MEASUREMENT_2026-05-31.md](./KS_N30_MEASUREMENT_2026-05-31.md)
> (90 场景 / 1,102 KS cell:~19% cell 因 n<30 被跳,34% measure 有 ≥1 cell 被跳,
> 但**全 cell 被跳的 silent-pass 仅 1%(2/148)**)。
> 本文记录对"这个 n<30 现象是否必须解决"的裁定及理由。

## 裁定

**n<30 不是必须解决的 bug,validator 维持现状,不改代码。**

唯一真实的覆盖漏洞是 1% 的 silent-pass(一个 measure 的所有 cell 都被跳过),
且它已在
[statistical.py:367-377](../../pipeline/phase_2/validation/statistical.py#L367-L377)
的 detail 串里透明标注("No testable cells"),并未假装测过。这个残余风险可接受。

## 理由

1. **跳过 n<30 是统计上正确的,不是缺陷。** KS 在小样本下功效极低(Massey 1951);
   validator 又对实测 cell 施加 Bonferroni(α = 0.05 / K,见
   [statistical.py:379](../../pipeline/phase_2/validation/statistical.py#L379)),
   小 cell 几乎永远拒绝不了——真去测只是噪声,不是信号。所以"19% cell 被跳"
   **≠**"19% 数据没把关",而是"这 19% cell 上 KS 本就说不出话"。
2. **validator 是对数据生成器的把关,不是数据本身的生产环节。** 对生成器,只要
   **大部分时候**在分布上可靠即达标;Bonferroni + KS 本身已偏保守、会误拒合理波动,
   对小 cell 宽松反而合理,不应再加测试压力去追求逐 cell 全覆盖。
3. **真正的 engine bug 是系统性的。** 它会污染整列的生成过程,因此会在 n≥30 的大 cell
   和聚合层面同样暴露;只藏在单个小 cell 里的 bug 罕见且后果小。换言之,被跳过的小 cell
   并不是 bug 的独占藏身处。

## 为什么不靠"加行数"解决

[KS_N30_MEASUREMENT](./KS_N30_MEASUREMENT_2026-05-31.md) 的 candidate follow-ups
列了几条"提高行数供给"的路子(绑定 Constraint 13、抬高 simple/medium 的 `target_rows`
下限、给 simple 档类目基数封顶)。它们**不作为主手段**:

- 粗暴且更贵(更多行 = 更高生成成本 + 更大表 + 可能触发重生成)。
- 与分档设计冲突——simple 档本就该小([scenario_contextualizer.py:102-106](../../pipeline/phase_1/scenario_contextualizer.py#L102-L106))。
- 受 `n ≈ target_rows / cell_count` 制约,在低档**根本喂不饱**:测量已显示分档只在有余量的
  complex 档奏效,simple/medium 没余量。

(给 simple 档类目基数封顶,若出于图表可读性/真实性等**其它**理由,可单独考虑;
但不为 KS n<30 而做。)

## 未来选项(若日后改变主意):PIT-pooled backstop

如果以后要消灭那 1% silent-pass,正确做法**不是造更多行**,而是 **PIT(概率积分变换)**:

- 每行按其 cell 声明的 CDF 变换 `u_i = F_{cell(i)}(x_i)`;若 engine 符合声明,则不论来自
  哪个 cell,所有 `u_i ~ Uniform(0,1)`,可汇成**一次**大样本 KS(`n = target_rows`),
  **永不触发 n<30 跳过**。它检验的零假设与逐 cell KS 完全一致,只是把证据汇总而非碎片化。
- **几乎零成本**:循环里每个 cell 已算出 `dist = expected_cdf(family, cell_params)`
  ([statistical.py:343-362](../../pipeline/phase_2/validation/statistical.py#L343-L362)),
  只需多攒 `dist.cdf(sample)`,循环后 `scipy.stats.kstest(pooled_u, "uniform")`。最小接入
  = 只把 K=0 分支的自动 pass 换成这次 pooled 检验。
- **接入前的验证**(只读、复用 `output/agpds/ks-measure-n90` 批次):对被 n<30 跳过的小
  cell 子集单独算 pooled PIT,看其拒绝 Uniform 的比率。≈5%(raw)/≈0(Bonferroni)即证明
  被跳数据无系统性偏差、坐实"无需修复";显著偏高才值得接入 backstop。

  **局限**:PIT 仅对**连续**分布精确(离散 family 有保守偏差,需排除/单列);pooled 检验
  擅长抓系统性偏差,对仅局限于单个小 cell 的偏差会被稀释——这恰好与上面"理由 3"的风险画像
  吻合(强在该强处,弱在罕见且后果小处)。

## 结论

维持现状。本裁定关闭 KS n<30 议题;PIT-pooled backstop 仅在未来 silent-pass 被证明有害时
重启,届时按上节的只读验证 → K=0 分支接入即可。
