## T0 · 两条贯穿全程的原则

**这两条约束下面每一项待办的写法，先于任何数字。**

### T0.1 · 目标是一篇通用的 chart generation pipeline，不是对齐 ParseBench

要做的是一个**general 的、有 novelty 的**图表生成流水线（可防守的轴是 grounding / provenance：`(键, 值, 区域)` 与 datum → mark → source_rows 这条链）。**ParseBench 是仪器，不是目标函数**——它是目前唯一能同时测 Charts 与 Visual Grounding 两维的现成基准，所以拿来做验收，但它测不到的东西不等于没价值。

三条判据，写任何一条改进意见都要过：

| 判据 | 说明 |
|---|---|
| **改动必须是加能力** | 每条改进带一行「对 storyline 的作用」。会削减现有能力的（例如按基准的类型配比裁掉七种图表），改写成「加一个可配置维度 + 保留原默认」（族权重向量，不是删类型） |
| **消融行只增不减** | 改完之后消融表的行数不能变少。这是上一条的可检验形式 |
| **「基准不测它」不等于「它无用」** | 对已有能力，正确的问法是「有没有东西消费它」——另一个目标基准、一行消融、或一条能力主张。三者皆无才算真的可裁 |

所以分析报告要**双栏出结论**：这一项对 ParseBench 分数的影响 / 这一项对通用性与 novelty 的作用。两者之间没有汇率，不要压成一列排序。

### T0.2 · 一切分析都要落在 ParseBench 自己的定义上

样例分析与失败分析都不能凭直觉判断「这一页难不难」「这个失败严不严重」，必须回到基准自己的定义：

- **chart 的定义**——什么算一张图、一页几张图、`other` 类型必须命名；数据集的构成见 [review/01](review/01_benchmark.md)
- **metric 的定义**——`ChartDataPointRule` 的四步判定（有没有表 → 值是否在容差内 → 键能否与该格关联 → 表前的粗体 / 标题回退），单条二值、按页平均；逐条见 [review/02](review/02_chart_metric.md)
- **标注的定义**——GT 只到抽查点（值 + 1–4 个键 + 容差），没有整表 GT，`expected_markdown` 恒为 null；tag 按文档级施加

**落地要求**：每个观察项声明它能改变四步判定的哪一步（上一轮的 `affects` 字段，保留这个做法）；空的就明确写「度量看不见它」，然后按 T0.1 的第二栏判断它值不值得做。失败归因的类目也必须能映回四步中的某一步，不能自造与度量无关的分类。

## 附录 · 旧分析留档

删除前要保住的东西：先是**两份 report 各自的结论**（下面两段，每段就是这一份的全部主张），再是支撑它们的数字。论述不留。

### 结论 · 样例分析（192 页）一句话

> ParseBench 的页面上，**图周围的文字**是最大的一块缺口（单位写在轴 / 标题里占 78% 的页、图号 56%、标题里带单位 60%），但**度量基本看不见它**（4,864 条规则里值带量纲词 0 条、标签用图号 14 条）。真正能提分的缺口集中在另一批组件：换行的类目标签、画在外侧的数值标签、脚注标记、无数值轴、负值、稠密图元。类型上没有大空洞——`other` 的 8% 拆开后只有 3 张是真正的新画法（区间 / 哑铃图）。

**这一句同时是 T0.1 的例子**：第一块几乎不影响分数，但 94% 的真实图有标题而我们的图连标题来源都没有，按「有没有东西消费它」判，它属于通用性那一栏，该做。

### 结论 · 失败样本分析（一次 82.75% 的运行）一句话

> 剩下的 896 个失败里 **72% 不是把数读错了，而是那个数在表里找不到能对上的键**——且失联的键有 79% 就写在同一张表里，只是不在值那一行。全部改对的上界是 82.75% → 95.41%。**第一顺位因此不是「画得更准」，而是「每个图元都带着它的全部键」**，正是输出单位 `(键, 值, 区域)` 的定义。第二顺位是稠密度：≤20 图元 85.5% → >400 图元 57.9%，而我们现在的上限全落在最容易那一档。

两份分析的第一顺位一致（都指向键的完整性），这是上一轮唯一有两条独立证据的结论，重跑时优先复核它。

### B · 失败样本分析（`ppdoclayoutv3_lean_qwen` 一次运行 / 不调模型）

**口径**：PP-DocLayoutV3 lean + Qwen3.8-27B，568 页 / 4,864 抽查点，`passed` 全取自官方 `_evaluation_report.json`。按页平均 **82.75%**，896 个失败。

| 失败形态 | 个数 | 占失败 |
|---|---:|---:|
| `label_unlinked` 值在表里，但键关联不上 | 599 | 66.9% |
| `value_off` 值读错 | 199 | 22.2% |
| `row_missing` 某个键整张表都没有 | 48 | 5.4% |
| `unit_mismatch` 量级写错 | 36 | 4.0% |
| `value_absent` 键都在但没写这个值 | 14 | 1.6% |
| `no_table` 整页无表 | 0 | 0.0% |

- 寻址失败合计 **72%**；失联键 **79.3% 就在同一张表里**，只是不在值的行 / 列 / 表头上
- 寻址失败全部改对的上界：按页平均 82.75% → **95.41%**
- 读数误差中位 **15%**，≤5% 的只占 13%（放宽容差救不回一半）
- 三条单调关系（两端 95% 区间不重叠）：定位键数 2 键 83.3% → 3 键 69.0% → 4 键 55.9%（全 568 页）· 图元数 ≤20 85.5% → >400 57.9% · 数值全部印出 94.5% vs 一个不印 75.9%

- 整页文字量与通过率**不单调**，原因未定

### C · 合并结论（`synthesis/`）

五条能力轴 + 一条方法轴，每条自带消融行：**A1 全地址键与键分量** · **A2 可读性是连续量而非二值门** · **A3 数值的呈现语义（量纲 / 负值 / 刻度格式）** · **A4 非数据图元与缺失** · **A5 图是页面对象（标题、图号、页面文字）** · **M 每条轴自带消融行**。

排序依据两条：频次（基准里有多少这种图）与失败率（这种图要付多少代价），两者第一顺位一致，都指向 A1。
