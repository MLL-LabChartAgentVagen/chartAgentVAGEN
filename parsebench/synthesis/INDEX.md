## 1 证据合并

### 1.1 两份分析各自测了什么

| | 页面分析 | 失败分析 |
|---|---|---|
| 读的对象 | 基准页面本身 | 一个解析器在这些页面上的输出 |
| 分母 | 192 页 · 1,658 个抽查点 · 265 张图 | 568 页 · 4,864 个抽查点 |
| 产物 | 65 项组件词表的逐页计数、类型配比、标题五字段、39 项「我们画不出来」 | 896 个失败的形态分布、失联键的落位、通过率随自变量的曲线 |
| 判据是怎么定的 | `affects`（能改变四步判定的哪一步）与文档分布，两列都在看任何一页之前按度量定义定死 | `passed` 全部取自官方 `_evaluation_report.json`，本地只做「这个值和这些键落在输出的哪里」 |
| 它单独能说什么 | 真实报告页有哪些构造、有多通用 | 剩下的失败是什么形状、每种形状值多少分 |
| 它单独说不了什么 | 每一项值多少分 | 基准上还有哪些构造根本没出现在失败里（因为解析器没被它绊倒，或因为它根本不承载规则） |

**两份的分母不独立**：192 页是 568 页的随机子集。因此「组件 → 通过率」那一类交叉只能提假设，不能当验收，理由在 [§5.2](#52-相关不是因果)。

合并的价值全在这四行——每一行都是任何一份单独的分析写不出来的。

### 1.3 两种可见性

第 3 行是这次合并唯一一处推翻了单份判定的地方，值得单独定义。

| | 定义 | 页面分析怎么判 | 失败分析怎么测 | 例 |
|---|---|---|---|---|
| **目标可见** | 这个构造本身承载某条规则的值或标签 | `affects` 非空 | 该构造所在页的点直接失败 | `negative_values` · `dense_marks_100plus` · `nonstandard_time_ticks` |
| **干扰可见** | 这个构造不承载任何规则，但改变解析器写出的表的形状 | `affects` 为空 → 归入「只提升真实性」 | 只能从控制组内的通过率差看出来 | `reference_line` · `annotation_callout` · `shaded_band` |

一条参考线永远不是抽查点，所以它**不可能**直接改变某条规则的判定。但 `pwc-semiconductor-and-beyond-2026-full-report_p17` 把两根柱之间的浅橙色连接带写成了第三个数据系列——干扰不改变规则，改变的是解析器输出里有几个系列、表头怎么写，于是**同一页上别的规则**寻址失败。

**对生成流水线的直接后果**：非数据图元从「真实性项」升为「提分项」，并且它需要的不是一个风格开关，而是一类新的标注目标——见 [A4](#a4--非数据图元与缺失)。

### 1.4 失败构成与上界

全部 568 页、4,864 个抽查点，896 个不通过。官方报告只分两种（值找不到 / 值找到但标签关联不上），下表拆成能对应到流水线改动的形状。

| 形态 | 个数 | 占失败 | 侧 | 归到哪条轴 |
|---|---:|---:|---|---|
| `label_unlinked` 数字对，但表里说不清这个数字是谁的 | 599 | 66.9% | 寻址 | A1 |
| `value_off` 数字读错了 | 199 | 22.2% | 读数 | A2 |
| `row_missing` 有个键压根没写进表 | 48 | 5.4% | 寻址 | A1 · A5 |
| `unit_mismatch` 数字写在了错的量级上 | 36 | 4.0% | 读数 | A3 |
| `value_absent` 键都在，就是没写这个数 | 14 | 1.6% | 读数 | A2 |
| `no_table` 整页没输出表 | 0 | 0.0% | — | — |

**寻址 72%（647 个）· 读数 28%（249 个）。** 568 页没有一页交白卷。

失联的 599 个点，把度量点名的那个键在解析器输出里再找一遍，791 次落位：

| 它在哪 | 次数 | 占比 |
|---|---:|---:|
| 就在同一张表里，只是不在这个数的行 / 列 / 表头上 | 627 | 79.3% |
| 在页面上，但只是一句普通正文 | 57 | 7.2% |
| 整页输出里找不到这个键 | 46 | 5.8% |
| 写在了另一张表里 | 38 | 4.8% |
| 是粗体 / 标题，但排在表后面 | 18 | 2.3% |
| 在表前面且是粗体 / 标题 | 5 | 0.6% |

**79% 的失联键就在同一张表里。** 解析器看见了这个键、也写下来了，只是把它放在了宽表的另一个位置。把 647 个寻址失败全部改对，按页平均从 **82.75% 升到 95.41%**——这是上界不是预测，它假设表换了形状而读数一个不变。

读错的 199 个点，相对误差中位 15%：≤5% 占 13% · ≤10% 占 36% · ≤20% 占 60% · ≤50% 占 82%。**放宽一倍容差救不回一半**，这一类多数不是估读偏差。

### 1.5 一句话结论

> 这个基准上剩下的失败主要是**无法说清一个数属于谁**，而不是读数精度不够。生成侧对应的能力是：**每个图元带着它的全地址键，并且每个键分量都能指回页面上画出它的那块像素**。这正是输出单位 `(键, 值, 区域)` 的完整形式——现在流水线只做到了 `值 → 区域`，没做 `键分量 → 区域`。

## 2 五条能力轴

五条轴按同一个模板写：吃掉哪些条目 · 证据 · 加什么能力 · **新产出的标注量** · 离开 ParseBench 还成不成立 · 成本 · 失败判据。

「新产出的标注量」这一栏是判断一条轴值不值得写进论文的标准：如果一条轴只是把现有字段调大调小，它是工程；如果它产出一个现有数据集没有的标注量，它才是数据集本身的贡献。

### A1 · 全地址键与键分量的落地

**一句话**：每个图元带一个全局唯一的键元组；键的每一个分量在页面上由哪个构造写出、写在哪块像素，同样记下来。

现在的记录里，`key` 是**面板内**的地址（`("Mercy General",)`），面板身份只是一个不带取值的标识符；而系列名与颜色的对应关系只有共享图例的多面板图才记（`legend[].applies_to_panels`）。两处都不够：面板名本身常常就是第三个键分量；系列名在真实报告页上有五种写法（图例色块、线端直标、面板标题条、轴标题、系列名自带单位），只有第一种被记录。

**要加的能力**

1. `key` 升为**图内全地址**：`(figure_id, panel_key, series, category, measure)`，`panel_key` 是被切维度的列名与取值，不是内部编号。一页多图时 `figure_id` 的可见形式（图号）也进键。
2. 记录里的 `legend[]` 推广为 **`key_carriers[]`**：每个键分量记一条「这个分量由页面上哪块像素写出」——图例色块、刻度标签、面板标题条、线端直标、两级刻度的外层、脚注上标所指的那一行。
3. 导出恒等地写成**长表**：一行一个值，这一行同时写全所有键分量。

**新产出的标注量**：`键分量 → 它的字面出处的区域`。现有工作 ground 的是结构元素（ChartREG++ 的 axes / ticks / legends 掩膜）或答案（ChartLens 的答案级归属），没有把「键的每一个分量指回它的字面出处」当作训练目标。它把 `图例绑定` 这一个目标推广成一整类目标。

|---|---|
| **吃掉的条目** | 失败改动 1（长表导出）· 2（面板名进键）· 3（颜色→系列）；`P2` `P3`；9 项组件缺口：`wrapped_category_labels` `footnote_marker` `color_encodes_extra_attribute` `two_level_x_ticks` `small_multiples_5plus` `inline_series_labels` `icon_category_axis` `total_row_below_axis` `stacked_and_grouped` |
| **证据** | 占全部失败的 72%；失联键 79% 就在同一张表里；2 键 83.3% → 3 键 69.0% → 4 键 55.9%；改对的上界 82.75% → 95.41% |
| **通用性** | 通用。输出单位是 `(键, 值, 区域)`，键必须是完整寻址元组，这条与任何具体度量无关。ParseBench 只要两个键，不构成把键裁到两个的理由——裁掉之后 provenance 链的 mark 端不再全局唯一 |

### A2 · 可读性是一个连续量

**一句话**：`readable` 从布尔改为 **ε——该图元在当前像素几何下能达到的相对精度**；稠密度从固定上限改为可控自变量。

现在的判据（`chart_types.md §4`）是三条分支：写了数值 → 容差 0；角度/颜色 → 不可读；长度/位置 → 「1% 的值折算成像素 ≥ 2」则可读、容差 1%。三个问题：**（a）** 容差是常数 1%，而基准的估读点容差中位 5%、四分位 [5%, 10%]；**（b）** 角度画法被预先排除，饼图在 5% 容差下本来可以进值目标；**（c）** 稠密度上限（`grouped_bar` \|P\|·\|S\| ≤ 24、`line` ≤ 6 条）算下来全部落在「图元 ≤ 60」这一档，也就是失败率最低的那一档。

**要加的能力**

1. 逐图元算 ε：`ε = (2 像素 × 每像素代表的值) / |值|`（长度 · 位置）；角度按同一式用可测角度下限算，不预先排除；颜色维持排除。写了数值标注的图元 ε = 0.01。
2. 值目标的容差由 ε 给出，取代常数 1%。
3. 抬高结构条件上限，或加一档高稠密配置，让图元个数覆盖 20 → 400+ 的全程。
4. 声明期多一个字段：**取值格**（整数 / 一位小数 / 百分点 / 归一到 100）。它是 01 的列声明里本来就知道的先验，能把读数直接吸附回合法取值。
5. 新图元形状与画法：阶梯线、区间连接线（哑铃）、叠在条上的刻度标记、数值标签外移带引线、无值轴。

**新产出的标注量**：**每个图元的可达读数精度 ε**。现有数据集只说「这个值是多少」，不说「这个值在这张图上最多能读到多准」。有了 ε，`稠密度 → 可达精度 → 模型表现` 这条链在同一份数据里可测，而 [§5.2](#52-相关不是因果) 说明这是相关性分析永远给不出的。ε 同时把 [05 §3](../../storyline/parsebench_chart/05_output.md#3-输出能自己验自己) 的可验证奖励从二值变成分级。

### A3 · 数值的呈现语义

**一句话**：一个图元表示的量，不是数据里的那个数，而是那个数经过一条**声明过的呈现链**——比例因子、单位、基期、符号约定、数字格式——之后印出来的样子。这条链现在一个字段都没有。

`.4` 与 `0.4` 差十倍；图题写 BILLIONS、标注写 `$101B` 而规则要 `101`；`2011 = 100` 的指数把值域整体搬走；负值让矩形图元从零线向两侧长。这四件事在现有三份规格里都没有落点：`unit` 只存在于 01 的 measure 声明里，一个字都不画出来；刻度格式化方式不是风格向量的维；零线没有被写过。

**要加的能力**

1. 记录里同时存 **`value`（规范值）** 与 **`printed`（印在图上的字面）**，中间是一条显式的呈现链：`scale`（×10⁶ / ×10⁹ / 百分比 / 归一化）· `unit` · `basis`（指数基期）· `sign_convention` · `format`（千分位 / 货币符号 / 括号负数 / 后缀 K,M,B）。
2. **单位承载位置**成为一个采样维：轴标题 / 副标题 / 图题 / 系列名 / 每个刻度 / 数值标签 / 不写。实测 149 / 192 页把单位只写在轴标题或图题里。
3. measure 的值域允许跨零，矩形图元支持从零线双向延伸；值轴起点、断轴标记进风格向量。
4. 新增第四项自检——**量纲往返**：从像素反算出的值，乘以声明的呈现链，必须等于印在图上的字面。

**新产出的标注量**：**规范值与印刷字面的配对，外加单位的承载位置**。现有 chart-to-table 数据集只留一个数，量级错误因此无法与读数错误分开统计。这条轴同时给出了一类现有工作没有的负样本：同一个 `value` 在两条不同呈现链下印成两个不同的字面，模型必须都答对。

| **证据** | `unit_mismatch` 36 个，两种写法各有整页实例；负值点通过率 67.4% vs 全体 81.6%；`negative_values` 控制组内 -8.8%（n=298）；`nonstandard_time_ticks` -9.4%（n=218）；单位只写在标题里的页面 78% |
| **通用性** | 通用，且是量级最严重的一类错误：数值错 15% 与量级错 1000% 在任何下游用途里的代价不同，而现有指标把两者算作同一种失败 |
| **成本** | 低。呈现链是声明字段与格式化函数；零线是绘制分支；量纲往返自检复用 `common/readback.py` |
| **ParseBench 预期** | 量级错的 4%，加上负值那一档的差 |
| **失败判据** | 加入呈现链标注后，模型输出的量级错误率不下降 |

### A4 · 非数据图元与缺失

**一句话**：图上画着但不是任何一个数据点的形状——参考线、批注框、阴影带、高亮、误差棒、`N/A` 占位——现在一个都画不出来，因此这份数据集从来没有教过「哪些形状不要转录」。

这是 [§1.3](#13-两种可见性) 那处改判的落点。现有八类训练目标全部是召回导向：每一个被画出来的形状都是一个 datum，模型多报一个不会被罚。而真实报告页上每一张图都混着不承载数据的图形，`pwc-…_p17` 就是把连接带读成了第三个系列。

**要加的能力**

1. 渲染器新增一类记录：**`decorations[]`**，每条带框、角色标签（`reference` / `annotation` / `band` / `highlight` / `connector` / `uncertainty` / `absence`）、以及**它是否携带一个不该被转录的数值**（目标线 y=17% 有值，但不是数据点）。
2. 新增训练目标：**非数据区域判别**——给定区域，回答它是不是一个 datum。以及配套的评测量：**多报率**（模型输出里落在 `decorations[]` 上的条目占比），现有八项没有任何一项测过这个。
3. 缺失作为一等状态：`N/A` 与空位替代图元，导出时是空格而不是 0。现在投影后每格必有值，缺失根本不进候选。
4. 误差棒：不确定性图元有上下端点，模型不能把上端点当成值。

**新产出的标注量**：**精确的负样本**。真实图表上没有人会去标「这条线不是数据」，成本高且判据主观；边画边记的生成器是唯一能零成本给出精确负样本的来源。这条轴把 grounded transcription 的误差面从「漏了多少」扩展到「多报了多少」——**这是这次合并里最强的单条新主张**。

| | |
|---|---|
| **吃掉的条目** | 失败改动 8（参考线、批注框、阴影带）；6 项组件缺口：`reference_line` `annotation_callout` `shaded_band` `highlighted_category` `error_bars` `missing_value_marker` |
| **证据** | 控制组内 `annotation_callout` -11.8%（n=164 · 33 页 · 23 文档）、`reference_line` -11.6%（n=297 · 43 页 · 22 文档），95% 区间不重叠；`pwc-…_p17` 的机制实例 |
| **通用性** | 通用，且比 ParseBench 更通用：任何以转录为输出的任务都同时需要召回与精确，而现有图表数据集只监督召回 |
| **成本** | 中。是 03 的新绘制形状 + 04 的新记录段 + 05 的新导出函数；不影响前两阶段 |
| **ParseBench 预期** | 干扰可见那一档，两项各约 -12%，改判前被记为「分数一格不动」 |
| **失败判据** | 加入负样本后，模型在带参考线 / 批注框的页面上的通过率与不带的页面之间的差不缩小 |

### A5 · 图是页面对象

**一句话**：图不是一张图像，是一个页面对象——它有身份（图号 + 标题 + 副标题 + 单位 + 位置）、有版面、有呈现自由度；身份同时是一页多图时的寻址根，也是 60% 的真实图上单位与口径的唯一载体。

现在 FigureSpec 有面板列表、版面、共享关系、关系、来源五个字段，没有标题。有的是 `caption`，画在图**下方**，而且八张图里只有三张意图图的 caption 有信息量，另外五张是复述坐标轴名的填充。

**要加的能力**

1. FigureSpec 加 `title`：图号 + 主标题 + 可选副标题 + 单位；渲染在绘图区**上方**，位置成为风格向量的四值取值（上方 / 侧栏 / 下方 / 无）。图号由页面合成器按页编号。
2. 标题按模板从声明合成（测度名 + 维度名 + 聚合 + 时间范围 + 单位），意图图的标题由 01 那一次调用多输出一行。**不增加 LLM 调用**。
3. `caption` 与 `title` 分家：`title` 每张图都有、进 L0 的 Text 元素；`caption` 只在意图图上产出，因此这个训练目标不再被无信息量的样本稀释。
4. 版面与呈现自由度补齐：图旁并排的正文栏、一页多图、横向条形、图例在绘图区内、值轴在右侧、轴标题位置、绘图区底色、线型区分系列。
5. 整页 markdown 导出：图表部分为长表，图标题写成表**前**的 markdown 标题。

**新产出的标注量**：**图身份把 L0 版面层与 L1 编码层连起来**。现在这两层只通过「图表是一个 Picture 框」相连；有了图身份，页面上的每个文本块可以指认它属于哪张图的哪个字段，这正是文档解析类基准要求的形态。

| | |
|---|---|
| **吃掉的条目** | 失败改动 9（标题与图号）· 10（页面文字量）；`P7` `P3` 的整页导出部分；9 项组件缺口：`side_text_bullets` `panel_background` `horizontal_bars` `axis_title_above_axis` `axis_title_below_plot` `legend_inside_plot` `right_side_y_axis` `dashed_line_series` `data_link_below_figure` |
| **证据** | 254 / 265 张图有标题（96%）· 149 张带图号（56%）· 88 张标题不止一行（33%）· 159 张单位写在标题里（60%）；位置四值：图上方 231 · 图下方 15 · 无标题 11 · 侧栏 8；一页多图 46 页 |
| **通用性** | 通用性高，**但不要当提分手段**：4,864 条规则里只有 14 条（0.14%）把图号当定位标签，值里出现量纲词 0 条。这一轴的价值在真实性与向文档解析类任务的迁移 |
| **成本** | 低。三件事都不需要新增 LLM 调用 |
| **ParseBench 预期** | 接近零。`row_missing` 里图号那一小部分（48 个中的少数） |
| **失败判据** | 与 ParseBench 分数无关，改为：生成页与真实报告页在「标题五字段的分布」上的差不缩小 |

### M · 每条轴自带消融行

这是方法轴，不产出能力，决定这份工作是数据集还是论文。

两份分析都只能给相关：页面分析的 `affects` 是按度量定义先验判的、难点是模型的预测；失败分析的组件价目表在控制组内只控住了最大的一个混淆项（数值是否印在图上），而组件之间高度共现——密集的图往往也有参考线、也不写数值。**「无标题的图通过率低二十个点」很可能是「无标题的图多半是密集的仪表盘版面」。**

要把相关变成因果只有一条路：**自己按单变量生成两组图、其余维度固定**。这正是生成流水线相对于任何真实语料的唯一结构性优势，也是把 A1–A5 从「工程清单」变成「可发表结论」的那一步。

| 轴 | 它变成哪一行消融 | 其余维度固定后测什么 |
|---|---|---|
| A1 | 键完整 / 键裁到两个 · 有 key_carriers / 无 | 寻址失败占比 |
| A2 | 稠密度阶梯（20 / 60 / 150 / 400 / 1000 图元）· ε 分档 | 读数误差随 ε 的曲线 |
| A3 | 同一 `value` 的多条呈现链 · 单位承载位置六选一 | 量级错误率 |
| A4 | 有非数据图元 / 无 · 有负样本目标 / 无 | 多报率 |
| A5 | 标题位置四值 · 一页一图 / 一页多图 | 上下文回退的贡献（此分片上信号弱，见 [§5.2](#52-相关不是因果)） |

现有消融表（[05 §7](../../storyline/parsebench_chart/05_output.md#7-消融)）八行里没有一行涉及标题、稠密度阶梯、呈现链或非数据图元。这五行是纯增量。

### 3.4 条件表本身要不要加行

类型缺口只有两处：`map`（3 张 / 3 文档）与模型报 `other` 时自拟的三种画法（`dumbbell range plot` · `three-marker range plot` · `vertical dumbbell range plot`）。

| 候选 | 判决 | 理由 |
|---|---|---|
| 区间连接线（哑铃 / 区间图） | **加**，作为一种新图元形状 | 4 页 / 2 文档偏少，但它是一种新形状（两点 + 连接段），落在 A2 的图元形状扩展里，边际成本低 |
| 阶梯线 | **加**，作为 `line` 的一种画法 | 同上，值的读法与直连折线不同 |
| 刻度标记系列 | **加**，作为一种新图元形状 | 19 页 / 7 文档；它与参考线形状相同而语义相反，正好是 A4 的对照 |
| 堆叠 + 分组同图 | **待定** | 0 页。两个维度分别吃掉 P 与 S，第三维无处可放，是键结构问题（A1）而非绘制问题 |
| `map` | **不加** | 地理投影不是六族中的任何一族，图元也不在五种形状里。3 文档，不为它改条件表 |

反过来，条件表里有、这份抽样里一张都没出现的三种（`box` `funnel` `heatmap`）**不删**——它们是为别的目标基准与类型广度消融留的能力，只说明按 ParseBench 调权重时不给它们配额。

### 4.1 排序

### 4.2 主张与失败判据

现有主张是一句：

> 带位置的转录可以由单个 VLM 完成——抽取每个值的同时给出读它的那块区域，在 chart-to-table 上持平专用 parser，同时达到版面感知流水线级别的视觉 grounding。

合并证据支持把它写成两段，第二段是这次分析新增的：

> **（i）** 在一个按页平均 82.75% 的强系统上，剩下失败的 72% 是寻址失败——模型读得出这个数，说不清这个数属于谁。因此带位置的转录的瓶颈在**寻址**，不在读数精度。
>
> **（ii）** 补上这一段所需的监督信号，恰好是只有「边画边记」的生成器能零成本产出的三类：**每个键分量的字面出处的区域**、**每个图元的可达读数精度**、**画在图上而不是数据的那些形状**。真实图表无法提供其中任何一类——它们要么需要逐分量对齐标注，要么需要主观判断。

**失败判据**（任何一条成立，对应的轴不成立）：

## 5 口径与边界

### 5.1 两次运行的口径

| | 页面分析 | 失败分析 |
|---|---|---|
| 输入 | 整页 PNG 150 dpi，一页一次结构化调用，effort `high`，`max_tokens` 12000，不裁剪、不接 OCR、不做第二轮 | 一个运行目录的 `<页面>.result.json` 与 `_evaluation_report.json`，不调模型，不重判分数 |
| 模型 | `claude-opus-5` | 被分析的系统是 PP-DocLayoutV3 lean + `Qwen3.8-27B-FP8`，200 dpi，verify_rounds=4，中位 91 秒 / 页 |
| 模型看不到什么 | 抽查点的**标签**、词表的「我们有没有」列、「影响哪一步」列、流水线结构 | — |
| 判分 | 值给了模型、标签没给，「要哪些键才能定位」是预测，规则来判分：1,635 个落位的值里对了 1,155 个（71%） | `passed` 全部取自官方报告。本地的「再找一遍」与官方在「值找没找到」上的一致率 99.84%（4,864 个点里分歧 8 个） |
| 结果 | 195 条交叉矛盾（最多的一类是模型预测的定位标签漏掉了规则实际用的标签，129 条）；514 个词表装不下的自拟名字 | 按页平均 82.75%，micro 81.58%，满分 296 页、零分 15 页 |

被分析的这一跑在同口径下（同 568 页、同 4,864 条规则、官方 metric）高于公开榜单上的所有方法（最高 LlamaParse Agentic 78.11%）。榜单行是否用同一版评测代码算出，无法核实，因此不写「新 SOTA」；能写的是——**这里分析的这些失败，是一个已经很强的系统剩下的失败**。

### 5.2 相关不是因果

第 1 节里凡是「组件 → 通过率」形态的行，全部是相关。理由三条：

1. **组件高度共现。** 密集的图往往也有参考线、也不写数值。控制组只控住了最大的一个混淆项——数值是否印在图上（它单独就值 19 个百分点：全部写出 94.5% · 部分 92.0% · 一个不写 75.9%）。
2. **「n」不等于证据量。** 一页最多十个抽查点，所以 n=60 有可能只来自六页、两份报告，那是一家出版方的习惯。`right_side_y_axis` -29.1% 正是这种情况（6 页 / 4 文档）。判据一律看文档分布，不看点数。
3. **反方向的行不要当杠杆读。** `axis_starts_above_zero` `data_link_below_figure` `figure_number_title` 这些通过率偏高的项，标记的是「这是一家会好好做图的出版方」。

**唯一能把相关变成因果的路径**是自己按单变量生成两组图、其余维度固定——这就是 [§2 M](#m--每条轴自带消融行) 的全部内容，也是这份合并报告认为该工作可发表的地方。

### 5.3 没有测的

- **只有一个模型、一条流水线。** 失败形态的分布是这一套系统的，不是「模型普遍如此」。第 1 节里凡是拿分布比例定优先级的（A1 的 72%、A2 的 28%），换一条流水线都要重跑。
- **Visual Grounding 一维没碰。** 这次运行只有 parse 产物，没有元素框的评测。而「单模型两项都强」正是本项目的主张，这一半目前没有实测。
- **192 页与全量不独立。** 组件价目表建立在同一批页面的随机子集上，只能提假设。
- **图表描述本身来自另一个模型**（`claude-opus-5`），它的错会原样传进所有以描述为自变量的行。可反向核对的一处见 [§1.2](#12-四处交叉) 第 4 行。
- **两种失败形态没能分出来**：「串系列」与「读了累计值」在全量上只找到 10 个候选，写下的数与真值都只差一格刻度，巧合能同样好地解释。这些点并入读数失败，不单列。**原因未定，不做推测。**
- **A4 的价没有独立控制。** `reference_line` 与 `annotation_callout` 的通过率差在控制组内成立，但两者本身共现（同一批「会做批注的出版方」）。A4 的因果只能由 [§2 M](#m--每条轴自带消融行) 那一行消融给出。
