# 合并结论

[reports/](../reports/INDEX.md)（基准页面长什么样，192 页）与 [failures/](../failures/ppdoclayoutv3_lean_qwen/INDEX.md)（一个强解析器失败在哪，568 页）合起来读，回答一个问题：**生成流水线该多出哪些能力**。原来的三份清单——39 项组件缺口、10 条失败改动、7 项 P 编号——互相重叠、粒度不齐，这里归成 **5 条能力轴 + 1 条方法轴**，每条带证据强度、成本、ParseBench 预期、离开 ParseBench 之后成不成立、以及失败判据。

**这一份自足。** 那两份的全部数字与全部证据都在这里重放一遍，读它不需要打开另外两份；反过来，**本目录不写另外两份下的任何文件**。

```
synthesis/
├── INDEX.md      中文正文，五节
├── INDEX.en.md   英文正文，逐节等价
├── view.html     中文图示版：五个标签页，每一项配原页与原始证据
├── view.en.html  英文图示版
└── assets/       view 读的降采样页面图（不入库，重跑即生成）
```

## view.html 里有什么

正文与表格来自 `INDEX*.md`，证据卡由数据现算，插在它论证的那一节下面。三种卡：

| 卡 | 出现在 | 一张卡里有什么 |
|---|---|---|
| **组件缺口** 39 张 | 第 2 节，按能力轴分组 | 出现页数与档位 · 影响判定哪一步 · 文档分布 · **模型当时写下的证据原文** · 送给模型的判据原话 · 现有规格为什么画不出来 · **失败分析测到的价** · 这一页所有图的类型/面板/系列/类目/图元/标题五字段 · 整页原图 |
| **失败页面** 10 张 | 第 1 节，按失败形态分组 | 它论证哪条轴 · 机制 · 该页通过几个点 · **解析器实际写的那张表**（失联的表头标红、值所在的格标绿）· 这一条规则要的值与键 · **写成长表就全过的那张表** · 判分程序的原话 · 整页原图 |
| **类型缺口** 2 张 | 第 3 节 | 图数与判决 · 条件表为什么没有它 · 这一页的图 · 整页原图 |

能力轴那一节，每条轴的卡片前还有一条缩略图带，指向这条轴的失败页面（跨标签页跳转）。

## 重建

```bash
python parsebench/tools/synthesis/build_view.py              # 两种语言 + assets
python parsebench/tools/synthesis/build_view.py zh           # 只重建中文
python parsebench/tools/synthesis/build_view.py --no-assets  # 页面图已在，跳过重采样
```

不调模型，不重判分数，重跑是零成本的。读三处，都是只读：`reports/pages/*/analysis.json`（页面分析的产物）· `data/stats/failures_<运行名>.json` 与 `data/runs/<运行名>/`（失败分析的输入）· `data/pages/*.png`。

代码在 [../tools/synthesis/](../tools/synthesis/)：`content` 放合并这一步新增的判断（哪一项归哪条轴）与两种语言的措辞 · `data` 读那两份分析 · `view` 渲染三种卡与 markdown · `build_view` 拼页面。**结论改在 `INDEX*.md`，`## ` 成一个标签页、`### ` 成该页目录的一项，编号 `1.3` / `1.4` / `3.4` / `A1`–`A5` 的小节自动接上对应的卡片组。**
