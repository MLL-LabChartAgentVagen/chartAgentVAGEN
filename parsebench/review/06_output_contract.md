# 输出契约 · 要出的三份报告

跑模型之前定死**产出什么**：三份报告、每份有哪几节、每节的表一行是什么、每列谁算。**这一份是唯一需要读的**；机读版 [`tools/contract/format.py`](../tools/contract/format.py) 是同一份内容，字段名一一对应。

---

## 0. 产物

| 产物 | 文件 | 内容 |
|---|---|---|
| **逐页报告** | `reports/pages/<page>.md`（20 份） | 一页一份：三家的答案与同一张图并排，供核对与裁决 |
| **报告 A · 样例分析** | `reports/sample.md` | 20 页 × 三家汇总：基准里有、storyline 没定义的东西 |
| **报告 B · 失败分析** | `reports/failures.md` | 一次运行的全部失败：形态由程序算，机制由三家归因 |
| **报告 C · overview** | `reports/overview.md` | 前两份合并：要给流水线加什么能力 |
| **图示版** | `reports/view.html` | 三份汇总的图示版，三个分区一一对应；每一项配一页实例与证据原文，**自足**——不打开 md 也能读完 |
| 原始答案 | `data/analysis/<model>/<page>.json` | 机读，一页一家一份。所有表由它算出 |

### 谁写哪一部分

| 谁 | 产出 |
|---|---|
| **三家模型** | 只产出 `data/analysis/<model>/<page>.json`，此外什么都不写 |
| **程序** | 全部计数、一致率、判分、失败统计，写成下面每一张表；这些数字进报告时原样引用 |
| **agent**（Claude Code） | 表之外的东西：逐页报告的裁决列与理由 · 三份汇总报告的结论散文 · `view.html`。**不产生任何数字**——每一句结论都要指回一张程序算出的表或一份逐页报告 |

这条分工就是上一轮那句「`model_claim` 的数字不单独印总数」的执行方式：模型说什么写在原始答案里，数字由程序算，话由 agent 写，三者互相可查。

**逐页报告是裁决面。** 契约要求冲突项由人看页面裁决，逐页报告就是那个地方：三家的分解、组件命中与证据原文、抽查点的判分并排在同一张图旁边，不用同时开三个 JSON 和一张 PNG。汇总表的实例列链到它。

**失败分析没有逐 case 文件**，与逐页报告的差别是规模不是原则：一次运行约 900 个失败，所以一个 case 是报告里的一行（带证据与 `case_id`），有冲突的集中列在裁决表里。

`view.html` 与三份 md 是同一份内容的两种形态，一次产出，不各写各的。

## 1. 逐页报告 `reports/pages/<page>.md`

| 节 | 表 | 一行是什么 | 列 |
|---|---|---|---|
| §1 这一页 | 页面 | 这一页 | 页名 · 文档 · 文档级 tags · 抽查点数 · 页面图像路径 |
| §2 三家怎么读这一页 | 图表分解 | (模型, 图序号) | 模型 · 图序号 · 类型 · 图元数 · 图号 · 标题位置 · 数值印不印 |
| | 组件命中 | 一个 key | key · 三家各自报没报 · 每家的证据原文 |
| | 词表外的自拟名字 | 一个名字 | 名字 · 哪家报的 · `affects` · 证据原文 |
| §3 抽查点 | 定位键 | 一个抽查点 | 值 · **规则的真实标签** · 三家各自预测的键 · 三家各自对错 · 这个点在失败运行里过没过 |
| §4 分歧与裁决 | 冲突 | 一个冲突项 | 量 · 三家各自的取值 · **人工裁决** · 裁决理由 |
| §5 原始答案 | 原始答案 | 一家模型 | 模型 · JSON 路径 |

§3 把三样东西放在同一行：模型的预测、`chart.jsonl` 的真实标签、这个点在失败运行里的实际结果。这一行是「模型的判断可不可信」的唯一直接证据，也是 §4 裁决时的依据。

### §1 要改什么

| 表 | 一行是什么 | 列 |
|---|---|---|
| 组件缺口 | 一个词表 key | key · 三家各自的页数 · 一致性 · `affects` · 文档分布 · 我们画不画得出 · 归入哪条 P · **对分数** · **对能力** · 一页实例（链到该页的逐页报告）与证据原文 |
| 词表外的观察 | 一个自拟名字（归并后） | 名字 · 哪几家报了 · 页数 · `affects` · 证据原文 |
| 类型缺口 | 一个图表类型 | 类型 · 三家各自的图数 · 一致性 · 条件表有没有这一族 |

### §2 基准长什么样

描述，没有待办。五张表，每张都是「取值 × 三家各自的数」，**并列不合并**：类型配比 · 数值印不印（三档）· 稠密度（五档）· 标题（图号有无、位置四值）· 卡在哪一步（另加一列：同一批页在失败运行里**实际**卡住的步）。

### §3 能不能信

| 表 | 一行是什么 | 列 |
|---|---|---|
| 调用口径 | 一家模型 | 模型 · effort · 图像 dpi · 调用次数 · 输入/输出 token · 用时 |
| 定位键预测的判分 | 一家模型 | 落位的值数 · 对的数 · 命中率（**唯一可核的量**） |
| 一致率 | 一个对齐量 | 三家一致 · 两家 · 一家 · 冲突 · 一致率 |
| 词表控制 | 一个模型的两次跑法 | 有词表报出的 key 数 · 无词表那次映回词表后重合的 key 数 · 重合率 |
| 交叉核对 | 一类矛盾 | 矛盾 · 三家各自的页数 |

## 5. 数字规则

### 三层可信度，报告里逐项标注

| 层 | 谁决定 | 例 |
|---|---|---|
| `rule_checkable` | `chart.jsonl` 的标注 | 规则用几个标签、定位键预测的对错、通过率 |
| `program_measured` | 程序从页面 / PDF 文字层 / 运行输出算 | 组件频次、页面文字量、一致率 |
| `model_claim` | 模型对页面的描述 | 类型判定、图元数、组件命中、标题、机制 |

`model_claim` 的数字**不单独印总数**，同一行必须有一致性那一列。上一轮全部结论落在这一层且只有一个观察者，这正是重跑的理由。

### 必须程序算的（`PROGRAM_ONLY`）

规则一句话：**能不调模型算出来的就不许问模型**。七项：组件出现在几页几份文档 · 通过率与 95% 区间 · 失败形态计数 · 规则实际用了几个标签 · 定位键预测的对错 · 页面文字量 · 三家的一致性与一致率。

### 三家怎么对齐

**逐页逐量对齐，不比报告总数**——两份总数相同的报告可以在每一页上都不一致。一个量进这张表的条件只有一条：**有一个决定消费它**。

| 量 | 相等的判据 | 谁消费它 |
|---|---|---|
| 组件命中集合 | 同一页同一个 key 都被报出 | 报告 A §1 的每一行 |
| 图表类型判定 | `type` 相同（`other` 还要 `type_other` 归一化后相同） | 类型配比 → P4 族权重向量 |
| 数值印不印 | `values_printed` 三值相同 | P6；也是失败分析最大的控制变量 |
| 稠密度档 | `marks` 落在同一档（≤20 / 21–60 / 61–150 / 151–400 / >400） | P5 的稠密度上限 |
| 标题 | 图号有无相同、位置四值相同（**标题正文不比**） | P7 的图号与位置两维 |
| 卡在哪一步 | `hardest_step` 相同 | 与失败运行实测的步对照，校准模型的判断 |
| 定位键预测 | 与规则的真实标签逐条判对错 | **唯一可核**，校准上面六条；同时是 P2 的证据 |

失败报告另有一条：**失败机制**（`mechanism` 相同，`affects` 不同记为冲突）。

**刻意不对齐的**（`NOT_ALIGNED`，写下来是为了下一轮不反射性地加回去）：改进意见（由组件命中派生，对齐等于数两遍，三家的原话附在报告里给人读）· 抽查点落到哪张图（与定位键预测同一条链）· 标题正文与系列名（比的是抄写差异，不是读图差异）。

| 类 | 定义 | 怎么用 |
|---|---|---|
| 三家一致 | 都报了，且按判据相等 | 直接进改造清单 |
| 两家 | 两家相同，第三家沉默（没报，不是报了别的） | 进清单，标注为两家 |
| 一家 | 只有一家报了 | 单列，不进清单 |
| 冲突 | 两家以上报了但取值不同，含 `affects` 不同 | 单列，人工看页面裁决；裁决写进报告，不改模型原答案 |

一致率 = 三家一致 / 至少一家报过的项，按页算再平均。**一致不是要最大化的分数**：它的用处只有一个，把「基准的性质」与「某一家模型的读法」分开，只有前者进改造清单。

## 6. 模型返回什么

报告的每一列都要有来源，来源就是这两份 schema（`format.PAGE_SCHEMA` / `FAILURE_SCHEMA`）。

### 两条先于字段的约束（[TODO §T0](../TODO.md)）

| 原则 | 在契约里的形式 |
|---|---|
| 分析落在基准自己的定义上 | 每个观察项带 `affects`——能改变[四步判定](02_chart_metric.md)的哪一步。**空数组是正常答案**，意思是度量看不见它 |
| 结论双栏，不压成一列 | 每条意见两个字段：`score_effect` / `capability_effect`，另加 `new_ablation_row`。**只削减现有能力的改动不许写进 `capability_effect`**，要改写成「加一个可配置维度 + 保留原默认」 |

### 每页返回什么

九个顶层字段：`page_note` · `figures[]` · `components[]` · `new_components[]` · `spot_checks[]` · `hardest_step` · `difficulty_notes` · `unreadable[]` · `suggestions[]`。

`figures[]` 逐图记：`heading`（图号 / 主标题 / 副标题 / 单位 / 位置）· `type`（19 型）· `type_other`（`other` 必须命名）· `orientation` · `panels` / `panel_names` · `series` / `series_names` · `categories` / `category_names` · `marks` · `values_printed` · `value_axis_ticks` · `source_line`。

三个形状不改：

- **`heading` 拆五个字段**，不是一个 caption 字符串——图号、副标题、单位、位置是四个各自独立的生成问题；按图记不按页记。
- **`components[].evidence` 必填**：`the y axis reads 0, 25, ... 200 with no unit` 是证据，「单位写在标题里」是复述 key。没有证据的 key 是主张，主张不能相加成频次表。
- **`spot_checks[].addressing_keys` 是唯一被打分的字段**——值送进 prompt、标签不送，所以它是预测，`chart.jsonl` 的 `labels` 判分。

长度上限写在字段描述里，不做程序截断：`evidence` ≤20 词 · `difficulty_notes` ≤60 词 · `score_effect` / `capability_effect` ≤30 词 · `category_names` ≤12 项。

### 归因返回什么

| 谁 | 产出 |
|---|---|
| 官方评测报告 | `passed`。不重判，一次也不 |
| 程序 | 失败形态（六类）、失联键的去向、全部计数 |
| 模型 | `mechanism`（13 项闭集）· `evidence`（解析器输出里的原文）· `affects` · `drawn_differently` · `maps_to` · `confidence` |

每个机制自带它属于四步的哪一步，**映不回四步的归因写不出来**；`other` 是唯一例外，必须配 `mechanism_note`。

### 组件词表：一份继承来的假设，不是定义

`components[].key` 的取值域是 [`vocabulary.py`](../tools/contract/vocabulary.py) 的 65 个 key。**它是上一轮长出来的**（29 → 56 → 69 → 65），由**一个模型**在 192 页上的自拟名字按词干归并而成，不是从基准定义推出来的；每个 key 的 `affects` 也是按度量定义作出的**指派**，不是测量。

**仍然用它**，理由只有一条：没有闭集，20 页上的自由命名相加不起来——上一轮 289 个自拟名字对应 26 个概念，命名发散约 11:1，差异表会退化成命名差异表。

**代价写在明处**：三家拿同一份 65 项清单（prompt 里约 2,240 token），一致率里有一部分是「照着清单勾」而不是「看到同样的东西」。所以配两条控制（`CONTROLS`），两条都不是可选项：

| 控制 | 怎么做 | 读出什么 |
|---|---|---|
| 词表外残差 | 数每家 `new_components` 的条数与占比 | 词表覆盖不了的部分有多大 |
| 无词表对照 | 三家取一家，同一批页再跑一次、prompt 不给词表，程序把自由名字映回词表 | 重合率低说明枚举在造一致，一致率按此折价。代价 20 次调用 |

**不按上一轮的频次裁剪词表**：裁掉低频 key 等于把上一轮的频次固化进这一轮，正是要避免的事。
