# 输出契约

跑模型之前定死**产出什么**：谁写哪份文件、每张表一行是什么、每列谁算。**这一份是唯一需要读的**；机读版 [`tools/contract/format.py`](../tools/contract/format.py) 是同一份内容，字段名一一对应。

---

## 1. 谁写什么

| 文件 | 谁写 | 内容 |
|---|---|---|
| `reports/pages/<page>.md`（一页一份，本轮 100 份） | 模型 + 程序 | 一页一份：三家对这一页的报告并排 + 抽查点判分 + 冲突表。**裁决面** |
| `reports/<model>.md`（3 份） | **模型** | 这一家自己的两份 overview（样例 / 失败）与它引用数字的对账 |
| `reports/compare.md` | **程序** | 全部数字：汇总表、一致率、判分、自报 vs 实测。**没有结论** |
| `reports/INDEX.md` | **agent** | 读完全部之后的那一份：裁决、改造清单、可信度。**唯一有结论的** |
| `reports/view.html` | **agent** | `INDEX.md` 的图示版，每项配一页实例与证据原文，自足 |
| `data/analysis/<model>/…json` · `verdicts.json` | 模型 · agent | 原始答案与裁决。所有文件由它们渲染 |

一页只有一个文件，三家并排在里面——按模型拆成三份就要开三个文件才能比一页。

**每家跑三种调用，一共 22 次：**

| 做什么 | 次数 | schema |
|---|---|---|
| 页面分析 | 20 | `PAGE_SCHEMA`，其中 `report_md` 就是这一页的报告 |
| 样例 overview | 1 | `OVERVIEW_SCHEMA`，输入是它自己那 100 份答案 + 程序为它算好的表 |
| 失败批次 | 1 | `FAILURE_SCHEMA`，抽样的 case 一次全给，返回逐条归因 + 这一家的失败 overview |

三家共 66 次，另加一家 20 次[无词表对照](#4-组件词表一份继承来的假设)。

**失败为什么不逐 case 调用**：逐 case 的**输出**必须留（三家只能逐条比），但逐 case 的**调用**买不到什么——case 是文本、一次装得下，而刚读完 50 条的那个模型正是该写 overview 的那个。所以归因与 overview 同一次出。case 按 `CASE_SAMPLE` 抽：**每形态 10 条**（不足 10 的全取，约 50 条）。等量抽不按比例抽，因为稀有形态才是未知机制可能藏身的地方；代价是机制计数只在**形态内部**成立，折算到全运行要用程序在全部失败上算的形态计数加权。

**数字只有一个来源。** 模型报告里的数字是 `model_claim`，旁边永远有程序实测那一列；agent 不产生任何数字。`numbers_cited` 让这条可查：模型正文里用的每个数字回填一条，程序逐条对账，**对不上记录不改写**。

## 2. 每份文件有哪几节

### `reports/pages/<page>.md`

| 节 | 表 | 一行是什么 | 列 |
|---|---|---|---|
| §1 三家怎么读这一页 | 页面 | 这一页 | 页名 · 文档 · tags · 抽查点数 · 页面图像路径 |
| | 报告 | 一家模型 | 模型 · `report_md`（≤150 词，原样印出） |
| | 图表分解 | (模型, 图序号) | 类型 · 图元数 · 图号 · 标题位置 · 数值印不印 |
| | 组件命中 | 一个 key | key · 三家各自报没报 · 每家的证据原文 |
| | 词表外的自拟名字 | 一个名字 | 名字 · 哪家报的 · `affects` · 证据原文 |
| §2 抽查点 | 定位键 | 一个抽查点 | 值 · **规则的真实标签** · 三家各自预测的键 · 对错 · 这个点在失败运行里过没过 |
| §3 分歧与裁决 | 冲突 | 一个冲突项 | 量 · 三家各自的取值 · **人工裁决** · 理由 |

§2 把模型的预测、`chart.jsonl` 的真实标签、这个点在失败运行里的实际结果放在同一行——这是「模型的判断可不可信」的唯一直接证据，也是 §3 裁决的依据。

### `reports/<model>.md`

§1 样例 overview（`headline` · 它的排序 · 正文 · `limits`）· §2 失败 overview（结构相同）· §3 它引用的数字逐条对账。

### `reports/compare.md`

§1 缺口表（组件 / 类型：三家各自的数 · 一致性 · `affects` · 文档分布 · 我们画不画得出 · 归入哪条 P · 实例链）· §2 基准长什么样（类型配比 / 数值印不印 / 稠密度档 / 标题 / 卡在哪一步，每格三家并列不合并）· §3 失败（形态与失联键去向 · 单变量通过率与 95% 区间 · 机制表）· §4 能不能信（调用口径 · 判分 · 一致率 · 自报 vs 实测 · 词表控制）。

### `reports/INDEX.md` + `view.html`

§1 要改什么（改造清单）· §2 失败说明什么（机制 → 能力）· §3 与 P1–P7 的对齐 · §4 没进清单的与还没裁决的 · §5 能不能信。`view.html` 是前三节的图示版。

## 3. 数字规则

**三层可信度**，报告里逐项标注：`rule_checkable`（`chart.jsonl` 的标注：规则用几个标签、定位键预测的对错、通过率）· `program_measured`（程序从页面 / PDF 文字层 / 运行输出算：组件频次、一致率、对账）· `model_claim`（模型的描述：类型判定、图元数、组件命中、标题、机制）。**`model_claim` 的数字不单独印总数**，同一行必须有一致性那一列。

**必须程序算的**（`PROGRAM_ONLY`，规则是「能不调模型算出来的就不许问模型」）：组件出现在几页几份文档 · 通过率与 95% 区间 · 失败形态计数 · 规则实际用了几个标签 · 定位键预测的对错 · 页面文字量 · 三家的一致性与一致率 · 模型自报的数字对不对。

**三家怎么对齐**：逐页逐量比，不比报告总数。一个量进这张表的条件只有一条——**有一个决定消费它**。

| 量 | 相等的判据 | 谁消费它 |
|---|---|---|
| 组件命中集合 | 同一页同一个 key 都被报出 | 改造清单的每一行 |
| 图表类型判定 | `type` 相同（`other` 还要 `type_other` 归一化后相同） | 类型配比 → P4 族权重向量 |
| 数值印不印 | `values_printed` 三值相同 | P6；也是失败分析最大的控制变量 |
| 稠密度档 | `marks` 落在同一档（≤20 / 21–60 / 61–150 / 151–400 / >400） | P5 的稠密度上限 |
| 标题 | 图号有无与位置四值相同（**标题正文不比**） | P7 的图号与位置两维 |
| 卡在哪一步 | `hardest_step` 相同 | 与失败运行实测的步对照 |
| 模型自报 vs 程序实测 | `numbers_cited` 与程序同一张表相等 | 报告可不可信的直接检验 |
| 排序 | 三家 `ranked_items` 前三名归一化后集合相同 | 改造清单的次序 |
| 定位键预测 | 与规则的真实标签逐条判对错 | **唯一可核**，校准上面几条；P2 的证据 |
| 失败机制 | `mechanism` 相同 | 失败一节与 `INDEX.md` §2 |

**刻意不对齐的**（`NOT_ALIGNED`，写下来是为了下一轮不反射性地加回去）：标题正文、系列名与类目名（比的是抄写差异不是读图差异）· 抽查点落到哪张图（与定位键预测同一条链）。

| 类 | 定义 | 怎么用 |
|---|---|---|
| 三家一致 | 都报了，且按判据相等 | 直接进改造清单 |
| 两家 | 两家相同，第三家沉默（没报，不是报了别的） | 进清单，标注为两家 |
| 一家 | 只有一家报了 | 单列，不进清单 |
| 冲突 | 两家以上报了但取值不同，含 `affects` 不同 | 单列，人工看页面裁决 |

一致率 = 三家一致 / 至少一家报过的项，按页算再平均。**一致不是要最大化的分数**：它的用处只有一个，把「基准的性质」与「某一家模型的读法」分开，只有前者进改造清单。

## 4. 模型返回什么

两条先于字段的约束（[TODO §T0](../TODO.md)）：每个观察项带 **`affects`**（能改变[四步判定](02_chart_metric.md)的哪一步，**空数组是正常答案**，意思是度量看不见它）；每条意见分 **`score_effect` / `capability_effect`** 两栏，另加 `new_ablation_row`，schema 层面就不给合并的机会。**只削减现有能力的改动不许写进 `capability_effect`**，要改写成「加一个可配置维度 + 保留原默认」。

**每页**（`PAGE_SCHEMA`，六个字段）：`report_md`（≤150 词，这一页的报告正文）· `figures[]` · `components[]` · `new_components[]` · `spot_checks[]` · `hardest_step`。
逐图记：`heading`（图号 / 主标题 / 副标题 / 单位 / 位置）· `type`（20 型，含 `unreadable`）· `type_other`（`other` 必须命名）· `panels` / `series` / `categories` / `marks` · `values_printed`。

**页答案里没有意见**。改进意见只在 overview 里出现——那时模型已经看过自己的 20 页和程序算出的计数，排序才有依据。

**overview**（`OVERVIEW_SCHEMA`，五个字段）：`headline`（≤40 词，需要「但是」就说明是两个结论）· `ranked_items[]`（what · why · 证据 · `affects` · 两栏结论 · `new_ablation_row` · `maps_to`）· `numbers_cited[]`（claim · value · source）· `report_md`（≤600 词）· `limits`（≤60 词）。

**失败批次**（`FAILURE_SCHEMA`）：`attributions[]`（case_id · `mechanism` 13 项闭集 · `mechanism_note` · `evidence`）+ 上面五个 overview 字段。`passed` 不进 schema，形态由程序给，`affects` 由程序从机制推出——**映不回四步的归因写不出来**，`other` 是唯一例外且必须配注。

三个形状不改：`heading` 拆五个字段（图号、副标题、单位、位置是四个独立的生成问题，按图记不按页记）· `components[].evidence` 必填（`the y axis reads 0, 25, ... 200 with no unit` 是证据，「单位写在标题里」是复述 key）· `spot_checks[].addressing_keys` 是唯一被打分的字段（值送进 prompt、标签不送，所以是预测，`chart.jsonl` 判分）。

### 组件词表：一份继承来的假设

`components[].key` 的取值域是 [`vocabulary.py`](../tools/contract/vocabulary.py) 的 65 个 key。**它是上一轮长出来的**（29 → 56 → 69 → 65），由**一个模型**在 192 页上的自拟名字归并而成，不是从基准定义推出来的；每个 key 的 `affects` 也是按度量定义作出的**指派**，不是测量。

仍然用它，理由只有一条：没有闭集，20 页上的自由命名相加不起来（上一轮 289 个自拟名字对应 26 个概念）。代价是三家拿同一份清单（prompt 里约 2,240 token），一致率里有一部分是「照着清单勾」。因此配两条**不可选**的控制：**词表外残差**（数每家 `new_components` 的条数与占比）· **无词表对照**（三家取一家，同 20 页再跑一次、prompt 不给词表，映回词表比重合率；低就说明枚举在造一致，一致率按此折价）。

还有第三条控制与词表无关但同样不可选：**自身重跑**——一家原样再跑一次同一批页，同一家两次的一致率就是**本底噪声**，跨家的分歧要减掉它才算真的分歧。实测同一模型两次跑同一页，`hardest_step` 与 `marks` 都会变。**不按上一轮频次裁剪词表**——裁掉低频 key 等于把上一轮的频次固化进这一轮。
