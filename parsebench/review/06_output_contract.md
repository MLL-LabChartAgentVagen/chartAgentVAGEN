# 输出契约

三家模型跑同一批页面，只有落在同一个契约上才能逐项比较。**这一份是唯一需要读的**；机读版是 [`tools/contract/format.py`](../tools/contract/format.py) 一个文件，字段名一一对应，另有 [`vocabulary.py`](../tools/contract/vocabulary.py) 的 65 项组件词表（数据表，不用通读）。

跑之前定死四样：每页返回什么 · 归因返回什么 · 报告有哪几节、哪些数字必须程序算 · 三家按什么对齐。

---

## 0. 两条先于字段的约束

按 [TODO §T0](../TODO.md) 写，它们决定下面每个字段的形状：

| 原则 | 在契约里的形式 |
|---|---|
| 分析落在基准自己的定义上 | 每个观察项带 `affects`——能改变[四步判定](02_chart_metric.md)的哪一步。**空数组是正常答案**，意思是度量看不见它 |
| 结论双栏，不压成一列 | 每条意见两个字段：`score_effect`（对分数）与 `capability_effect`（对流水线能力），另加 `new_ablation_row` |

`capability_effect` 带一条硬约束：**只削减现有能力的改动不许写在这里**，要改写成「加一个可配置维度 + 保留原默认」。

词表 65 个 key 的 `affects` 已按度量定义定死（看任何一页之前就有答案），**不问模型**；只有模型自己提出的新组件与新意见要自己声明。

## 1. 分析 schema：每页返回什么

`format.PAGE_SCHEMA`，九个顶层字段。

| 字段 | 内容 | 取值域 |
|---|---|---|
| `page_note` | 这一页上有什么，一句中文 | 自由文本 |
| `figures[]` | 逐图的结构描述 | 见下 |
| `components[]` | 页面上出现的词表 key，每项带证据 | 65 项枚举 |
| `new_components[]` | 词表装不下的构造 | 自拟 key + `affects` |
| `spot_checks[]` | 逐个抽查点：落在哪张图、哪个图元、要哪些键定位 | 顺序与 prompt 给的值一一对应 |
| `hardest_step` | 卡在四步的哪一步 | `1 \| 2 \| 3 \| 4` |
| `difficulty_notes` | 为什么是那一步，要用这一页的数字论证 | 中文 ≤60 词 |
| `unreadable[]` | 不是图、或读不出任何东西的条目 | 中文 ≤20 词 |
| `suggestions[]` | 该加什么能力 | 双栏结论 + `maps_to` P1–P7 |

**`figures[]`**：`id` · `heading`（图号 / 主标题 / 副标题 / 单位 / 位置）· `type`（19 型枚举）· `type_other`（`other` 必须命名）· `orientation` · `panels` / `panel_names` · `series` / `series_names` · `categories` / `category_names` · `marks` · `values_printed`（`all \| some \| none`）· `value_axis_ticks` · `source_line`。

三个形状是上一轮换来的，不改：

- **`heading` 拆五个字段，不是一个 caption 字符串**——图号、副标题、单位、位置是四个各自独立的生成问题；且按图记不按页记，否则一页两张图会把一个标题数两次。
- **`components[].evidence` 必填**，写页面上的原话或画了什么。没有证据的 key 是主张，主张不能相加成频次表：`the y axis reads 0, 25, ... 200 with no unit` 是证据，「单位写在标题里」是复述 key。
- **`spot_checks[].addressing_keys` 是唯一被打分的字段**——抽查点的值送进 prompt、标签不送，所以它是预测，`chart.jsonl` 的 `labels` 来判分。

**长度上限**（写在字段描述里，不做程序截断）：`evidence` ≤20 词 · `difficulty_notes` ≤60 词 · `why_it_matters` / `score_effect` / `capability_effect` ≤30 词 · `category_names` ≤12 项。

## 2. 归因 schema：失败样本那一份

`format.FAILURE_SCHEMA`。分工是死的：

| 谁 | 产出 |
|---|---|
| 官方评测报告 | `passed`。不重判，一次也不 |
| 程序 | 失败形态（六类 `FORMS`）、失联键的去向（`LABEL_HOMES`）、全部计数 |
| 模型 | `mechanism`（13 项闭集）· `evidence`（解析器输出里的原文）· `affects` · `drawn_differently` · `maps_to` · `confidence` |

机制是闭集，理由与组件词表相同：三家用三句话描述同一个失败，读出来是三处分歧。每个机制自带它属于四步的哪一步，**映不回四步的归因写不出来**——`other` 是唯一例外，必须配 `mechanism_note`。

## 3. 报告结构与数字来源

`format.PAGE_REPORT` / `FAILURE_REPORT` 定义每节的问题与行。

**样例分析三节**：① 要改什么（一项一行：key · 三家各自的页数 · 一致性 · `affects` · 文档分布 · 归入哪条 P · 双栏结论）② 基准长什么样（描述，无待办；每一格三家并列，不合并）③ 能不能信（调用口径 · 三家各自的判分 · 交叉核对 · 差异表）。

**失败分析四节**：① 失败长什么样 ② 什么样的图更容易失败 ③ 翻成流水线改动 ④ 能不能信。第 2 节全部是相关不是因果，这句话进第 4 节，不进第 2 节的表。

**必须程序算的**（`format.PROGRAM_ONLY`，规则是「能不调模型算出来的就不许问模型」）：每个组件出现在几页几份文档 · 通过率与 95% 区间 · 失败形态计数 · 规则实际用了几个标签 · 定位键预测的对错 · 页面文字量 · 三家的一致性。

**三层可信度**（`format.PROVENANCE`），报告里逐项标注：

| 层 | 谁决定 | 例 |
|---|---|---|
| `rule_checkable` | `chart.jsonl` 的标注 | 规则用几个标签、定位键预测的对错 |
| `program_measured` | 程序从页面 / PDF 文字层 / 运行输出算 | 通过率、页面文字量、组件频次 |
| `model_claim` | 模型对页面的描述 | 类型判定、图元数、组件命中、标题、难点 |

`model_claim` 的数字不单独印总数，旁边必须有一致性那一列。上一轮全部结论落在这一层且只有一个观察者，这正是重跑的理由。

## 4. 比较口径：三家按什么对齐

`format.QUANTITIES`。**逐页逐量对齐，不比报告总数**——两份总数相同的报告可以在每一页上都不一致。

十个量：图表类型判定 · 图数与图元数（按稠密度档）· 组件命中集合 · 标题五字段 · 数值印不印 · 卡在哪一步 · 抽查点落到哪张图 · 定位键预测 · 改进意见 · 失败归因。每个量写清「一个可比单位是什么」与「两家什么时候算说了同一件事」，例如类型要 `type` 相同（`other` 还要 `type_other` 归一化后相同），意见要落在同一条 P 且指向同一个 key、**`affects` 不同记为冲突**。定位键预测是唯一 `rule_checkable` 的一项，它问「谁对」不是「谁和谁一致」。

| 类 | 定义 | 怎么用 |
|---|---|---|
| 三家一致 | 都报了，且按判据相等 | 直接进改造清单 |
| 两家 | 两家相同，第三家沉默（没报，不是报了别的） | 进清单，标注为两家 |
| 一家 | 只有一家报了 | 单列，不进清单 |
| 冲突 | 两家以上报了但取值不同，含 `affects` 不同 | 单列，人工看页面裁决；裁决写进报告，不改模型原答案 |

一致率 = 三家一致的项 / 至少一家报过的项，按页算再平均，与基准自己的按页平均口径一致。

**一致不是要最大化的分数**。它的用处只有一个：把「基准的性质」与「某一家模型的读法」分开，只有前者进改造清单。
