# 样例分析怎么做

设计文档。要回答的是：**这一页用了哪些组件，其中哪些我们的流水线画不出来**——共享图例、双 y 轴、参考线、两级刻度标签这一类。不是抽取数值（数值已有真值）。

---

## 1. 一次调用，整页原图，不做任何预处理

```
page.png（整页 150 dpi） ──► VLM 一次结构化输出 ──► reports/<stem>/
                                                        │
                                    与 chart.jsonl 的标签交叉核对（程序）
```

没有定位步骤，没有裁剪，没有 OCR，没有工具，没有多轮。

### 为什么这样就够：这份组件词表本身就是这么得出来的

[组件词表](../tools/analysis/vocabulary.py) 最初那 29 项，是**在 120–130 dpi 的整页渲染上看出来的**，一张图都没有裁过。参考线带独立图例项、两级 x 轴标签、旋转刻度、堆叠与分组同图、零线居中的分叉条、窄分段的数值标签移到外部带引线——全部在整页上可辨。

**词表现在 65 项，后 36 项是它自己长出来的。** 每一轮跑完，模型在词表之外自拟的名字里，出现 ≥3 页的并入词表，下一轮起有自己的计数。第一轮 96 页养出 26 项（289 个自拟名字，按词干归并近义名之后），第二轮 192 页再养出 13 项，同一轮又删掉 4 项——图题那四个 key 在重复记录 `heading` 五个字段已经记的事。扩词表与扩样因此是一件事：新 key 让下一轮的 `new_components` 残差更干净，残差再养出下一批 key。

要检测的组件都是**大尺度结构特征**，不是细小文字。整页足够。

### 裁剪能带来多少，以及为什么不值

按 `2023-05-sigma-01-english_p24` 的 Figure 17 实算（图占页宽 88%、页高 32%）：

| 路径 | 图表在送达图像里占多大 |
|---|---|
| 整页 | 0.62C × 0.32C |
| 裁剪后重渲染 | 1.00C × 0.52C |

`C` 是服务端对长边的缩放上限，两条路径都会触到它，所以比值与 `C` 无关：**线性 1.6 倍，像素 2.6 倍**。

代价是一次额外调用、一个会失败的定位步骤，换 1.6 倍——对大尺度结构判断不划算。

### 为什么不接 OCR

**567/568 页有 PDF 文字层**（`pdftotext` 实测，只有 1 页少于 50 个字符）。需要页面文字时直接取，精确且免费，OCR 只会在本来没有误差的地方引入误差。而且要的不是文字转录，是结构分类。

### 为什么不做 agent

没有需要验证的东西——数值已有 4,864 条真值，不存在"抽出来再设法确认"的循环，而那正是 agent 的主要用途。另外，模型自主决定的多轮调用会让 llmkit 的缓存键不稳定，同一份分析跑两次得到两个结果，192 份报告就无法横向汇总。

### 两条回退

都是异常处理，不是流程的一环。

**看不清。** 结构化输出里留一个 `unreadable` 字段。模型在某一页说"看不清"时，**只对这几页**按框重渲染再问一次。两轮跑完，这条一次都没有触发：`unreadable` 非空的 9 / 192 页，写的全是"这个条目根本不是图"（装饰色块、注释文字块、占位），不是"这张图看不清"。整页 150 dpi 对组件判断够用，这一条至此是实测结论，不再是设计假设。

**空答案。** 这个分片的每一页都带抽查点，所以每一页都有图；`figures` 为空说明这次回复退化了，不是这一页的性质。驱动检出后，在同一份 prompt 后面加一句"这页有图，再看一遍"重问一次，只此一次。192 页里触发了 3 次（约 1.5%；典型形态是首次回复只有一百多个输出 token、`difficulty_notes` 写着"占位"）。重问走的是不同的 prompt，因而是另一个缓存键，重跑仍然确定。

所以 192 页共 195 次调用。

## 3. 分析多少页：192，随机

`tools/analysis/sample_pages.py`，**均匀随机**抽样，种子 20260817，结果在 `data/stats/analysis_sample.json`。实得 192 页 / 70 份文档 / 覆盖 1,658 条抽查点，占总体 568 页的 34%。

分三次抽到位：48 → 96 → 192，每次 `--extend` 保留已抽中的页，其余从剩下的均匀抽。均匀样本加上其补集的均匀样本仍是并集的均匀样本，无偏性不变。

**为什么扩到 192**：96 页时，真值 2% 的组件期望出现 2 次，与「模型一次性的自拟命名」无法区分——289 个自拟名字里 265 个只出现 1 次。翻倍之后真值 2% 的期望变 4 次、跨过「≥3 页并入词表」的门槛，纯噪声仍停在 1 次。改造顺序的头名不因此改变（`figure_number_title` 离档位线太远），中低档边界上的三项会变稳。

不做分层、不设每文档上限。理由是汇总表要的是**频次**——[reports/INDEX.md](../reports/INDEX.md) 按「我们无」的出现频次排序，那张表直接就是改造顺序。均匀随机的频次是总体频次的无偏估计；任何筛选策略都会让这张表失去这个性质。

抽中的分组构成只报告、不干预：

| 分组 | 抽中 / 总体 |
|---|---|
| `untagged`（数值全写出） | 63 / 188 |
| `need_estimate` | 111 / 309 |
| `3d_chart+need_estimate` | 16 / 68 |
| `3d_chart` | 2 / 3 |

要覆盖更多，加大 `--size`。llmkit 按 `(prompt, image, model)` 缓存，扩样是增量的，已跑过的页不会重跑。

## 4. 组件分析与全量评测是两件事

「568 页跑一遍 parse 并打分」不在这一阶段。它和组件分析回答的不是一个问题：

| | 回答什么 | 什么时候需要 |
|---|---|---|
| 样例分析（192 页） | 我们缺哪些组件、难点在哪 | **现在**，它决定流水线改什么 |
| 全量 parse + 打分（568 页） | 我们在这个基准上得几分 | 改造完成后，作为改动前后的对照 |

失败案例由人工提供（[data/failure_cases/](../data/failure_cases/)），不需要先跑全量去筛。全量跑挪到 [README](../README.md#todo) 的 D 组。

## 5. 第三条信号是免费的

`chart.jsonl` 的标签本身携带结构证据，不用调模型：

```
labels 有 3 个                        → 三键索引（面板 × 类目 × 系列）
同一页多条规则的首个标签取值重复且少   → 那一维很可能是面板名
labels 里出现 '2022:06' '1Q-2024'     → 时间刻度的格式
```

用它交叉核对 VLM 的输出：模型说"单面板"但规则要三个键，就是矛盾，标进报告。这一步是程序，不是模型——`tools/analysis/checks.py` 的 `crosscheck`，逐页写进 `report.md` 第 2 节。

### 规则劈成两半：值送进去，标签留下来

一条规则是 `(值, 标签, 容差)`。这两半的作用不同：

- **值**送进 prompt。模型逐个说它落在哪张图的哪个图元上、数字是否直接印在图上、要哪些标签才能定位。这是让答案**必须关于这一页**的手段——上一轮 `difficulty_notes` 里出现过「刻度太稀，读数困难」这种放到任何一页都成立的句子，给了值之后写不出来了。
- **标签留下来**，一个字都不送。于是模型给的 `addressing_keys` 是**预测**，程序拿规则的真实标签判它（`_keys_agree`，双向子串，与基准自己的匹配方式一致）。

这比两头都设盲强：设盲时只能做「规则要 3 个键，图最多提供 2 个」这种不等式核对；劈成两半之后，每一个值都有一次直接判分。也比两头都给强：把标签一起送进去，核对就退化成让模型复述刚看到的东西。

一个实例（`2023-05-sigma-01-english_p23`，Figure 15，指数图，图上一个数字都没印）：10 个值里模型有 7 个落在了错误的年份或错误的系列上。这不是核对写错了——**这正是那一页自己说的难处**：值轴 0/50/100/150/200，1 个指数点约 1.5 px，2022 年两条线终点相差 1 个点、不足 2 px。判分把「读不出来」从模型的一句话变成了 7/10 这个数。

### 模型还不知道什么，以及一处已知的偏置

除了抽查点标注，还有两样东西**故意不给**：

| 不给 | 为什么 |
|---|---|
| 抽查点的**标签** | 见上一节。给了，`addressing_keys` 就不是预测了 |
| 词表的「我们有没有」那一列 | 送过去的每一项只有 `key = 英文名: 判据`。告诉模型「我们画不出参考线」，它在边缘情况上就会倾向报参考线，[缺口表](../reports/INDEX.md) 立刻从测量退化成自我印证。这一列在看任何一页之前就按规格定死，程序照抄，两边独立。图表类型也照同一个问题问了一遍（`CHART_TYPE_OURS`），同样不给 |
| 流水线的结构 | 五阶段、只有一次 LLM 调用、`(键, 值, 区域)` 的输出单位、6 族 13 型的条件表，一个字都没有。system 里只有一句「这决定一个 chart generator 得能画什么」 |

### 两条正交的轴：会不会扣分，是不是通用

频次单独看会骗人。`unit_in_axis_or_title` 出现在 149 / 192 页（78%），排在缺口表第一行——但 ParseBench 的度量**根本看不见它**：4,864 条规则里，值出现量纲词的 **0 条**，标签出现单位符号的 461 条全是 `Anticipated Reserve Margin (%)` 这种系列名自带的。把它排第一，等于把「常见」当成了「重要」。

所以每个组件带**两个声明字段**，都在看任何一页之前定死：

| 字段 | 依据 | 例子 |
|---|---|---|
| `ours` | `storyline/parsebench_chart/` | `reference_line` = 无（参考线不是任何族的图元） |
| `affects` | [02 四步判定](02_chart_metric.md) | `no_value_axis` = (2,)（读不出值）· `unit_in_axis_or_title` = ()（度量看不见） |

65 项里 **42 项能改变某一步，23 项不能**。两个判据依次问，39 项缺口各归其一：

| 清单 | 判据 | 怎么处理 |
|---|---|---|
| **保留 · 能提分** | `affects` 非空且出现过 | 做完 ParseBench 的分数会动 |
| **保留 · 只提升真实性与视觉多样性** | 不满足第一条 · 通用度 通用 / 常见 | 分数一格不动，但生成的图会更像真实报告页 |
| **舍弃** | 前两条都不满足 | 某家出版方的排版习惯，或一次都没出现。记录，不改条件表 |

**前两份之间没有汇率。** 硬排成一列就得凭空发明一个换算率，那才是把编辑判断伪装成测量。我们要的是一份通用的 chart 数据集，所以第二份不是可以砍掉的部分；但把第二份的项报成「改造顺序第一名」，是报告本身在误导。

**分界不是硬的**：通用度印的是比值本身（实际覆盖的文档数 / 这些页最多能覆盖的文档数），0.70 以上通用、0.45 以上常见。`highlighted_category` 落在 0.44，换一份抽样就可能换一份清单——所以比值要印出来，不能只印结论。

### 每一项都要带证据

组件字段从 `["unit_in_axis_or_title", ...]` 改成 `[{key, figure_id, evidence}, ...]`，`evidence` 是不超过 20 词的英文：**页面上的原话，或者画了什么、画在哪**。

这一条不是为了好看。上一轮 `unit_in_axis_or_title` 报了 146 页，而汇总表给出的实例页在图上看不出这个组件——没有证据就无从判断是这一项报错了，还是实例挑错了。这一轮同一个 key 报 149 页，每一页都写出了看的是哪几个字：

> `y axis reads 0 ... 200 bare; "in USD billion (2022 prices)" appears only in the title`

判据里也写明了什么**不算**证据：`the unit is in the title` 只是把 key 换个说法。程序会数没写出证据的条数（`component_without_evidence`），写进 [INDEX §6](../reports/INDEX.md)。

同一条理由适用于类型：`other` 必须带 `type_other`。上一轮 8% 的图停在 `other` 说不出是什么，那是答案上的一个洞，不是一种类型。命名之后 26 张分成三堆——表格 14、根本不是图 7、真正的新画法 5——**原来的类型空洞主要是表格与非图**。

**图题从词表里删掉了。** 图号 / 主标题 / 副标题 / 单位 / 位置是 `_HEADING` 的五个字段，每张图都记。词表里原本有四个 key 在记同一件事，而且是按页记不是按图记：一页同时报 `figure_number_title` 与 `subtitle_above_plot`，就把一个标题数了两次。删掉之后词表 69 → 65，标题缺口按维度读而不是按 key 读。

**唯一泄漏出去的是 P1–P7 的一行描述**，在 `suggestions` 那一段——这一段现在被移到 prompt 末尾，并明写「这是给你已经在第 2 节做出的发现分类用的，不是拿来对着找东西的清单」——不给选项，模型就没法把意见归到某一项上。代价是一处**已知偏置**：P6 那行写着「标注位置、刻度格式与单位位置、负值与零线」，正好点名了 `value_label_outside`、`nonstandard_time_ticks`、`negative_values` 三个 key，不能排除它们的频次被抬高。

这条可以证伪，而且很便宜：**把 `suggestions` 整段从 prompt 里删掉跑一轮，比较这三个 key 的频次**。不显著就可以忽略；显著就把意见拆成第二次调用，或者去掉 `maps_to`、归类交给人。

同一份规则还负责把每条抽查点归到某张图上：标签与图印出来的名字互为子串就算命中，命中最多的图得这条规则。归不上的条数本身是一个信号——它意味着定位这个值要用的键在页面上根本没有以文字形式出现。

## 6. 代码与产物都在 parsebench 下

只有 `src/llmkit` 从目录外引入（共享的模型调用层，[图像通路已实现](../../src/llmkit/types.py)）。

| 路径 | 内容 |
|---|---|
| `tools/dataset/` | 下载、渲染、标注统计——把基准数据拿进来，与分析无关 |
| `tools/analysis/sample_pages.py` | 随机抽样，`--extend` 增量扩样 |
| `tools/analysis/vocabulary.py` | 65 项组件词表 + 图表类型的「我们有没有」，唯一定义处：英文判据进 prompt，中文名进报告 |
| `tools/analysis/schema.py` | 结构化输出的契约：字段、图表类型、四步、P1–P7、通用度 |
| `tools/analysis/prompt.py` | 送什么给模型。这段文字是缓存键的一半，所以单独一个文件 |
| `tools/analysis/rules.py` | `chart.jsonl` 的规则与归图，模型看不到 |
| `tools/analysis/checks.py` | 调用之后的两类核对：答案对自己、答案对规则 |
| `tools/analysis/markdown.py` `report.py` `index.py` | 两种渲染，与它们共用的中文措辞 |
| `tools/analysis/analyze_pages.py` | 驱动：`llm.map(..., schema=SCHEMA)` 并发跑完样本，写报告与汇总 |
| `data/stats/analysis_sample.json` | 抽样结果 |
| `data/stats/analysis_summary.json` | 汇总的机读形态：频次向量、类型配比、难点分布 |
| `tools/analysis/viewer.py` | 同一份数据的图示版 `view.html`：每一项配一页实例 |
| `reports/pages/<stem>/` | 一页一份报告，六节 |
| `reports/INDEX.md` `reports/view.html` | 汇总，两种形态，一次跑出 |
| `tools/dataset/page_text_stats.py` | 页面文字量：568 页从 PDF 文字层实测，中位 359 词 |

`llm.map()` 加了一个 `schema` 参数：带 schema 时每一项走 `json()` 而不是 `complete()`，批量调用因此拿到与单次结构化调用相同的解析失败反馈。这是 `src/llmkit` 里唯一为这条通路做的改动。

## 7. 成本

实测每页 12.4k 输入 token、约 5.7k 输出（`claude-opus-5`，effort high，1241 × 1654 的整页 PNG；词表 65 项后 prompt 约 3.6k token）。192 页合计约 **2.39M 输入 + 1.10M 输出**，8 并发约 35 分钟。

输出比上一轮翻了五倍，因为这一轮每个组件要带证据、标题拆成五项、每个抽查点要逐个定位——**贵的那部分正是能被核对的那部分**。

`max_tokens` 定在 12000：192 页里有 5 页跑满被截断，这几页由 `analyze_pages.py` 用 16000 再问一次（`RETRY_TOKENS`）。**`max_tokens` 也在缓存键里**，所以这是给那 5 页开的第二个键，不是给已经跑通的 187 页重新计费。再往上不行——超过某个值 SDK 会要求走流式请求。

缓存键是 `(prompt, image, model, max_tokens, effort, schema)`，所以**改判据措辞、往词表加 key、改 schema，都会让已跑过的页全部失效**。修判据、并入新组件、扩样这三件事因此要打包成一次跑；分三次做要付三次钱。

## 8. 什么时候才需要工具与多轮

刷榜阶段。那时目标是把分拉高，裁剪放大、多轮自检、代码计算都可能有用——CharTool（`2604.02794`）用图像裁剪 + 代码计算在 CharXiv-R 上报告 +8.0%。

但**分析阶段不要提前把系统做成 agent**：分析要测的量之一就是「稠密页面是不是更容易失败」（[04 P5](04_pipeline_gap.md#p5--稠密度上限抬高把稠密度变成一个可控自变量)），给分析器加自适应放大会把这个信号抹掉。

## 9. 反向差集：同一套词表也跑我们自己的页面

上面的流程只测一个方向——**基准有而我们画不出来的组件**。另一个方向现在完全看不见：**我们产出、而 ParseBench 里从不出现的组件**。

做法不需要新代码：把 03 渲染出的页面图像喂给**同一个 prompt、同一份 65 项词表**，得到我们自己的组件频次向量，与基准的向量相减。

### 「基准里没有」不等于「没用」

本项目不是只对 ParseBench 一个基准，[顶层 README](../../README.md#对齐的基准) 写的是「图表类型覆盖 6 族 13 型的常见形态，不局限于任何单一基准收录的那几种」。所以差集的第二个方向**不能直接读作无效产能**——那正是 [04 §3](04_pipeline_gap.md#3-与-storyline-的关系) 点出的唯一约束风险：让基准的类型分布反过来驱动生成。

正确的判据不是「ParseBench 里有没有」，而是「**有没有东西消费它**」：

| 消费者 | 实例 | 结论 |
|---|---|---|
| 另一个目标基准 | scatter / heatmap → ChartQA · CharXiv · ChartQAPro 的不退化边界；密集小元素 → ChartAB；指代 grounding → ChartREG++ | 保留，这是覆盖面 |
| 一行消融 | [05 §7](../../storyline/parsebench_chart/05_output.md#7-消融) 的「只用 Tier 1 图表类型」「只用意图图、去掉轮转图与多面板图」 | 保留，这是实验设计 |
| 一条能力主张 | box 的五数值字典证明值字典不是标量；scatter 的 L2 退化（每图元 1 行）证明 provenance 链在逐行形态下同样成立 | 保留 |
| **无人消费** | 待测 | 只有这一类可以压预算 |

第四类很可能是空的。**若为空，反向差集不改任何配置**，它的价值转为描述性：刻画我们的生成分布与各目标分布的包含关系，本身就是一张论文图。

而一个我们产出、却没有任何现有基准测的组件，有两种读法——**现有基准的空白**（可以指出来，是 dataset 侧 novelty 的论据），或**范围蔓延**。上面这张表就是用来区分这两者的。

### 三个方向各自的用途

| 差集方向 | 含义 | 用途 |
|---|---|---|
| 基准有 − 我们有 | 缺的能力 | 改造顺序（[reports/INDEX.md](../reports/INDEX.md)） |
| 我们有 − 基准有 | 覆盖面差异 | 先过上面那张消费者表；只有「无人消费」那一格才进 [P4](04_pipeline_gap.md#p4--轮转图的族采样加权重向量) 的权重向量 |
| 两边都有 | 有效交集 | 合成数据到 ParseBench 的迁移基础 |

注意 P4 的权重向量有两份配置：**默认那份维持均匀轮转**，反向差集只影响「对齐 ParseBench 的那一份」，即为刷榜专门产一批数据时用的配比。它不改默认值。
