## 3. 三键索引

`3d_chart` 的官方说明是 "3D chart rendering"，但被标记的页面上没有透视渲染的图表。实际含义是**定位一个值需要三个键**：

| | 1 标签 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|
| 有 `3d_chart` | 0 | 46 | **633** | 24 |
| 无 | 268 | **3,801** | 82 | 10 |

两个实例：

```
She-figures_p115                value='61'   labels=['EU-27','Women','Researchers']
                                横向堆叠条，键 = 国家 × 性别 × 职业。平面绘制。
2023-05-sigma-01-english_p24    value='9.1%' labels=['US','2022:06','Inflation']
                                两面板折线，键 = 面板 × 时间点 × 系列。
```

标签按文档级施加，所以同页的二键图表也带上这个标记——上例第二页里 Figure 16 的 `labels=['2011','Direct']` 只有两个键，同样带 `3d_chart`。

三键在宽表里需要 colspan 表头才判得上关联，在长表里不需要（[02 §2](02_chart_metric.md#长表根本不会走到第四步)）。

## 4. 版面形态

### 图不会单独出现

整页正文的文字量，568 页实测（PDF 文字层，非 OCR）：

| | 词数 |
|---|---|
| 中位 | **359** |
| 四分位 | 241 – 502 |
| 最大 | 2,857 |

≥100 词的 534 页（94%），≥200 词的 455 页（80%）。**只有 6 页少于 50 词**，即整页近乎只有一张图。

所以「图表嵌进含正文的版面」不只是定性对齐——[03 §5 页面合成](../../storyline/parsebench_chart/03_render.md#5-页面合成) 还欠一个**文字量目标**：合成页要落在这个量级，否则我们产出的是「一张图配三行字」，与被打分的页面差一个数量级。

### 其余现象

| 现象 | 实例 |
|---|---|
| 输入是整页：正文、页眉页脚、图号标题、note、source 行 | 全部 5 页 |
| 一页多张独立图表，各自有图号，抽查点横跨它们 | `2023-05-sigma-01-english_p24`（Figure 16 + 17） |
| 一张图内左右两面板，量纲不同（计数 vs 百分比） | `05021ff2-en_p19` |
| 小倍数版面，6 面板各自带图例，面板名充当标签 | `(Web_version)_E-Government_Survey_2024_1392024_p101` |
| 两面板共享系列定义与图例结构 | `2023-05-sigma-01-english_p24` Figure 17 |
| **标题块排在绘图区左侧一栏，与图并排**，不在图上方 | `2023-05-sigma-01-english_p23` Figure 15 |
| 图旁另有一栏蓝色提要文字，与图占同一横带 | `2023-05-sigma-01-english_p10`、同报告多页 |

图号与图标题位于图之上、图表之外——正是 [02 §2 第四步](02_chart_metric.md#2-四步判定走一遍这条规则)上下文回退的对象。

**「之上」不是唯一的位置。** 同一份 sigma 报告里，p10 的 Figure 6 标题在图上方，p23 的 Figure 15 标题却排在左栏、与绘图区左右并排。对第四步来说这两种差别很大：侧栏标题在解析出的 markdown 里落在哪一段，完全取决于解析器怎么切版面块。标题块位置因此是一个四值维度（图上方 / 与图并排 / 图下方 / 无），见 [P7](04_pipeline_gap.md#p7--图标题成为一等公民)。

| 特征 | 实例 |
|---|---|
| 无纵轴线，只有水平网格线 | `05021ff2-en_p19`、`2023-05-sigma-01-english_p24` |
| 面板整体带浅色底 | `2023-05-sigma-01-english_p24` |
| 图例底部色块无边框 / 顶部且含实线与虚线参考线两类 | `P505350-..._p49` / `..._p101` |
| 水平虚线参考线，带独立图例项 | `2023-05-sigma-01-english_p24` Fig 16 |
| 数值标签写在条内（白字）/ 分段内小字 / 窄段移到外部带引线 | `..._p101` / `P505350-..._p49` |
| x 刻度标签整体旋转 90° | `2023-05-sigma-01-english_p24` Fig 17 |
| x 轴两级标签（年在内，分组名在外，带分隔线） | `P505350-..._p49` |
| 分叉条形图，零线居中，含负值 | `05021ff2-en_p19` 右面板 |
| 堆叠条与分组条同图 | `P505350-..._p49` |
| 类目轴为 ISO 国家码，纵向排布 | `She-figures_p115` |

## 6. 标签与数值的文本形态

| 类别 | 实例（全部取自实际规则） |
|---|---|
| 时间 | `2018` `1Q-2024` `2021/2022` `2022:06` `08` `3/15/2025` `Q1 2005-Q1 2024` |
| 实体缩写 | `EU-27` `IRL` `NLD` `LDC/LLDCs` `UMICs` |
| 系列名（**单位写在系列名里**） | `Operating Cash Flow ($B)` `% change in real US$ terms` |
| 面板名 / 图标题 | `193 UN Member States` `B. GHG-intensive occupations` |

数值文本：带 `%` 499 · 带货币符号 45 · 带千分位逗号 77 · 负值 **399** · 整数 3,111 · 1 位小数 1,309 · 2 位及以上 444。

### 标注写的是**画在图上的那个数**，不是量纲还原后的数

一张标题写着 `in USD billion` 的图，标注里的值是 `50`，不是 `50000000000`。4,864 条规则的整数位数分布：

| 整数位数 | 条数 | 占比 |
|---|---|---|
| 1 位 | 1,268 | 26% |
| 2 位 | 2,297 | **47%** |
| 3 位 | 732 | 15% |
| 4 位及以上 | 221 | 5% |
| 小于 1 / 等于 0 | 313 | 6% |
| 值里带了量纲或括注 | 33 | 1% |

**89% 落在 1–3 位**，绝对值 ≥10⁶ 的只有 23 条（0.5%），而那 23 条本身就是轴上直接标成 `26,704,000` 的图。实例 `2023-05-sigma-01-english_p10`（Figure 6，标题 `Growth in global natural catastrophe insured losses in USD billion (2022 prices)`，y 轴只有 `0 … 200`）的十条规则取值是 `50` `27` `72` `155` `70` `80` `169` `95` `123` `100`。

**对我们的意义有两条。**

1. **记录的 `value` 就是绘制时的刻度值**，与 [04](../../storyline/parsebench_chart/04_record.md) 现在的做法一致，不需要改。
2. **量纲只以文本形态存在**，写在标题或轴标题里（`unit_in_axis_or_title` 是最高频的缺口之一）。所以它必须**被渲染出来**才可能被解析出来——这正是 [P7](04_pipeline_gap.md#p7--图标题成为一等公民) 把 `unit_text` 单列为标题的一个字段、以及 [P6](04_pipeline_gap.md#p6--风格向量补三维) 把「单位位置」列为风格维的原因。measure 声明里有 unit 但一个字都不画出来，等于这条信息在产出上不存在。

规则本身设了 `normalize_numbers: true`，只归一化千分位与格式，不做量纲换算。

最后那 33 条是唯一的例外，也值得单看：`$1.5M` `1.2bn` `400m` `£10.4m` `€123.2` 把货币或倍数写进了值本身，`25 (13.0%)` `1 (2005)` 把括注也写了进去。**这些字符要原样出现在解析结果里才算对**，所以它们既是取值问题也是文本问题——数值标注的渲染不能只画数字。
