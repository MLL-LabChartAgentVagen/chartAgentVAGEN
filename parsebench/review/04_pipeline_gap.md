# 流水线改进清单

对照 `storyline/parsebench_chart/` 当前版本。**每条都是往流水线上加能力，没有一条要求删掉现有设定**——为什么，见 [§3](#3-与-storyline-的关系)。规格改动仍写回 `storyline/`，本文只列结论。

按「影响的抽查点比例 × 改动成本」排序。

## 2. 七项改进

### P1 · `readable` 从二值门改为按可达精度分级

**现状** [chart_types.md §4](../../storyline/parsebench_chart/chart_types.md#4-值的画法)：没写数值时，长度/位置画法要求「1% 的值折算成像素 ≥ 2」才 readable；角度/颜色画法一律排除。写了数值则容差 0。

**基准**：估读点容差中位 5%、四分位 [5%, 10%]；显式数值点中位 1%（不是 0）。论文明写图表类型含 pie。

**改**：把判据的输出从布尔改成 **ε——该图元在当前像素几何下能达到的相对精度**：

```
ε = (2 像素 × 每像素代表的值) / |值|        长度 · 位置
ε = (可测角度下限 × 值域) / |值|            角度，按同一式算，不预先排除
颜色                                        维持排除：色标量化与感知非线性不构成可计算的 ε
```

值目标按 ε 写容差，写了数值标注的图元 ε = 0.01（对齐基准，而非要求字符串精确相等）。

**对 storyline 的作用**：产出一个现在没有的标注量——**每个 mark 的可达读数精度**。数据集因此能声明"这个 mark 能读到 ±3.2%"，而不只是"能读/不能读"。三处收益：① [05 §3](../../storyline/parsebench_chart/05_output.md#3-输出能自己验自己) 的可验证奖励从二值变成分级；② 角度画法的取舍从规定变成计算结果，饼图在 5% 容差下重新进入值目标；③ 「精度随像素几何变化」本身可作为一条消融曲线。现有工作没有 per-mark 可达精度标注。

### P2 · 面板维进入键

**现状** [04](../../storyline/parsebench_chart/04_record.md)：三层记录按 `(figure_id, panel_id, key)` 对齐，`key` 是面板**内**的键，面板身份只是一个标识符，不带取值。

**基准**：14.5% 的点需要三个键，形态是 面板 × x 类别 × 系列（`['US','2022:06','Inflation']`）。

**影响**：正交切片关系产出的小倍数图，第三个键就是被切那一维的取值；它目前只体现为 `panel_id`，导出的表里没有这一列，这类样本在基准上无效。

**改**：多面板图每个面板带一个 `panel_key`——被切维度的列名与取值。`key` 的定义不变，是给面板加一个字段。

**对 storyline 的作用**：`key` 从「面板内地址」升为「图内全地址」，provenance 链 `datum → mark → source_rows` 的 mark 端因此全局唯一。这正落在本项目可防守的那条轴上，也是跨面板一致性样本的前提——两个面板的 mark 现在可以按 `panel_key` 对齐比较。

### P3 · 加一个整页 markdown 导出

**现状** [05 §2](../../storyline/parsebench_chart/05_output.md#2-训练目标)：A 组「带位置的表」是 `(键, 值, 区域)` 全集。

**基准**：解析器输出整页 markdown / HTML，规则在其中所有表里搜索，且面板名必须是粗体或标题才被上下文回退认可（[02 §2](02_chart_metric.md#同一页改一个字符就变-0-分)）。

**改**：加一个导出函数——整页 markdown，图表部分为长表，图标题写成表**前**的 markdown 标题。不改流水线。

**对 storyline 的作用**：纯加法，[05 §4](../../storyline/parsebench_chart/05_output.md#4-同一份记录还能派生什么) 已经写了「元数据一次产出，多次投影」，这是又一个投影。副产品是我们能直接在基准上跑出自己的数。

### P4 · 轮转图的族采样加权重向量

**现状** [02](../../storyline/parsebench_chart/02_figure.md)：轮转图「按图表族轮转，先补批次里还没有的族」，目标是类型覆盖面。

**基准**：Charts 只覆盖 bar、line、pie、compound。histogram、scatter、box、heatmap、funnel、waterfall 在这个基准上不出现。

**改**：族采样加一个可配置权重向量。**默认维持均匀轮转**（服务 [05 §7](../../storyline/parsebench_chart/05_output.md#7-消融) 的类型广度消融），另给一份对齐 ParseBench 的权重配置。不删任何类型。

**对 storyline 的作用**：零约束。权重向量本身让「类型配比 → 目标基准表现」变成一条可测关系，比现在的均匀轮转多一个自变量。

**这一项管不到「画不出来的族」。** 权重向量只能在条件表已有的 13 型之间分配配额；基准里出现而条件表根本没有的类型（地图、仪表盘，以及模型报 `other` 时自己命名的那些形式）不是权重问题，是缺一整族。这类缺口现在与组件缺口并排列在 [INDEX §1.2](../reports/INDEX.md)——以前它只出现在「类型配比」表里，于是缺口表看着是全的，实际漏掉了整族画不出来的图。要不要为其中某一族加条件行，按同一条标准定：**看它的文档分布，不看它的页数**（[INDEX §2](../reports/INDEX.md)）。

### P5 · 稠密度上限抬高，把稠密度变成一个可控自变量

**现状** [chart_types.md §2](../../storyline/parsebench_chart/chart_types.md#2-条件清单)：`grouped_bar` \|P\|·\|S\| ∈ [6,24]，`stacked_bar` [6,20]，`line` 系列 1–6。

**基准实例**：`She-figures_p115` 为 44 类目 × 2 × 4 = 352 个分段；`2023-05-sigma-01-english_p24` Fig 17 为单面板 49 时间刻度 × 3 折线。现有上限画不到这一档。

**改**：抬高结构条件上限，或加一档高稠密配置。

**对 storyline 的作用**：ChartAB（`2510.26781`）报告小元素定位在密集版面下显著退化，但没有工作能**受控地**生成稠密度阶梯。抬高上限之后，稠密度是一个能连续调的自变量，P1 的 ε 随之变化——「稠密度 → 可达精度 → 模型表现」这条链在同一份数据里可测。

### P6 · 风格向量补三维

| 维 | 现状 | 基准实例 |
|---|---|---|
| 数值标注形态 | [03 §6](../../storyline/parsebench_chart/03_render.md#6-数值标注) 只记布尔 `labeled` | 条内白字 / 分段内小字 / 窄段移到外部带引线 / 面板外侧 |
| 刻度标签格式与单位位置 | `time` 列由 start/end/freq 声明；unit 在 measure 声明里 | `2022:06` `1Q-2024` `08`；ISO 码 `IRL`；单位写在系列名里 `Operating Cash Flow ($B)` |
| 负值与零线 | 三份规格均未涉及 | 399 条规则是负值；`05021ff2-en_p19` 右面板零线居中 |

**改**：`labeled` 从布尔改为标注位置枚举；刻度格式化方式与单位位置成为风格向量的维；measure 允许值域跨零，矩形图元支持从零线双向延伸。三项互相独立。

**对 storyline 的作用**：风格向量多三维，风格配对样本的对照更硬，[04 §6](../../storyline/parsebench_chart/04_record.md#6-三项自检) 第三项自检（换风格答案是否不变）的检验力随之上升。

### P7 · 图标题成为一等公民

**现状**：[02 §5](../../storyline/parsebench_chart/02_figure.md#5-figurespec) 的 FigureSpec 有面板列表、版面、共享关系、关系、来源五个字段，**没有标题**。有的是 `caption`——[05 §2](../../storyline/parsebench_chart/05_output.md#2-训练目标) 的一个训练目标，[03 §0](../../storyline/parsebench_chart/03_render.md#0-示例) 把它画成图**下方**的图注。

而 [01 §2](../../storyline/parsebench_chart/01_data.md#分析意图有什么用) 自己写明：**没有意图，caption 只能从 ViewSpec 生成**，"Average wait time by hospital" 这种复述坐标轴名的句子，当训练目标学不到东西。八张图里只有三张意图图有意图，**另外五张（2 张多面板 + 3 张轮转）没有标题文本的来源。**

**基准**：192 页实测，**254 / 265 张图有标题（96%）**，其中 149 张（56%）带 `Figure N` / `Exhibit N` 前缀，88 张（33%）标题不止一行，159 张（60%）把单位写在标题里。位置：图上方 231 · 图下方 15 · **与图并排的侧栏 8** · 无标题 11。标题的形态有三种，都在同一批页面里出现：

| 形态 | 实例 |
|---|---|
| 论断句 | `Figure 5. Women persistently receive lower labor income than men everywhere` |
| 描述句 | `Figure 18: Innovation performance of the EU27 Member States in the Intellectual assets dimension` |
| 短标签 | `Operating Margin` |

标题还常常是**单位与口径的唯一载体**——`unit_in_axis_or_title` 出现在 149 / 192 页（78%），`2011 = 100` 这类指数基准也写在标题里。

**但要说清楚：P7 基本不会提高 ParseBench 的分数。** 度量只比对「值 + 定位标签」，两样都不引用标题：

| 检验（4,864 条规则全量） | 结果 |
|---|---|
| 值里出现量纲词（`billion` `million` …） | **0 条** |
| 标签里出现单位符号 | 461 / 10,243（4.5%），全是 `Anticipated Reserve Margin (%)` 这种**系列名自带**的，属 `unit_in_series_name` |
| 标签里出现图号 | **14 条（0.14%）**，且只在一页多图、图题当第三个键时 |

所以 P7 的理由**不是刷分，是数据真实性**：94% 的真实图有标题、54% 带图号，而我们八张图里五张连标题文本的来源都没有。一份从不给图配标题、从不把单位写进标题的生成数据，与真实报告页的差距就摆在这三行数字旁边。第四步的上下文回退确实存在，但它在这个分片上只被 14 条规则触发——**把 P7 当成提分手段是把 0.14% 当成 76%**。

**改**，三件事，都不需要新增 LLM 调用：

1. **FigureSpec 加 `title`**：图号 + 标题 + 可选副标题 + 单位。渲染在绘图区**上方**；`caption` 仍是训练目标，渲染位置（上 / 下 / 不渲染）成为风格向量的一个取值。图号由页面合成器按页编号，一页多图各自有号。
2. **轮转图与多面板图的标题按模板从声明合成**：测度名 + 维度名 + 聚合 + 时间范围 + 单位，例如 `Average wait time by hospital and severity, Jan–Jun 2024 (minutes)`。这是规则，不是模型判断——列名与单位都在 [01](../../storyline/parsebench_chart/01_data.md) 的声明里。
3. **意图图的标题由 01 那一次调用多输出一行**：意图句本来就在那一次调用里，多写一行报表体标题不增加调用，也不违反「不在 prompt 里出现图表类型」。

**对 storyline 的作用**：`caption` 现在只有意图图那三张有信息量，其余五张是复述坐标轴名的填充。拆成「title（图上画的）+ caption（训练目标）」之后，两者各自的定义都变清楚：title 每张图都有、可由规则合成、进入 L0 的 Text 元素；caption 只在意图图上承载图外信息，其余图**可以不产出 caption**，从而 caption 这个训练目标不再被无信息量的样本稀释。

**标题不是一个组件，是一个有五个字段的对象。** 图号 / 主标题 / 副标题 / 单位 / **位置**。词表里原本有四个 key（`figure_number_title` `subtitle_above_plot` `caption_below_figure` `title_block_beside_plot`）在重复记录这同一件事，而且是**按页**记不是**按图**记——一页同时报「图号标题在上方」和「副标题分行」，就把同一个标题数了两次。这四个 key 已经删掉；现在每张图直接记这五个字段，缺口按维度读。

**位置这一维是四值不是两值。** `2023-05-sigma-01-english_p23` 的 Figure 15：图号、标题、副标题三行排在**左栏**，与绘图区左右并排。同一份报告的 p10 则是标准的图上方。这两页只差一个版面参数，而侧栏标题在 markdown 里落在哪一段完全取决于解析器怎么切版面块。

**新增的消融行**：`标题在图上方 / 与图并排（侧栏）/ 图下方 / 无标题`。它测的是 [02 §2 第四步](02_chart_metric.md#2-四步判定走一遍这条规则) 上下文回退的贡献——**这个分片上只有 14 条规则会用到它，所以这一行的信号在 ParseBench 上会很弱**，它的价值在别的目标基准与 QA 导出上。[05 §7](../../storyline/parsebench_chart/05_output.md#7-消融) 现在没有任何一行涉及标题。

## 3. 与 storyline 的关系

**没有一条改动要求删掉现有设定。** 七项里五项（P1、P2、P5、P6、P7）是往 grounding / provenance 与风格这两条轴上加东西：

- P1 新增 **per-mark 可达精度 ε**——现有工作没有的标注量
- P2 把 mark 的地址从面板内升为图内全局，补齐 provenance 链
- P5 把稠密度变成受控自变量
- P6 扩风格向量，加强风格不变性的检验
- P7 把图标题从 caption 里拆出来，caption 因此只保留有信息量的那一类

**唯一真实的约束风险**是让基准的类型分布反过来驱动生成：ParseBench 只考 bar / line / pie / compound，若据此裁掉其余七型，就丢掉了 13 型覆盖与类型广度消融。P4 写成「权重向量 + 默认均匀」而不是「删类型」，就是为了把这个风险挡在配置层。

**反过来，ParseBench 对 storyline 有一项正面作用**：它把 Charts 与 Visual Grounding **分开评分**，且现状是没有任何方法两项都强（纯 VLM 的 Grounding 只有 6–7%，版面感知流水线的 Charts 只有 1–2%，见 [01 §4](01_benchmark.md#4-榜单)）。本项目的输出单位 `(键, 值, 区域)` 一次同时供给这两维——**"单模型两项都强"这个主张，ParseBench 是目前唯一能测它的仪器**。对齐它不是把 storyline 收窄成一个基准的形状，而是给已有主张找到了度量。
