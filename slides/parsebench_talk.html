02 The LLM writes a program, not numbers

Four SDK methods. Columns are declared first, rows are emitted last.

# dimension group: geography, hierarchical dim("borough", ["Manhattan", "Brooklyn", "Queens"], weights=[.42, .34, .24]) dim("station", STATIONS_12, parent="borough") # 4 stations per borough # dimension group: rider and bike, conditional dim("membership", ["member", "casual"], weights=[.62, .38]) dim("bike_type", ["classic", "electric"], parent="membership") time("date", "2024-01-01", "2024-03-31", freq="D") # month / dow / is_weekend derived # measures: expressions. Dependencies are inferred from free variables. measure("duration_min", "lognormal(2.6, 0.5) * (1.35 if is_weekend else 1.0)") measure("distance_mi", "duration_min * gaussian(0.14, 0.02) * (1.3 if bike_type=='electric' else 1.0)") measure("revenue_usd", "1.50 + 0.12 * duration_min * (1.8 if bike_type=='electric' else 1.0) * (0.7 if membership=='member' else 1.0)") measure("co2_saved_lb", "distance_mi * 0.85") emit(1250)
9 declared columns plus 3 derived calendar fields. Every relationship lives inside an expression, never in a follow-up patch call.

Enumerate: four structural rules

Each registry entry declares typed slots. A binding is legal when all four rules hold.

1Slot type must match
categorical / temporal / measure. A slot accepts one kind of column.
× bar( x = duration_min )
a measure cannot fill a categorical slot
2Cardinality in bounds
Each slot carries a distinct-value range from the registry.
× pie( x = station )
12 slices, the pie slot allows 2 to 8
3Two categoricals must cross groups
Columns inside one dimension group nest, they do not form a grid.
× grouped_bar( x = borough, series = station )
3 × 12 = 36 cells, 24 of them structurally empty
4Required slots all filled
Optional slots may stay empty, and each option multiplies the count.
× scatter( x = duration_min )
scatter needs two measures, y is empty
No data values are read. Everything above is decided from Schema Metadata alone.

Does this step need a model call

The earlier data_generation spec has no call here. What changes if it stays deterministic.

Deterministic — operator compatibility
Keep a view if at least 2 operators from the question algebra apply to its chart type. One compatibility table, no call, no intents.
222 candidates → every compatible view survives
pie( borough, MEAN duration_min ) is kept
Intent-tagged select
Map 3 intents onto the 222 candidates and return the ids. Produces the intent tag that filter 2 and the caption both consume.
222 candidates → 5 tagged picks
the model can still pick badly — #4 and #5
The difference is filter 2. "Would an analyst draw this" has no expression without an intent — compatibility alone cannot see that a mean is not additive.

Four invariants

What holds at every stage

Atomic grain
Each fact table row is one indivisible event. Aggregation happens only in the SQL projection.
No LLM numbers
The LLM writes the program and picks from enumerated options. Every value comes from the engine.
Free annotation
All ground truth is exported from renderer state, with no estimation and no human labeling.
Style is separate
Ground truth follows the FigureSpec and is invariant to the style vector.
