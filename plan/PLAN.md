# 图表数据生成流水线 · 实现计划

**五个阶段全部落地，端到端可跑、逐位可复现。** 施工清单 130 项完成 126 项，剩下四项要先有训练与
评测那一侧（见 [§7](#7--还没做的)）。跑出来的东西在 [`reports/report.html`](reports/report.html)。

规格在 [`../storyline/parsebench_chart/`](../storyline/parsebench_chart/)——能画什么、怎么记，
唯一定义处。本文不重复规格，只写三样东西：**为什么这么切**、**哪里会踩坑**、**做了哪些项**。
人看的图解版是 [`plan.html`](plan.html)。

**做**：从领域池到训练目标文件的完整数据生成流水线，以及它的自检。
**不做**：模型训练、评测脚本、真实图表的抓取与清洗。这三项消费本流水线的产物，不在本仓库。

## 1 · 流水线

### 1.1 · 一条数据走完全程

五个阶段，一条单向的数据流。每个阶段只认它上游那一份数据接口。

```
配置 + 根种子
     │
     ▼
┌──────────┐ FactTable   ┌──────────┐            ┌──────────┐          ┌──────────┐          ┌──────────┐
│ 01 data  │+TableSchema │02 figure │ FigureSpec │03 render │RenderOut │04 record │  Record  │05 output │
│ 数据 LLM①│────────────▶│选图 LLM② │───────────▶│  渲染     │─────────▶│ 标注记录  │─────────▶│ 训练目标  │
└────┬─────┘             └────┬─────┘            └──────────┘          └──────────┘          └──────────┘
     │ 逐族判非空               │ 逐条判候选
     └──────────┬──────────────┘
                ▼
     registry/conditions.py    ViewSpec + TableSchema → 能不能画
     纯函数，01 与 02 共用，只读声明

──────────────────── 共享层 ────────────────────
  interfaces/  六份数据接口，唯一定义处
  registry/    图表条件表 + 条件判定 + 可读性判据
  common/      种子 · 几何 · 像素反算 · 读写与版本 · 缓存
```

| 阶段 | 输入 → 输出 | LLM |
|---|---|---|
| 01 data | 领域池 → FactTable + TableSchema（含场景与意图绑定） | **1 次**：写场景、生成脚本与意图绑定。解析、判族、执行、结构检查全是程序 |
| 02 figure | FactTable + TableSchema → FigureSpec | **1 次**：选完图之后写标题与列的散文名。选图本身全是程序 |
| 03 render | FigureSpec + StyleVector → RenderOutput | 0 |
| 04 record | RenderOutput → Record | 0 |
| 05 output | Record → 训练目标文件 | 0 |

每个阶段是一个函数：`阶段(上游产物, 种子, 配置) -> 下游产物`。同样的输入必得同样的输出。

**没有候选清单这个中间产物。** 01 只判每个族非空还是空；02 的三类图分别用构造、推导、采样产出具体
ViewSpec。两处调同一个 `registry/conditions.py`。

### 1.2 · 两次 LLM 调用，都不产出数值

01 写数据（场景、脚本、意图），02 在图选定之后写字（标题、副标题、单位、每列的散文名）。
**LLM 只在「定义」和「命名」时出现，不在「选择」时出现。** 构造、推导、采样、拒绝、组版全部是规则。

### 1.4 · 运行方式

**种子**：一个根种子，按 `(scenario_id, 阶段名, 序号)` 派生子种子。任何阶段不读全局随机状态。

**缓存**：02 的产物按输入的内容哈希落盘，命中直接返回。渲染不缓存——它的产物是记录旁边的一个文件，
没有图像的记录不是产物。

**产物布局**：`data/generated/<run_id>/<scenario_id>/` 下按阶段分文件，图像与记录同名不同后缀。
写 schema 的同时写一份 `schema.md`（层级树、数值列依赖、意图指向三张 Mermaid 图）。

**失败处理**：任何阶段失败只丢弃当前场景或当前图并写一条带原因的记录，不中断批次。跑完输出各阶段
通过率与丢弃原因——这是流水线健康度的主要观测量。

## 2 · 设计决定

一步一小节。每条都对着一处会踩的坑；规格里已经写清的东西这里不重复。

### 2.1 · 共享层：五步的地基，不是其中一步

- **接口先定死。** 定死之后五个阶段才能并行开发，每个只需要上游的样例文件。改接口要同时改
  `tests/samples/` 并升 `serde.SCHEMA_VERSION`，让旧产物在读取时报错而不是静默错算。
- **图表条件表是唯一定义处。** 新增一个类型只改 `registry/charts.py` 加一个绘制分支。
  四类条件、图元形状、值字典逐项相同的两个「类型」（实心饼与中空饼）只占一行，差别是风格向量的一维。
- **类型表由乘积定义。** `GRID` 是「投影形态 × 图元形状」的 4 × 6 网格，每一格要么填类型，要么写明
  为什么空着。缺哪种图是**读一张表**，不是在别人的基准里撞见。加第六种图元形状就是多一列。
- **像素反算只有一个实现。** `common/readback.py` 提供「框内某颜色的占比」与「框 + 轴 → 值」。
  04 的自检拿渲染器的记录当输入，05 的奖励拿模型输出当输入——**前两项自检只需要图像和被声称的
  「值 · 框」，不需要真值**，所以同一段代码在生成端是自检、在训练端是奖励。
- **容差是参数，不是常数。** 三个调用点传的不是同一件事，也不能互相替换：抽查标注集传基准口径
  （印了 0、估读 1%），自检与奖励传像素能分辨的那个量。三种「ε 在图内会变」的情形写在
  `channels.py` 的文档串里：对数轴逐图元算、堆叠中间段两次读数、部分印数时印了的那个 ε ＝ 0。
- **密度是一档，不是一个常数。** `DENSITY_BANDS` 抬的是**声明了上界且上界本来就不低的那些类型**的
  上界；饼的 8 格是「角度还读得出来」的界，不是密度的界，任何档都不动它。最稀疏档逐位复现所有
  声明的界。档位另给事实表行数下界，行数不够就降档，**不放宽 `min_rows_per_cell`**。

### 2.2 · 01 数据

- **一次调用写三段，不拆成两次。** 脚本是场景的形式化写法。分两次会在中间放一层有损的 JSON——层级、
  有序性、单位、可加性在自然语言里都不显式——而且下游没有回到上游的通路。三段各有独立校验，
  哪段不过就带具体原因回喂哪段。
- **可行性在声明期判完。** `dim` 的取值表给出基数，`time` 的起止与频率给出点数，`additive` 与
  `ordered` 是声明字段。01 只问每个族是不是非空，从不展开组合。只有方差 / 相异值 / 实际单元格数
  要看真实数据。
- **一行事实表 ＝ 一次事件。** 聚合只发生在 02 的投影里，而且那里有三种形态根本不聚合。

### 2.3 · 02 选图

- **三类图三种产出方式，只有一种需要随机数。** 意图图**构造**（绑定固定列、聚合与族；条件表固定
  类型；确定顺序打破并列）；多面板图与组合图**推导**（锚点必须是一张已单独通过准入的图）；
  轮转图**采样加拒绝**。名字描述的是「怎么被选中的」，不是重要性——不要重新引入「主图 / 补充图」。
- **不枚举候选清单。** 枚举要把几百到几千条候选全算出来、每条投影一遍才知道通不通过，而一个场景
  只出十来张图。轮转先补批次里还没有的族，同族里先抽还没出现的类型，并且**在抽之前**用声明的语义
  条件收窄候选池——那是读声明，不是枚举候选。
- **多样性由判据管，不由数量管。** 批次里已有「键集合相同、图元形状也相同」的图就拒。没有阈值要调。
  `K_max` 只是渲染与存储的预算：拿数量当代理挡不住「八张图全是 `bar(hospital × …)`」。
  两处豁免：从锚点推导出来的图（键重复正是配对样本的来源），以及**同一页且各有标题**的多张图。
- **投影永远是一条 SELECT，四种形态。** 分组标量 / 分组五数 / 分箱计数 / 逐行不分组。四者分支是
  因为值字典大小、能用哪些数据条件、L2 有没有用，三件事都不同。产出的值字典只留类型声明的那几个
  键——画不出来的数读不出来，留着就是一个没有问题能问到的值。
- **九条关系，六条把第二个视图放进另一个绘图区，三条放进同一个。** 同一条关系两种落法，这就是
  「一个面板放两个视图」是组合规则而不是类型表一行的原因。两个叠放的视图必须图元形状不同，
  否则框重合、记录里分不开。轴数由量纲定：异量纲两条，同量纲一条，**同量纲但值域比 > 20 倍也给两条**
  （否则叠加压成贴轴的直线，自检②会把整张图丢掉）；同量纲且值域相当时由 `dual_axis` 采样决定。
- **行过滤只在 `panel.py` 里出现。** 它只服务「时间对照」，是配对时从锚点现场切出来的，不是
  ViewSpec 的一个采样维度。
- **键的每一段记下它从哪读到。** 九种取值。一条键里三段的出处各不相同：模型要找 `Mercy General`
  得看面板标题，要找 `Surgery` 得看 x 轴刻度——**记一个「这张图的键来自哪」答不出这两个问题里的
  任何一个**。同一份数据换个画法出处就变，键没变。它是 FigureSpec 的属性，不是风格的。
- **第二次调用写字，不选图。** 一个场景一次，八张图批在一起；输入是 sub-schema，**不含任何数据值**；
  输出是每张图的标题 / 副标题 / 单位，加每列的散文名。**每张图都要标题**——意图那个区分是 caption
  的事：caption 是训练目标里那段讲图上读不出来的话，标题是画在图上的字。三张用意图、五张拼模板，
  语料里就有两种一眼听得出的腔调。校验**不许含数字**（年份与季度除外）：标题画出来就是真值。
  拿不到模型时退回模板，日志记的是**实际发生的事**，不是尝试过什么。

### 2.4 · 03 渲染

- **画和记不分开。** 画每个图元的那一行同时写记录——只有那一刻框、键、值三者同时在手。
  永远不要先画完再回头解析图像。
- **布局参数冻结。** 图像尺寸、dpi、绘图区矩形三项写死。**每一条带都占固定高度，有没有内容都留着**：
  图上方的文字带、轴标题下面的图例带、右边给第二条值轴的位置。哪一条只在需要时才出现，绘图区就会
  移动，而所有已经记下的框都作废且不报错。
- **按图元形状分文件，不按图表类型分文件。** 17 种类型 6 种形状。`draw/rect.py` 同时服务 bar 族、
  histogram、waterfall、funnel、区间条——差别只在值字典里填哪几个键、矩形的底在哪。
- **风格向量是一张声明式取值域表。** 40 维，每维四个字段：取值域 · 默认 · 绘制分支 · 是否影响可读性。
  两条元测试读这张表——每个声明的取值都要有绘制分支（否则记录会写下一件没发生的事），标了
  「不影响可读性」的维度在自检③下答案逐位不变。
- **边不能比它勾的形状还厚。** 描边用页面底色、勾在形状内侧，比边宽两倍还薄的矩形会被自己的边
  画没，而记录照样写着框、值和 `readable=True`。边宽按图元厚度收窄。
- **同一份 FigureSpec 渲两份风格版本是一个产物**，不是一次重试：它既是配对样本，也是自检③的输入。
  渲一次，两处用。

### 2.5 · 04 标注记录

- **可读性在渲染之后判，判据只有一处。** 从实际像素几何加编码通道判：长度 / 位置类可能可读；
  角度 / 颜色类不可读；印出来的数总是可读且容差为 0。**读不出来的图元掉出值目标，仍留在定位目标里。**
  键里有一段页面上没写（散点的行号）的，**主动排除出值目标**——那种问题没有正确答案。
- **每种形状量哪几个键，是形状的属性。** 平的矩形量离基线远的那条边；堆叠段量两条累计边（它的
  `value` 是差，不落在任何一条边上）；箱线量四分位那两条；区间条与误差棒量两端；散点两条轴各量一次；
  直方图只量计数（量箱边会把条宽钉死）；扇形与格子一个都不量。
- **三项自检在生产路径上，不在测试里。** 边画边记的错误只会在真实数据上暴露。前两项不需要真值，
  所以同一段代码在训练端就是可验证奖励。第三项不需要额外渲染——它消费的两份风格版本本来就是产物。
- **底色读自面板自己的上边与两侧。** 按白底判「框里有没有东西」，加了底色之后会**静默失效**；
  只取顶部一条又会在热力图上取到格子的颜色。整块画满的面板没有底色可判，就明说这一项对它没有分辨力。

### 2.6 · 05 输出

- **对外产物的形状是导出参数，不是记录结构。** `key_scope` 决定一个图元的地址交出去多长（绘图区
  里面的、加上它所在的面板、加上只有颜色说的那一段），`granularity` 决定一图一份、一页一份还是
  一批一份。两者都**随产物落盘**——模型报回来的键要能落回图元，不知道用的哪个作用域就落不回去。
- **页面部件按页合并，与粒度无关。** 一页两图各导一份，两份都只标了自己那张的文本块，互相把对方的
  漏掉——半页标注不是更小的任务，是错的答案。
- **记录自足。** 导出程序只 import `interfaces/record.py` 与 `common/`。一份存下来的记录如果要靠
  某个阶段模块才能读懂，它就只有生成它的那份代码能解释。
- **奖励拿到的是整个值字典。** 把模型的答案缩成一个 `value`，形状自己的「哪两个键横跨这个框」的
  规则就永远不生效，瀑布、堆叠、箱线、误差棒的**正确答案会被判为错**。容差里那个「记录精度」也必须
  从记录传进去：从这一批答案里反推，一个答案的判定就取决于同批的其他答案，模型把所有数四舍五入
  就能给自己换来更宽的容差。

## 3 · ParseBench 的十条缺口与五条一般化

证据在 [`../parsebench/reports/INDEX.md`](../parsebench/reports/INDEX.md)。
**ParseBench 是覆盖度的第一个对照集，不是目标函数**：每条都写成一个带默认值、可枚举、可扫的维度，
默认行为与改造前逐位一致；换一把尺子时改的是对照集，不是流水线。

| | 缺什么 | 怎么落的 | 落在 |
|---|---|---|---|
| **P1** | 可读判据的容差从写死变成参数 | `channels.readable(..., tolerance)`；三个调用点各传各的 | [2.1](#21--共享层五步的地基不是其中一步) |
| **P2** | 面板名进对外的键 | `key_scope="panel"`，面板名取自它自己画出来的标题 | [2.6](#26--05-输出) |
| **P3** | 一页多图，导出的表要分得开 | 页面部件按 `page_id` 合并；准入给同页多图开豁免；整页 markdown | [2.6](#26--05-输出) |
| **P4** | 族采样权重可换 | `sampling.py` 三个预设，作用在抽取顺序上而不是配额 | [2.3](#23--02-选图) |
| **P5** | 基数上界随密度档 | `DENSITY_BANDS` 五档，只抬「密度性」的上界 | [2.1](#21--共享层五步的地基不是其中一步) |
| **P6** | 风格向量补取值 | `STYLE_DOMAINS` 40 维 ＋ `series_marks` / `dual_axis` / 画布三维 | [2.4](#24--03-渲染) |
| **P7** | 标题块成为记录里的对象 | `TextBlock` 八个角色，画出来的那串字进 `Element.text` | [2.4](#24--03-渲染) |
| **P8** | 颜色分组进对外的键 | `Binding.colour_group`，映射是函数时才加这一段 | [2.3](#23--02-选图) |
| **P9** | 图元记下它对着哪条轴、自己是什么形状 | `Mark.value_axis` / `mark_shape` | [2.5](#25--04-标注记录) |
| **P10** | 类型表加三行 | 区间条 · 表格型图 · windsock，另加乘积表预测出的误差棒 | [2.1](#21--共享层五步的地基不是其中一步) |

五条一般化——把「补上实测缺的那几项」抬了一层，覆盖面大得多，而且都不增加复杂度：

| 一般化 | 原来的写法 | 抬一层之后 |
|---|---|---|
| **键的每段记来源** | P2：面板名进键；P8：颜色承载键的一段 | 键的**每一段**记下来源，九种取值 |
| **图外文本一等对象** | P7：标题拆成五个字段 | `TextBlock(role, scope, placement, text)`，八个 role |
| **风格取值域表** | P6：照实测清单补 30 项 | `STYLE_DOMAINS`，每维带取值域 / 默认 / 绘制分支 / 是否影响可读性 |
| **类型表按乘积** | P10：加三行 | 类型表由「投影形态 × 图元形状」的乘积定义，缺口靠读网格找 |
| **导出粒度是参数** | P3：加一个整页 markdown 导出函数 | 导出粒度是一个参数（一图一表 / 一页一份 / 一批一份） |

**视觉出处是这一轮的可防守轴**，不是第十一条缺口，是 P9 ＋ P1 ＋（P2 抬一层）各出三分之一拼出来的
那条轴：每一个原子都能回答「你是从图上哪里、通过哪一种编码被读出来的」。

| 原子 | 出处字段 |
|---|---|
| **值** | `value_axis`（对着哪条轴）＋ `mark_shape`（按哪种形状换算）＋ 可读判据的容差 |
| **键的每一段** | `KeySource`：轴刻度 / 图例 / 面板标题 / 图元旁标注 / 标题里 / 只有颜色 / 记号形状 / 填充纹理 / 没写 |
| **图外的每一段文字** | `TextBlock.role`：图号 / 主标题 / 副标题 / 单位 / 来源行 / 注释行 / 轴标题 / 图例标题 |
| **区域** | 边画边记——框在画的那一刻就写下来了 |

真实图表的标注只能事后猜「这个数是从哪读出来的」，我们的记录在画的那一刻就写下来了——而
**寻址类错误占解析器失败的 72.2%**。

## 5 · 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 坐标漂移 | 自动布局、dpi、`bbox_inches` 改变实际绘图区，框整体偏移且不报错 | 冻结这三项；自检①逐图元拦截 |
| 轴映射错误 | 对数轴、负值、堆叠基线上反算出的值与记录不符 | 自检②；轴的 scale 先设再设值域，否则自动缩放会把值域改回去 |
| 声明期与执行后基数不一致 | 按声明判非空的族在实际数据上一张也画不出 | 01 的结构检查强制实际基数与声明一致 |
| 单次调用负担过重 | 场景 + 脚本 + 意图三段一起写，某一段质量下降 | 三段各有独立校验，哪段不过就带具体原因回喂哪段 |
| 采样抽不中 | 某个族反复抽到不合法或冗余的候选 | 每族至多 T 次；抽之前先用声明的语义条件收窄候选池 |
| 值目标稀疏 | 饼图、热力图的值几乎全部读不出 | 预期结果不是缺陷；值目标产出率按图表类型分别统计 |
| 风格泄漏进真值 | 某个风格参数意外改了求值结果 | 自检③；`STYLE_DOMAINS` 标了「不影响可读性」的维度有元测试盯着 |
| 标题对数值下断言 | 「等待时间大幅下降」画出来就成了真值 | 校验拒绝含数字的输出；标题只许命名画了什么 |
| 第二次调用让流水线不再确定 | 同一份输入两次运行出不同标题 | 按内容哈希缓存；schema 按本批的列逐个声明，否则调用永远失败而兜底静默生效 |
| 面板底色静默关掉自检① | 自检恒过、偏移的框照样写盘 | 底色读自面板自己的上边与两侧；画满的面板明说没有分辨力 |
| 描边把细图元画没 | 记录写着框、值和可读，图上什么都没有 | 边宽按图元厚度收窄 |
| 太薄的框被自检跳过 | 最可能画错的图元恰好是不检查的那些 | 框先按最小尺寸向外撑开再判；只有「值本来就是零」才免检 |
| 奖励与自检判得不一样 | 完美答案在瀑布 / 堆叠 / 五数上被判错 | 奖励拿整个值字典；记录精度从记录传入，不从这一批答案反推 |
| 一页两图各导一份 L0 会互相漏标 | 两份都只标了自己那张的文本块 | 页面元素按 `page_id` 合并，与导出粒度无关 |
| 权重按下标写会静默错位 | 新增类型之后配比对错族 | 按名键入，随产物落盘 |

### G9 绘图区里的说明框、箭头与参考线

实测频次（100 页 × 三家模型，[analysis_summary.json](../parsebench/data/stats/analysis_summary.json)）：

| 组件 | 100 页里出现在几页 |
|---|---|
| 绘图区内的说明框 / 引线注解 `annotation_callout` | 17 / 9 / 14 |
| 参考线（水平或垂直虚线，含零线，常带独立图例项）`reference_line` | 25 / 29 / 11 |

两者都在 ParseBench 的 65 项组件词表里标着"我们画不出来"，都归 [C6](../parsebench/README.md) 那一条。做法是清楚的，而且两者进不同的层：

- **说明框 / 箭头 / 框加箭头**是一个**页面元素**。它画在画区里，承载的是解释而不是数据，所以进 L0（`Element`，带自己的类别与框），**不进 L1**。它同时是一个明确的干扰项——一个转写模型不该把说明框里的数字当成一个数据点交出来。
- **参考线**跨越整个画区，常常在图例里占一项。它同样不是数据图元，转写时把它报成一个数据点就是错的。也进 L0，但要在图例里占一项。

**排在下一轮的理由**：它会改变 `page_elements` 目标的构成，与这一轮的画布改动叠在一起会让"改造前后哪个数变了"说不清楚。单独一批重跑，前后可比。

**跨图一致性有意留在导出函数里**：这条轴 2026 年的工作已经占了，我们的可防守轴是出处（[§3](#3--parsebench-的十条缺口与五条一般化)）。
